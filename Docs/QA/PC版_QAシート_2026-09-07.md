## 0. 本シートの範囲

### 0-1. PC版とは

| 項目 | 値 | 出所 |
|---|---|---|
| プラットフォーム | Windows Standalone (x64) | `Release_Windows.asset` |
| 配布経路 | Steam / 配信用の直接配布 (zip) | ストア仮登録資料 §1 |
| 想定解像度 | 1920 × 1080 | `defaultScreenWidth/Height` |
| FPS 目標 | **60 FPS 以上** (Android の30とは別基準) | GS-08 |
| ロード時間 | 3秒以内 | GS-08 |
| ビルドプロファイル | `Release_Windows` (Development ビルドではない) | `m_Development: 0` |
| 収録シーン | グローバルのシーンリストを使用 (Android と同じ7本) | `m_OverrideGlobalSceneList: 0` |

### 0-2. 本シートが扱うもの / 扱わないもの

**本シートは PC 固有の観点だけを扱う。**

ゲームロジック (リズム判定 / 戦闘 / キルコード / 音楽同期 / リザルト / アウトゲーム / セーブの中身)
の検証項目は [`CBT_QAシート_2026-09-06.md`](CBT_QAシート_2026-09-06.md) の §3〜§10 をそのまま流用する。
**同じ内容を二重に管理しない。**

| 検証対象 | 使うシート |
|---|---|
| 配布・起動・ウィンドウ・入力デバイス・PC性能・多重起動・Windowsのセーブ場所・Steam | **本シート** |
| リズム判定 / 戦闘 / キルコード / 音楽同期 / リザルト / アウトゲーム / セーブ内容 | `CBT_QAシート` §3〜§10 |

> CBTシートの項目をPCで実施する際、**判定基準が違うのは FPS だけ** (Android 30 → PC 60)。
> それ以外の合否条件は共通である。

### 0-3. Android版CBTとの関係

CBT (Google Play クローズドテスト) は **Android のみ**であり、PC版は対象外である。
本シートは Steam リリースおよび配信用ビルドの検証に使う。

## 1. 配布・インストール・起動

- [ ] 1-1. 配布された zip を展開するだけで起動できる (追加のランタイム導入が不要)
- [ ] 1-2. 実行ファイル名と表示名が `Symphony Kill Chord` になっている
- [ ] 1-3. パスに日本語・空白が含まれるフォルダに置いても起動する
- [ ] 1-4. デスクトップ以外 (別ドライブ、外付けドライブ) からも起動する
- [ ] 1-5. Windows Defender / SmartScreen の警告が出た場合の挙動を記録した
- [ ] 1-6. 管理者権限なしで起動できる
- [ ] 1-7. 初回起動でクラッシュせずタイトルまで到達する
- [ ] 1-8. 初回起動にかかった時間を記録した (秒)
- [ ] 1-9. `*_Data` フォルダや DLL を消さずに配布物一式が揃っている

> 1-5: Steam 経由なら問題にならないが、**配信用の zip 直接配布では毎回警告が出る**。
> 視聴者に配る場合は手順の案内が要る。

## 2. ウィンドウ・ディスプレイ

- [ ] 2-1. 起動時に**ネイティブ解像度**のフルスクリーンで立ち上がる
- [ ] 2-2. `Alt + Enter` でウィンドウ / フルスクリーンを切り替えられる
- [ ] 2-3. ウィンドウモードでウィンドウの**端をドラッグしてもサイズが変わらない**
- [ ] 2-4. ウィンドウモードでウィンドウを移動できる
- [ ] 2-5. 1920×1080 以外の解像度 (1280×720 / 2560×1440 / 3840×2160) で UI が破綻しない
- [ ] 2-6. 16:9 以外のアスペクト比 (16:10 / 21:9) で見切れ・引き伸ばしが起きない
- [ ] 2-7. マルチモニタ環境で、意図したモニタに表示される
- [ ] 2-8. モニタ間でウィンドウを移動しても描画が壊れない
- [ ] 2-9. Windows の拡大縮小 (DPI スケーリング 125% / 150% / 200%) で文字がぼやけない
- [ ] 2-10. リフレッシュレート 60Hz 以外のモニタ (120Hz / 144Hz) で挙動を記録した

> 2-1 / 2-3 は設定値どおりの挙動を確認する項目。
> `defaultIsNativeResolution: 1` `resizableWindow: 0` `allowFullscreenSwitch: 1`。
> **リサイズ不可は仕様である。**リサイズできたら NG。

> 2-10: リズムゲームなので、**高リフレッシュレート環境で判定がずれないか**は重点確認。

## 3. 入力 — キーボード / マウス

- [ ] 3-1. 移動 (Move) がキーボードで操作できる
- [ ] 3-2. 視点 (Look) がマウスで操作できる
- [ ] 3-3. 攻撃 (Attack) が入力できる
- [ ] 3-4. 回避 (Dodge) が入力できる
- [ ] 3-5. ロックオン (LockOn) と対象切替 (LockOnSelect) が動く
- [ ] 3-6. ポーズ (BattlePause) と設定 (Option) が開く
- [ ] 3-7. アウトゲームで 決定 (Submit) / 取消 (Cancel) が動く
- [ ] 3-8. シナリオで 送り / 早送り / スキップ / オート / UI非表示 が動く
- [ ] 3-9. マウスカーソルがインゲーム中に画面外へ出ない
- [ ] 3-10. Alt+Tab 後にマウスカーソルの状態が正しく戻る
- [ ] 3-11. 高速連打しても攻撃入力が取りこぼされない (**リズム判定に直結**)
- [ ] 3-12. マウスのポーリングレートを変えても視点操作の挙動が破綻しない
- [ ] 3-13. IME が有効な状態でもキー入力が誤変換されない
- [ ] 3-14. キーの同時押し (移動 + 攻撃 + 回避) が取りこぼされない

> 3-11 / 3-14 は **PC 固有の最重要項目**。本作は入力間隔が武器と必殺技を決めるため、
> 取りこぼしはそのまま誤判定になる。

## 4. 入力 — ゲームパッド

- [ ] 4-1. ゲームパッドを接続した状態で起動し、操作できる
- [ ] 4-2. 起動後にゲームパッドを接続しても認識される (ホットプラグ)
- [ ] 4-3. プレイ中にゲームパッドを抜いても操作不能にならず、キーボードへ戻る
- [ ] 4-4. ゲームパッドとキーボードを交互に使っても入力が競合しない
- [ ] 4-5. アウトゲームのメニューをゲームパッドだけで移動・決定できる
- [ ] 4-6. **画面のボタン表示がゲームパッド用に切り替わるか記録した**
- [ ] 4-7. スティックのデッドゾーンが極端でない
- [ ] 4-8. 振動の有無を記録した

> **重要**: `KillChordInputActioMap.inputactions` に定義されている **control scheme は
> `PC_Keyboard-Mouse` の1つだけ**である。バインディング自体は Gamepad / Joystick にも
> 張られているため入力自体は通る可能性が高いが、**scheme 単位のデバイス切替が成立しない。**
> 4-6 のボタン表示切替は、仕組み上まだ実装されていない可能性が高い。
> GS-09 は「controller navigation」を要求しているため、**仕様と実装の差として扱う。**

## 5. 音声出力 (PC固有)

- [ ] 5-1. 既定の音声出力デバイスから音が出る
- [ ] 5-2. プレイ中に出力デバイスを切り替えても音が復帰する
- [ ] 5-3. Bluetooth イヤホンで**音と拍のズレが判定を壊さない**
- [ ] 5-4. 有線 / USB DAC / HDMI 出力それぞれで遅延の体感を記録した
- [ ] 5-5. 他アプリ (Discord / ブラウザ) と同時に音を出しても排他エラーにならない
- [ ] 5-6. OS 側の音量変更が反映される
- [ ] 5-7. サンプルレートが異なる出力デバイス (44.1kHz / 48kHz) で BGM が破綻しない

> 5-3 / 5-4 は本作のコアに直結する。**音楽同期がずれると企画そのものが伝わらない。**
> ズレを感じた場合は、遅延の体感値 (ms) ではなく「何拍ずれたか」で記録すると開発側で扱いやすい。

## 7. 中断・フォーカス・多重起動

- [ ] 7-1. `Alt + Tab` で他アプリへ切り替えられる
- [ ] 7-2. 非アクティブ時の挙動を記録した (停止するか、動き続けるか)
- [ ] 7-3. 復帰後にゲームが正常に続行できる
- [ ] 7-4. 最小化 → 復元で描画が壊れない
- [ ] 7-5. Windows のスリープ → 復帰後にゲームが続行できる
- [ ] 7-6. **同じゲームを2つ同時に起動できてしまわないか確認した**
- [ ] 7-7. 2つ起動した状態で両方セーブした場合の挙動を記録した
- [ ] 7-8. タスクマネージャから強制終了 → 再起動で進行不能にならない
- [ ] 7-9. ウィンドウの × ボタンで正常終了する (プロセスが残らない)

> 7-2: `runInBackground: 0` のため、**非アクティブになるとゲームが止まる**設定である。
> 音楽同期型のゲームなので、復帰時に拍がずれないかを併せて見る。
> `visibleInBackground: 1` なのでフルスクリーンでも背後に見え続ける。

> 7-6 / 7-7 は**重点確認**。`forceSingleInstance: 0` のため **二重起動できる。**
> 同じセーブファイルを2つのプロセスが書くと進捗が壊れる可能性がある。
> 二重起動できた場合、7-7 でセーブ競合が起きるかを必ず確かめること。

## 11. PC版固有の既知の不足 (仕様と実装の差)

**QAで確認する項目ではなく、開発側で判断が要る事項。** 実機で確認した上で、
不足が確定したら仕様側へ差し戻す。

| # | 事項 | 根拠 | 影響 |
|---|---|---|---|
| 11-1 | **解像度・ウィンドウモードをゲーム内から変更できない** | `Screen.SetResolution` / `FullScreenMode` が Runtime に存在しない | 起動時のネイティブ解像度で固定。`Alt+Enter` 以外に手段が無い |
| 11-2 | **画質設定をゲーム内から変更できない** | 同上。品質レベルは7段階定義されているが切替UIが無い | 低スペック環境で FPS が出ないとき、プレイヤーに回避手段が無い |
| 11-3 | **キーコンフィグが無い** | 入力アクションに remap 経路が無い | GS-09 の remap 範囲は仕様側も未定義 |
| 11-4 | **ゲームパッド用の control scheme が無い** | control scheme は `PC_Keyboard-Mouse` のみ | デバイスに応じたボタン表示切替が成立しない |
| 11-5 | **ゲーム内設定が音量のみ** | Runtime の設定系が `AudioSettings*` だけ | PC版として設定画面が薄い |
| 11-6 | **二重起動を防いでいない** | `forceSingleInstance: 0` | セーブ競合の可能性 |

> 11-1 / 11-2 は **Steam レビューで直接叩かれる箇所**。PCゲームでは解像度と画質の設定が
> あって当然と見なされる。CBT (Android) では表面化しないが、**Steam リリースまでには要判断**。
