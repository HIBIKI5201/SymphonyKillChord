# CBT QA回答方式 — Symphony Kill Chord

- 作成日: 2026-09-06
- 対象: [`CBT_QAシート_2026-09-06.md`](CBT_QAシート_2026-09-06.md) を QAチームに実際に回してもらうための方式と設問定義
- 前提: **QAチームは非エンジニア。無料サービスのみ。**
- **感情曲線アンケートは本書の対象外。** Voluptas の専用集計ツールで収集・集計する
  ([`CBT_感情曲線アンケート_2026-09-06.md`](CBT_感情曲線アンケート_2026-09-06.md) は、その入力内容の定義として残す)

---

## 1. 結論

QAシートの回答は、性質の違う2つの入力に分ける。**1つの器にまとめない。**

| # | 入力 | 頻度 | 1回の量 | 器 |
|---|---|---|---|---|
| 1 | **チェックリストの消化** (約120項目) | 週1〜2回 | 30〜60分 | **スプレッドシート直接記入** |
| 2 | **不具合報告** (NGが出た時) | 見つけた時 | 1件2分 | **フォーム (1件1送信)** |

理由: チェックリストは項目を行き来しながら埋める作業なので、1問ずつ縦に進むフォームでは最悪になる。
逆に不具合報告をスプレッドシートに直接書かせると、複数人が同時に開いて行を壊し、
再現手順の書式もばらける。

### 1-1. 却下した選択肢

| 方式 | 却下理由 |
|---|---|
| 全部をフォームにする | 120項目のフォームは誰も最後まで答えない |
| 全部をスプレッドシートにする | 不具合報告の同時編集で行が壊れる。書式が統一されない |
| 専用フォームシステムを構築して Spreadsheet に POST | 無料で作れるが**保守が開発側に乗り続ける**。既製のフォームで足りる |
| Unity Editor 拡張 | QAチームは配布ビルドしか持たない。Editor とライセンスの前提が成立しない |
| CLI | 非エンジニア向けではない |
| GitHub Issues | テスター全員にアカウントを作らせるのは14日間に対して重い。**開発側がフォーム回答から起票する**形にする |

## 2. チェックリストシートの構造

QAシートの md を、そのままスプレッドシートに落とす。テスター1人 = 1タブ。

### 2-1. 列定義

| 列 | 内容 | 入力方法 |
|---|---|---|
| A | セクション | 自動 (md から生成) |
| B | 項目番号 (`4-5` など) | 自動 |
| C | 項目内容 | 自動 |
| D | **重点** | 自動。仕様ギャップ High/Medium の項目に `★` |
| E | **判定** | **プルダウン**: `OK` / `NG` / `対象外` / `未実施` |
| F | メモ | 自由記入 |
| G | 不具合報告ID | NG のとき、フォーム送信後に採番されたIDを貼る |

- E列の既定値は `未実施`。空欄を残さない。
- E列が `NG` の行を条件付き書式で赤くする。
- D列が `★` の行は薄い黄色にして、消化を優先させる。

### 2-2. 集計タブ

項目番号ごとに、全テスターのタブを横断して数える。

- `OK` 件数 / `NG` 件数 / `未実施` 件数
- **NG が 12人中4人 (1/3) 以上** の項目を赤信号として上に並べる
- 端末別に `NG` が偏っていないか (機種依存の切り分け)

QAチームは集計タブを触らない。**入力タブだけ**を使う。

### 2-3. 端末情報 (シート先頭に固定)

各タブの1〜5行目に、そのテスターの環境を書く。

| 行 | 項目 |
|---|---|
| 1 | テスターID (氏名は書かない) |
| 2 | 端末名 (機種名) |
| 3 | Android バージョン |
| 4 | ビルドバージョン |
| 5 | 実施日 |

## 3. 不具合報告フォームの設問定義

**1件1送信。** まとめて書かせない。所要2分。
型の表記は §5 参照。器を Google に限定しない形で定義する。

| ID | 設問 | 型 | 選択肢 / 条件 |
|---|---|---|---|
| `B-01` | テスターID | `TEXT_SHORT` **必須** | 運営が配布した英数字ID。氏名は書かない |
| `B-02` | 発生した日 | `DATE` **必須** | 既定値 = 今日 |
| `B-03` | 端末名 (機種名) | `TEXT_SHORT` **必須** | 例: Pixel 8 |
| `B-04` | Android バージョン | `SINGLE` **必須** | 10以下 / 11 / 12 / 13 / 14 / 15 / 16 / わからない |
| `B-05` | ビルドバージョン | `TEXT_SHORT` **必須** | タイトル画面に表示されている番号 |
| `B-06` | QAシートの項目番号 | `TEXT_SHORT` | 例: `8-8`。チェックリスト起因でなければ空欄 |
| `B-07` | 分類 | `SINGLE` **必須** | 進行不能 / クラッシュ・強制終了 / セーブが消えた・戻った / 表示崩れ / 音が出ない・ずれる / 操作できない / 動作が重い / 誤字・文章 / その他 |
| `B-08` | 発生した場面 | `SINGLE` **必須** | 起動前・インストール / タイトル / チュートリアル / Stage_01 / Stage_02 / リザルト・報酬 / アウトゲーム (Home・作戦・研究・改造) / 設定 / その他 |
| `B-09` | 何が起きましたか | `TEXT_LONG` **必須** | |
| `B-10` | 本来どうなるべきだと思いましたか | `TEXT_LONG` **必須** | |
| `B-11` | 再現手順 (順番に書く) | `TEXT_LONG` **必須** | |
| `B-12` | 再現性 | `SINGLE` **必須** | 毎回起きる / たまに起きる / 1回だけ |
| `B-13` | 重要度 (自己申告) | `SINGLE` **必須** | A: これでは遊べない / B: 遊べるが気になる / C: 細かい点 |
| `B-14` | スクショ・動画のリンク | `TEXT_SHORT` | Discord に投げたメッセージのリンクを貼る |

### 3-1. 設計上の注意

- `B-10` は省きたくなるが、**「不具合」と「仕様どおりだが不満」を分ける**のに必要。これが無いと
  開発側が「仕様です」と返して終わる報告が量産される。
- `B-14` を**ファイルアップロードにしない**。多くのフォームサービスはアップロード時に回答者へ
  ログインを強制し、離脱要因になる。画像・動画は Discord の専用スレッドに投げてもらい、
  リンクだけ受け取る。
- `B-06` があると、チェックリストのどの項目が落ちたかを機械的に突き合わせられる。
- 重要度は**自己申告**として受け取り、開発側で再判定する。テスターの申告をそのまま採用しない。

## 4. 運用フロー

```
[テスター]
  遊ぶ
   ├─ 不具合を見つけた → 不具合報告フォーム (1件2分)
   │                      └→ スクショは Discord スレッドへ、リンクをフォームに貼る
   └─ 週1〜2回 → チェックリストのタブを開いて消化 (30〜60分)
                    └→ NG にした行に、送信済みの不具合報告IDを貼る

[開発側・週次]
  集計タブを見る
   ├─ NG が 1/3 以上の項目 → 最優先
   ├─ 重要度Aの報告 → 即対応
   └─ 対応するものを GitHub Issue に起票 (テスターには起票させない)
```

## 5. 設問型の定義

| 型 | 意味 |
|---|---|
| `TEXT_SHORT` | 1行の記述 |
| `TEXT_LONG` | 複数行の記述 |
| `DATE` | 日付 |
| `SINGLE` | 単一選択 |

`必須` = 未回答なら送信できない。

### 5-1. Google フォーム / スプレッドシートで実装する場合

無料で完結する構成として、以下を想定している。他の器を選ぶ場合は §2〜§3 の定義だけを使う。

| 本書の型 | Google フォームの設問形式 |
|---|---|
| `TEXT_SHORT` | 記述式 |
| `TEXT_LONG` | 段落 |
| `DATE` | 日付 |
| `SINGLE` | ラジオボタン |

- フォームは「リンクを知っている全員が回答可」にし、**ログインを要求しない**
- フォームの回答先スプレッドシートと、チェックリストのスプレッドシートは**同じファイル**にして
  タブを分ける。テスターIDで突き合わせる
- `B-02` の既定値を今日にすると入力が速い
- チェックリストのタブは `Docs/QA/CBT_QAシート_2026-09-06.md` から生成する。
  md を原本のまま保ち、仕様が変わったら再生成する
