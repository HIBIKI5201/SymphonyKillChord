## 1. 設計の骨子

### 1-1. 120項目を1本のフォームにしない

Google フォームは**途中保存にログインが必要**で、ログインを要求すると回答率が落ちる。
1本120項目にすると、必ず途中で閉じられて何も残らない。

対策は2つ。

1. **選択式グリッドで、QAシートの1セクションを1問に圧縮する。**
   行 = チェック項目、列 = 判定。10〜15項目が1画面に収まる。
2. **プレイの流れに沿って4本に分割する。** 1本あたり20〜30分で完了でき、
   途中保存が要らなくなる。

これで 116項目が **13グリッド / 4フォーム** になる。

### 1-2. QAリード不在への対応

進行役がいないので、**フォーム自体に手順を埋め込む**。

- 各フォームの冒頭に「このフォームを始める前にやること」を説明文で置く
- 各グリッドの説明文に、そのセクションの**確認手順**を書く (QAシートの本文を転記)
- 判定に迷う項目は、選択肢の直下に判定基準を書く
- フォームの最後に「次はどのフォームか」を明示する

QAメンバーは **QAシートの md を開かなくても回答できる**状態にする。
md は原本として残すが、実作業ではフォームだけを見る。

## 3. 判定の定義 (全グリッド共通)

グリッドの列は**3択に固定**する。スマホで回答するため、4列以上は横スクロールが発生して押し間違える。

| 選択肢 | 意味 |
|---|---|
| `OK` | 期待どおりだった |
| `NG` | 期待どおりでなかった → **F5 で報告する** |
| `試せなかった` | 環境が無い・そこまで到達できなかった・項目の意味が分からなかった |

- **各行を必須にする。** 空欄を許すと「OK」と「未確認」が混ざって集計できなくなる
- 迷ったら `試せなかった` を選んでよい、と説明文に明記する。
  無理に `OK` を付けさせると不具合が埋もれる

## 4. 各フォームの設問定義

### 4-0. 全フォーム共通のヘッダ (F1〜F5 すべての冒頭に置く)

| ID | 設問 | 型 | 選択肢 / 条件 |
|---|---|---|---|
| `H-01` | テスターID | `TEXT_SHORT` **必須** | 運営が配布した英数字ID。**氏名は書かない** |
| `H-02` | 実施日 | `DATE` **必須** | 既定値 = 今日 |
| `H-03` | 端末名 (機種名) | `TEXT_SHORT` **必須** | 例: Pixel 8 |
| `H-04` | Android バージョン | `SINGLE` **必須** | 10以下 / 11 / 12 / 13 / 14 / 15 / 16 / わからない |
| `H-05` | ビルドバージョン | `TEXT_SHORT` **必須** | タイトル画面に表示されている番号 |

> `H-03`〜`H-05` を毎回聞くのは冗長に見えるが、**アプリ更新をまたいで比較する**ために必要。
> CBT期間中に必ず1回はビルドが更新される。

| `B-02` | 分類 | `SINGLE` **必須** | 進行不能 / クラッシュ・強制終了 / セーブが消えた・戻った / 表示崩れ / 音が出ない・ずれる / 操作できない / 動作が重い / 誤字・文章 / その他 |
| `B-03` | 発生した場面 | `SINGLE` **必須** | 起動前・インストール / タイトル / チュートリアル / Stage_01 / Stage_02 / リザルト・報酬 / アウトゲーム (Home・作戦・研究・改造) / 設定 / その他 |
| `B-04` | 何が起きましたか | `TEXT_LONG` **必須** | |
| `B-05` | 本来どうなるべきだと思いましたか | `TEXT_LONG` **必須** | |
| `B-06` | 再現手順 (順番に書く) | `TEXT_LONG` **必須** | |
| `B-07` | 再現性 | `SINGLE` **必須** | 毎回起きる / たまに起きる / 1回だけ |
| `B-08` | 重要度 (自己申告) | `SINGLE` **必須** | A: これでは遊べない / B: 遊べるが気になる / C: 細かい点 |
| `B-09` | スクショ・動画のリンク | `TEXT_SHORT` | Discord に投げたメッセージのリンクを貼る |

#### 設計上の注意

- `B-05` は省きたくなるが、**「不具合」と「仕様どおりだが不満」を分ける**のに必要。
  これが無いと開発側が「仕様です」と返して終わる報告が量産される
- `B-09` を**ファイルアップロードにしない**。Google フォームのアップロードは
  **回答者に Google ログインを強制する**。画像・動画は Discord の専用スレッドに投げてもらい、
  リンクだけ受け取る
- 重要度は**自己申告**として受け取り、開発側で再判定する

## 6. 集計

4つのフォームの回答先を**同じスプレッドシート**にして、タブを分ける。テスターIDで突き合わせる。

### 6-1. 見るもの

| 指標 | 出し方 | 判断 |
|---|---|---|
| 項目別 NG 率 | グリッドの各列を `COUNTIF` | **12人中4人 (1/3) 以上が NG** → 赤信号 |
| 重要度A の報告件数 | F5 の `B-08` | 1件でも残っていれば CBT 提出不可 |
| `試せなかった` 率 | グリッドの各列を `COUNTIF` | 高い項目は**手順の説明不足**を疑う。不具合とは別問題 |
| 端末別の偏り | `H-03` × NG のクロス集計 | 特定機種に偏れば機種依存 |
| ★項目の消化状況 | ★行の `試せなかった` 件数 | 重点項目が確認されていないまま提出しない |

### 6-2. 開発側の週次オペレーション

```
週1回
  ├─ NG率が1/3以上の項目を上から並べる
  ├─ 重要度Aの F5 報告を確認
  ├─ 「試せなかった」が多い項目 → フォームの説明文を直す (不具合ではない)
  └─ 対応するものを GitHub Issue に起票 (テスターには起票させない)
```

QAメンバーは集計を見ない。**フォームに答えるだけ**でよい状態にする。

## 7. Google フォームでの実装メモ

| 本書の型 | Google フォームの設問形式 |
|---|---|
| `TEXT_SHORT` | 記述式 |
| `TEXT_LONG` | 段落 |
| `NUMBER` | 記述式 + 回答の検証「数値」 |
| `DATE` | 日付 |
| `SINGLE` | ラジオボタン |
| `GRID(行 × 列)` | **選択式グリッド** (「各行に回答を1つ必須にする」をON) |

- フォームは「リンクを知っている全員が回答可」にし、**ログインを要求しない**。
  そのぶんファイルアップロードは使えないので `B-09` はリンク記述式にする
- `H-02` の既定値を今日にすると入力が速い
- **グリッドの列は3つまで。** スマホで4列以上は横スクロールが発生し、押し間違えが増える
- グリッドの行ラベルは長くなるので、`4-5. 最初の入力が All ノーツになる` のように
  **項目番号を先頭に付ける**。回答スプレッドシートの列名になり、集計時に効く
- F1〜F4 と F5 の回答先を同じスプレッドシートに設定する
- 各フォームの「確認メッセージ」に、次にやること (NGがあれば F5 へ) を書く
