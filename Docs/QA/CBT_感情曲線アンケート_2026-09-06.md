# CBT 感情曲線アンケート — Symphony Kill Chord

- 作成日: 2026-09-06
- 対象: Google Play クローズドテスト (CBT) のテスター
- 目的: 「どこで心を掴み、どこで離れたか」を **数値** で残し、14日間で直す場所を優先順位付きで決める
- 設計の下敷き: LUDIARS **Voluptas** の感情曲線 (Russell 円環モデルのワンタップスタンプ → 感情曲線 →
  ピーク・エンド則とアーク分類 → ホットスポット統計と生存曲線) と、学術標準の SAM / GEQ / PENS
- 併用: 不具合の検出は [`CBT_QAシート_2026-09-06.md`](CBT_QAシート_2026-09-06.md)。**こちらは「面白かったか」を測る**。

---

## 0. なぜスタンプと数字なのか (実施者向け・テスターには見せなくてよい)

自由記述だけを集めると「声の大きい人の感想」に全体が引きずられる。
Voluptas が採っている方針をそのまま踏襲する。

1. **座標系を先に決める** — 感情を valence (快–不快) × arousal (覚醒度) の 2 軸に置く (Russell 円環モデル)。
   連続量なので時系列にでき、区間ごとに集計できる。
2. **絶対値でなく順序で見る** — 人間の申告は「強さ4」より「さっきより上がった」の方が信頼できる。
   §2 と §3-2 は必ずセットで取り、集計時に **人ごとに順位化してから** 平均する。
3. **終わり方を重く見る** — 体験の記憶はピークと終わり方でほぼ決まる (ピーク・エンド則)。
   §4 が最重要設問。
4. **場所を必ず聞く** — 「つまらない」ではなく「どの区間でそうなったか」。§2 の区間IDが
   ホットスポット統計の入力になる。

## 2. 感情スタンプ (プレイ中・区間ごと)

各区間を終えたら、**その区間で一番強かった感情** を1つだけ選んで記号を書く。
迷ったら「どちらでもない」を選んでよい。1区間15秒以内で答えること。

### 2-1. スタンプの意味 (Russell 円環モデルの4象限)

|  | **快 (楽しい側)** | **不快 (つらい側)** |
|---|---|---|
| **高覚醒 (気持ちが動いた)** | 🔥 **盛り上がり**<br>手に汗、テンションが上がった | ⚡ **ストレス**<br>イライラ、焦り、理不尽 |
| **低覚醒 (落ち着いていた)** | 💙 **スキ**<br>心地よい、しっくりくる、綺麗 | 💤 **嫌い**<br>退屈、だるい、興味が切れた |

- どちらでもない = **・** (ニュートラル)
- 「怒り」と「無力感」を区別したいときだけ、記号の後に `(自分で操作できた)` / `(何もできなかった)` を添える。

|---|---|---|---|---|

## 7. 集計手順 (実施者向け)

### 7-1. 前処理 — 人ごとに順位化してから平均する

生の5段階値をそのまま平均しない。**回答者ごとに z 化 (または順位化) してから** 区間平均を出す。
辛口の人と甘口の人が混ざっても、区間の相対的な高低が壊れなくなる。

### 7-2. 感情曲線を描く

- 横軸 = 区間ID (S0〜S9)、縦軸 = valence の平均 (正規化後)。
- スタンプは 🔥 = (valence +1, arousal +1) / 💙 = (+1, −1) / ⚡ = (−1, +1) / 💤 = (−1, −1) に写像し、
  強さ (1〜5) を掛けて重み付けする。
- 人数が揃ったら、曲線を §4 Q4-5 のアーク5分類で層別する。**同じゲームでも人によって形が違う**なら、
  「誰に向けて直すか」を先に決める必要がある。

### 7-3. ホットスポットを特定する

- 区間ごとに ⚡ (ストレス) と 💤 (嫌い) の割合を出す。
- **1人1票**にする (同じ人が同じ区間に何度も書いても1票)。声の大きい人で統計が動かないようにする。
- 割合が高い区間から順に修正候補にする。少人数なので p 値は求めず、
  「12人中何人が同じ区間を挙げたか」を判断材料にする。**4人 (1/3) 以上で赤信号**として扱う。

### 7-4. 生存曲線を描く

- 横軸 = 日数、縦軸 = 「その日もプレイした人の割合」。
- **Day1 → Day2 の落ち** が最も大きいはず。ここが落ちる原因は §4 Q4-3 に出る。
- CBT の成立条件 (12人 × 連続14日) と直結するので、**落ちた人には個別に声をかける**。
  日数は作業量では取り戻せない。

### 7-5. 優先順位の付け方

| 順位 | 条件 |
|---|---|
| 1 | 生存曲線を落としている区間 (離脱の直接原因) |
| 2 | ⚡ / 💤 が 1/3 以上に集まった区間 (ホットスポット) |
| 3 | Q4-3 が「終わり方が悪い」側に寄っている (ピーク・エンド則) |
| 4 | Q3-3 のコアコンセプト理解率が低い項目 |
| 5 | Q3-4 の平均が低い項目 |

## 8. 運用メモ

- 回答は **プレイ直後に取る**。翌日に聞くと、ピークと終わりしか残らない (duration neglect)。
- §2 は紙・Googleフォームどちらでもよいが、**区間IDを必ず選択式にする**。自由記述にすると集計できない。
- §5 は毎日1行なので、Discord のスレッドに1日1投稿でもよい。
- 個人が特定できる情報 (氏名・メールアドレス) は集めない。テスターIDのみで運用する。
