## 10. リリース品質の観点で抜けている項目（2026-08-05 追加調査）

### 10-1. 🔴 コードを読んで見つかった実害のある欠陥

#### (A) セーブデータが原子的に書き込まれていない → タスクキルでセーブ消失

`Assets/Scripts/Runtime/0.Utility/Savedata/SaveBase.cs:84-87`

```csharp
if (File.Exists(FilePath))
    File.Delete(FilePath);
File.Move(tempPath, FilePath);
```

Delete と Move の**間でプロセスが死ぬとセーブファイルが完全に消える**。`.tmp` は残るが `ReadAsync()` は `FilePath` しか見ないので復旧されない。

Androidではタスクキル・バッテリー切れ・OSによるメモリ回収が日常的に起きるため、これは机上の懸念ではない。`File.Replace` を使うか、Deleteせず直接上書きMoveにする。

#### (B) セーブデータにバージョン番号が無い → アップデートでセーブが壊れる

`SaveBase.cs` は `JsonUtility.FromJsonOverwrite` のみで、スキーマ変更時のマイグレーション経路が無い。**10月リリース後に修正パッチを出した瞬間、既存プレイヤーのデータが不整合になる。**

version フィールドはリリース**前**に入れないと後から入れられない。最優先で対応すべき。

#### (C) 中断・復帰処理が一切ない

`Assets/Scripts` 全体で `OnApplicationPause` / `OnApplicationFocus` / `OnApplicationQuit` の実装が **0件**。

ホームボタン・着信・画面ロックでの一時停止と復帰、バックグラウンド遷移時のセーブが実装されていない。(A)との合わせ技で確実に事故る。

#### (D) SafeArea 対応が無い

`Assets/Scripts` 全体で `SafeArea` の参照が **0件**。メインプラットフォームがAndroidなのに、ノッチ／パンチホール／ジェスチャーバー領域のUI回避が未実装。

#### (E) 未解決TODOの残存

`SaveBase.cs:100` — `// TODO セーブデータの格納先が決まったらここを直す。`

### 10-2. 🔴 Android実機検証がスケジュールに存在しない

**メインプラットフォームはAndroidだが、8/23の配信はWindowsビルド。** 8月を通してAndroid実機での検証機会がゼロになる。

- メーカー別（Galaxy／Xperia／Pixel／AQUOS）の挙動差
- OSバージョン差（`AndroidMinSdkVersion: 25` = Android 7.1 まで対応を謳っている）
- ローエンド〜ミドルレンジ端末でのメモリ・熱・フレームレート
- チーム内に検証用実機が何台あるかの把握

IL2CPP/ARM64移行と合わせ、**8月下旬に実機検証週を確保する必要がある。**

### 10-3. 🟡 TGS展示専用ビルドが計画に無い

展示には通常のゲームには不要な機能が要る。

| 必要な要素 | 内容 |
|---|---|
| アテンドモード | 無操作N秒でタイトルへ自動復帰 |
| セーブ自動リセット | 次の来場者に前の人のデータを見せない |
| 終了・設定変更のロック | 来場者がアプリを閉じられないように |
| デモループ | 誰も遊んでいない間の自動再生映像 |

加えて **65インチモニターに何を繋ぐのかが未定**。Android実機のミラーリングか、Windows版か。タッチ操作前提のゲームをモニター展示でどう見せるかは9月ではなく今決める事項。

| **リリース後の運用体制** | 全員学生で就活中。10/31リリース後のクラッシュ対応・レビュー返信・緊急パッチを誰がやるか。**Play Console権限保持者が1人だとバス係数1** |
| リリース日が土曜 | 2026-10-31 は土曜日。作業体制の確認 |

### 10-5. ⚪ 過剰と判断した項目（あえてやらない）

| 項目 | 判断 |
|---|---|
| セーブデータの暗号化 | オフライン単騎・課金なし・ランキングなしのため不要。改造されても他者に影響しない。**§10-1(A)(B) の方が圧倒的に優先度が高い** |
| Crashlytics / Sentry の導入 | Google Play Console の Android vitals でクラッシュ・ANRが**無償かつSDK不要**で取得できる。SDK追加は §9-4 の「データを収集しない」申告を崩し、プライバシーポリシーの記述も増える。**入れない方が総コストが低い** |
| 特定商取引法に基づく表記 | 無料・課金なしのアプリに特商法の表記義務は生じない。必要なのは Google Play が求める**連絡先メールアドレスと開発者住所の公開**（§9-3） |

### 10-6. 既に存在するので不要な項目

| 項目 | 実態 |
|---|---|
| CI/CD 自動ビルドの構築 | **既に存在する。** `.github/workflows/BuildAndRelease.yml`（868行）が稼働中。Sprint 43のレビューで「自動ビルドの完成（WindowsとAndroid）」と報告済み。PRマージ時とworkflow_dispatchでトリガー。新規構築ではなく**IL2CPP/ARM64対応の確認**が実際のタスク |
| データセーフティ申告 | v2 §5 の申請トラックに記載済み。かつ §9-4 により内容は簡単 |
| OSSライセンス表記 | §9-3 に記載済み |
