## 1. ⚠️ 収録前に決めてほしい設計判断

### 判断1: 1拍・3拍・6拍を、チュートリアルで教えるか

現仕様のフローは6拍種すべてを教える構成です。しかし**チュートリアルで使うキルコードは スキル0（4→4→4）と スキル13（2→8→8）だけ**なので、**1拍・3拍・6拍は教えても一度も使いません。**

尺を積算すると、

| 構成 | 所要時間 |
|---|---|
| 1・3・6拍を含む（現仕様） | 約6分25秒 |
| 1・3・6拍を除く | 約5分25秒 |

**5分目標は、1・3・6拍を外さないと物理的に達成できません。**

G-Lab解析も同じ方向を指しています。

> 最小の価値単位を「4拍attackを2回成功し、因果を説明できる」に切り、次に8拍、最後にpatternへ組み合わせるべき

松木さんの「初心者でも楽しく遊べる難易度が良い」とも整合します。

**推奨: 本編フローは 4拍 → 8拍 → 2拍 の3種に絞る。** 1・3・6拍は「チュートリアル2周目以降に出る任意パート」か「通常ステージ序盤」に移す。

ただし**この判断を今日決める必要はありません。** 台本を後述のとおりモジュール分割してあるので、1・3・6拍のブロック（§4-6）だけ切り離せます。収録は全部やっておき、実装時に入れるかを決める形にすれば、再収録は発生しません。

### 判断2: 失敗時ボイスのバリエーション数

チュートリアルは初見の人が**必ず失敗します**。同じ台詞が繰り返されると一瞬で不快になります。

各失敗ポイントに**最低2パターン、できれば3パターン**を用意し、ランダムまたは順送りで再生してください。台本では `_F1` `_F2` `_F3` で分けてあります。

### 判断3: 無線加工は収録後に行う

ラジオボイスのEQ・ノイズ・歪みは**後処理**です。収録は素の音で行ってください。加工前提で演技を作ると、後で調整できなくなります。

### 判断4: BGMとの干渉

音楽同期ゲームなので、ボイスがBGMの拍を潰すと**ゲームの根幹が伝わらなくなります**。

- ボイス再生中はBGMを **-3〜-6dB ダッキング**
- 長い説明ボイスは**プレイヤーの操作を止めている間**に置く（戦闘中に被せない）
- 戦闘中に流すのは §台本で「短」と書いた2秒以内の行のみ

## 2. 台本IDの規約

```
TUT_<フェーズ>_<連番>_<話者>[_<種別>]

話者:  TRI = Triad / SYM = Symphony
種別:  （無印）= 通常  F1/F2/F3 = 失敗時バリエーション  R = 再プレイ時差し替え
```

例: `TUT_BEAT4_03_TRI_F2`

CSV投入時はこのIDを主キーにしてください（`CSV入力作業` タスクの既存フローに合わせる）。

```
    ↓

    ↓
[Phase 7] 回避
    ↓

    ↓
[Phase 9] キルコード スキル13（2→8→8）
    ↓
[Phase 10] 総仕上げ・撃破・締め
```

各フェーズは **cue（合図）→ safe attempt（安全な試行）→ feedback（結果の提示）→ 変形課題 → prompt fade（表示を消す）** の順で構成しています。最後の prompt fade がないと、通常ステージで何もできなくなります。
