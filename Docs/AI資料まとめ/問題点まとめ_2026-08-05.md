このファイルは、Battle / Character / Player / Music・リズム判定 / Enemy・Boss / Mission / Buff の7ドメイン監査で見つかった問題点を、ドメイン横断で優先度別に並べ替えたチェックリストです。同一事象が複数ドメインから指摘されたものは1項目にまとめ、関連ドメインを併記しています。file:line の根拠・仕様書引用は元レポートを参照してください。

| 記号 | 意味 |
| --- | --- |
| [A] | 仕様書にあるが実装が無い／一致しない |

## 優先度: 最高

- [ ] **[C] Just判定が全攻撃経路で機能していない**（Battle / Music）— `isJustHit`が通常攻撃・スキル攻撃・キルコード・敵攻撃の全経路でハードコード`false`。±0.1秒の許容窓を計算するロジック自体が存在せず、拍種解決成功＝Just成立という別物になっている。マスターデータの`_justDamageMultiplier`も実質0。「上級者向け精度報酬」という核心メカニクスが骨格のみで死んでいる。
- [ ] **[A] 拍子別攻撃仕様（武器ダメージ%・射程・攻撃形状・貫通・複数対象・ノックバック・三点バースト）が丸ごと未実装**（Battle）— `BeatStep.cs`は拍子数をそのままダメージ倍率にするのみ。6武器のマスターデータは全て同一パラメータ。仕様書は`仕様概要/仕様リスト/プレイヤー/攻撃アクション.md:40-64`に実在（外部ファイルではなくリポジトリ内が一次情報）。
- [ ] **[C] 敵の攻撃力が全種固定値10でハードコード**（Enemy）— `EnemyAttackUsecase.cs`/`ShellAttackUsecase.cs`/`EnemyTripleShotAttackUsecase.cs`の3箇所全てに同一TODOコメント付きで放置。歩兵/砲兵/ボスの攻撃力差（5/10/10）が完全に無視される。
- [ ] **[C] バフ付与スキル（02・06・07）が`null`固定で機能停止**（Buff）— `SkillEffectExecutorFactory.RegisterDefaults`が全スキルの`IBuff`引数へ一律`null`を渡す。NullReferenceExceptionの要因にもなりうる。社内Discordログでも実態と認識のズレが指摘されている。
- [ ] **[B] Missionのクリア条件アーキテクチャが「目標シーケンス制」へ全面刷新され、仕様書との対応が根本的に失われている**（Mission）— `ObjectiveSequenceClearCondition`等、中核アーキテクチャの刷新が技術仕様書に一切反映されていない。
- [ ] **[B] Missionステップ連動のバフ・デバフ付与機構が未文書化**（Mission / Buff 重複指摘）— `PlayerBuffClearCondition`。コミットメッセージ「とりま無理やりバフシステムで続行」から、企画合意なき先行実装の可能性。
- [ ] **[A] 回避アクションがリズム入力として一切記録されない**（Music）— 「攻撃や回避でリズムを刻む」という仕様の核のうち回避側が丸ごと欠落。
- [ ] **[A] 同時被弾時のダメージ間引き（最も遠い敵のみ着弾）ルールが未実装**（Enemy）— 複数の敵が同時攻撃を命中させると理不尽な多重ダメージが発生しうる。
