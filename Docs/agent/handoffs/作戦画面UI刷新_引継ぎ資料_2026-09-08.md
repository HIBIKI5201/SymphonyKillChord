# 作戦画面(StageSelect)UI刷新 引継ぎ資料

作成日: 2026-09-08
対象ブランチ: `feature/demo/level-design/master`

## 1. 経緯・要望

作戦画面(ステージ選択画面)について、以下の要望が段階的に出された。

1. ステージノードをクリックした際、そのノードを拡大して(ズームして)画面に写すようにしたい。
2. ズーム時、選択したノードが画面のわかりやすい位置に来るようにしたい(要望は数回変遷し、最終的に「画面全体の横幅25%の位置」に確定)。
3. ノード・接続線(パス)が小さいので25%程度拡大したい。
4. 作戦マップのスクロールバーは非表示にしつつ、マウスのクリック&ドラッグでマップをパンできるようにしたい。
5. 作戦画面を開いた直後の見た目は変えずに、左方向へも(空白まで)ドラッグできる「あそび」がほしい。
6. (未解決)作戦画面に入って最初の1回だけ、ノードクリック時のズーム位置がおかしくなる不具合がある。

## 2. 実装内容サマリ(最終状態)

### A. ノードクリック時のズーム演出
- `StageSelectInitializer.BuildNodeElements`内のノードクリックハンドラで`ZoomMapToNode(center)`を呼び出す。
- `ZoomMapToNode`: `StageMapCanvas`に`transform-origin`をクリックしたノードの中心へ設定し、USSクラス`.stage-map-canvas--zoomed`(`scale: 1.5 1.5`、[StageNode.uss](Assets/Level/Scenes/Develop/OutGameTest/StageSelect/UIToolkit/USS/StageNode.uss)に定義)を付与して拡大する。
- 同時に`ScrollView.scrollOffset`を、クリックしたノードが**画面全体の横幅25%の位置**に来る値まで、`schedule.Execute(...).Every(16ms)`によるC#駆動のイーズアウト補間(0.35秒)でアニメーションさせる(`AnimateScrollOffsetXTo`/`CalculateCenteredScrollOffsetX`、定数`FOCUS_TARGET_SCREEN_RATIO = 0.25f`)。
- ステージ詳細画面を閉じる(`HandleStageDetailClosed`/`HandleScreenClosed`)と`ResetMapZoom()`でズーム前の状態(倍率・スクロール位置)へ戻る。既存の「フォーカスフレーム固定」ロジックと同じライフサイクルに相乗りしている。

### B. ノード・パスの25%拡大
`StageSelectInitializer.cs`冒頭の定数を全て25%拡大(表と対応するUSS値も同時に変更済み)。

| 項目 | 変更前 | 変更後 |
|---|---|---|
| `NODE_SIZE` | 100.0f | 125.0f |
| `CONNECTION_THICKNESS` | 14.0f | 17.5f |
| `HORIZONTAL_SPACING` | 220.0f | 275.0f |
| `VERTICAL_SPACING` | 160.0f | 200.0f |
| `MAP_PADDING` | 40.0f | 50.0f |
| `.stage-node`の`border-radius`/`border-width` | 50px/12px | 62.5px/15px |
| `.stage-node-focus-frame`の`width`/`height` | 100px | 125px |

ラベル文字サイズ(`.stage-node__label`の`font-size`)はユーザー指定により20pxのまま変更していない。

### C. スクロールバー非表示 + マウスドラッグパン
- [StageSelect.uxml](Assets/Level/Scenes/Develop/OutGameTest/ScreenTransitionTest/UI%20Toolkit/StageSelect.uxml)の`horizontal-scroller-visibility`を`Auto`→`Hidden`に変更。
- ドラッグパンは、研究画面(スキルツリー画面)で既に使われている共通マニピュレータ[ScrollViewDragManipulator.cs](Assets/Scripts/Runtime/4.View/OutGame/SkillTree/ScrollViewDragManipulator.cs)を`ScrollDragAxis.Horizontal`で流用(独自実装は一度作ったが車輪の再発明と判断し置き換え済み)。
- クリック時ズームのスクロールアニメーションとドラッグが競合しないよう、`ScrollViewDragManipulator`に`DragStarted`イベントを新設し、`StageSelectInitializer`がドラッグ確定時に`_scrollAnimationItem?.Pause()`する。

### D. 左方向への「あそび」
- `MAP_LEFT_DRAG_BUFFER`(現在500px)の空白バッファを`StageMapCanvas`の左側に確保し、初期スクロール位置をそのバッファ分に設定することで、開いた直後の見た目は変えずに左へドラッグできる余地を作った。

## 3. 発生した不具合・誤診断とその対応(重要: 撤回した変更に注意)

このセッションは同じ症状に対して**複数回の誤診断と撤回**が発生している。次のセッションで同じ轍を踏まないよう詳細に記録する。

### 3-1. `ScrollViewDragManipulator`のドラッグが「1pxも動かない」不具合(解決済み)
`ApplyScroll`内で`_scrollView.contentContainer.layout.width`を使っていたが、`mode="Horizontal"`のScrollViewではこの値が実際のコンテンツ幅ではなく**ビューポート幅と同じ値**を返してしまい、スクロール可能量が常に0と計算されていた。
→ **対応**: 研究画面の`SkillTreeViewportView.cs`で既に使われている「`Scroller.lowValue`/`highValue`から範囲を取得する」パターンへ切り替えて解決。ScrollView内部が管理する値のため`contentContainer`のレイアウトサイズに依存せず頑健。

### 3-2. 「作戦画面に入って1度目だけこのようなアップになる」不具合(★未解決・要注意)
ユーザーからノードが勝手にズーム+詳細表示された状態のスクリーンショット付きで報告があった。

**1回目の誤診断(撤回済み)**: 「他画面から作戦画面に初めて入った直後、何も操作していないのに不規則なノードが誤クリックされる」という意味だと解釈し、`ScreenViewBase.cs`(画面フェード完了〜初期フォーカス確定までの間に決定入力(`NavigationSubmitEvent`)が漏れる、という画面遷移共通基盤の隙間)を調査・修正した。しかしユーザーへ確認したところ、実際の意味は「**作戦画面に入ってから最初にノードをクリックした時**だけズーム位置がおかしい」ことだと判明し、**この修正(`ScreenViewBase.cs`/`UINavigationExtensions.cs`の変更)は全て撤回済み**。

**2回目の対応(撤回済み)**: 「1回目のクリックだけ中央寄せ位置が(左シフト前の)古い位置になる」という理解のもと、`TryBuildStageMapElements`内の初期スクロール位置設定ジョブ(1回限りの`schedule.Execute`)が、表示直後すぐにクリックした場合にズームアニメーションの位置を上書きしてしまう競合を発見し、`_initialScrollOffsetItem`フィールドで保持して`AnimateScrollOffsetXTo`開始時に`Pause()`する修正を行った。しかしユーザーから**「余計にひどいことになった」**との報告があり、**この修正も全て撤回済み**。

→ **現状、この不具合(1度目だけノードクリック時のズーム位置がおかしい)は未解決のまま**。撤回後、中央寄せロジック自体が「画面全体の25%位置」というシンプルな式に置き換わった(2節A参照)ため、**症状の再現性自体が変わっている可能性がある**。次のセッションでは、まず現状のコードで実際に再現するか、再現するなら具体的にどうおかしいのか(位置がどうずれるか、スクリーンショット等)をユーザーに改めて確認してから調査を始めることを強く推奨する。

### 3-3. バナー除いた中央寄せが反映されない(解決済み・現在は別方式に置き換え)
一時期「ステージ詳細バナーを除いた領域の中央」に寄せる方式を実装したが反映されず、原因はノードの`ClickEvent`に登録順で2つのハンドラ(ズーム処理→詳細画面`Show()`)があり、ズーム処理の時点では詳細パネルがまだ`display:None`で幅が0を返していたため。インラインスタイル値へのフォールバックで対応したが、**最終的にこの「バナー除いた中央寄せ」方式自体をユーザー要望により撤廃し、「画面全体の25%位置」というシンプルな方式に置き換えた**(2節A参照)。関連コード(`GetStageDetailPanelWidth`、`_stageDetailContainer`フィールド等)は全て削除済み。
