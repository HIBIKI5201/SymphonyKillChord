プロダクト概要: Symphony Kill Chord

証拠の状態

  • 出典: 公開Notionの 仕様概要 とリンク先35ページを統合した最終コーパス。インデックスは spec/data/notion-full-spec-index.json。
  • 出典: 本作は、馴染みのある移動・射撃・回避操作の上に、より複雑なリズムパターン戦闘を構築する三人称リズムコマンドアクションである。
  • 出典: 想定対象は、コンシューマーアクションゲームとニコニコ由来の音楽ゲーム文化に馴染みのある26～35歳。β版の対象プラットフォームとしてPCとAndroidが明記されている。
  • 実装のみ: リポジトリの評価対象は commit 0cca5d536257fd5a2f7951f7d3a0756dfc0d5788。
  • 未解決: 商業モデル、価格、発売日、アクセシビリティ受入基準、最終コンテンツ量、ローカライズ範囲は未指定である。

プロダクトが約束する体験

攻撃入力は一つだが、認識されたリズムが攻撃／武器を選択し、装備中のキルコードを成立させるノーツになる。馴染みのある三人称の移動・射撃・ローリングによって操作負荷を抑え、リズムの選択、同期する敵攻撃の把握、スキルパターンの完成へ注意を配分できるようにする意図がある。

仕様例では、2拍入力をショットガン、4拍入力をハンドガン、8拍入力をサブマシンガンに対応付ける。スキルはリズムパターンとアクション種別を組み合わせ、攻撃、バフ、デバフを発生させる。

中核ループ

  1. 戦闘: 音楽と敵予告を読む → 移動・射撃・回避 → 拍ノーツを記録 → 装備中キルコードを成立 → damage／buffを解決 → ミッション達成。
  2. ステージ: ステージまたはシナリオを選択 → 約2分の戦闘 → ミッション、時間、最大コンボ、ランクを確認 → 戻る／再出撃。
  3. 編成: スキルを獲得・解放 → 初期2枠、特殊ノード解放後は3枠へ装備 → コマンドとinteractive BGM編成の両方へ反映。
  4. 成長: ステージ報酬を受領 → スキルツリーノードとスキルを解放 → 個別スキルを強化 → 進捗と設定を保存。

表現方針

  • トゥーン調の肌とリアルな装備を組み合わせたキャラクター、現実的で落ち着いた環境表現。
  • クラシック音楽とEDMの融合。
  • 戦闘BGMはintro、差し替え可能なloop、outroで構成し、装備スキルからloop phraseを選ぶ。現在再生中の音楽要素を視覚表示する。

β版の受入目標

  • PCは60 FPS以上、Androidは30 FPS以上。
  • インゲームのロード時間は3秒以内。
  • 15分間、エラーなし、かつメモリリークがほぼない状態でプレイできる。
  • コンテンツ制作と調整に移行できる、基本ゲームループの完成をβ版の目標とする。

ゲーム仕様ベースライン

以下は、仕様rootからリンクされた公開Notion35ページの統合コーパスから整理した最終規則である。取得手順や旧版との差分ではなく、現在確認できる仕様だけを記載する。画像内だけの詳細、空ページ、明示的な :未確定: は推測で補完しない。コード観測は commit 0cca5d536257fd5a2f7951f7d3a0756dfc0d5788 に固定する。

GS-01 リズム判定

  • 出典: 攻撃と回避入力がノーツを作る。直前入力からの間隔をBPMで補正し、拍種を選択する。
  • 出典: 専用ページ リズム判定 は、1、2、3、4、6、8の6拍種を定義する。
  • 出典: 最初の入力、1.5小節以上空いた後の入力、被弾直後の入力では拍を判定できない。これらはコマンド先頭でのみ利用可能なAllノーツとなる。
  • 出典: 音楽gridに合う入力はJust判定となる。攻撃の硬直時間は0.56秒と記載されている。
  • 矛盾: コアメカニクスについて は12と16を加えた8拍種を記載する。専用判定ページとコードは6拍種であり、仕様の所有元を決定する必要がある。

GS-02 リズムコマンド戦闘

  • 出典: 一つの攻撃入力で選択中の敵を射撃し、リズムが武器／攻撃定義を選ぶ。例は2=ショットガン、4=ハンドガン、8=サブマシンガン。
  • 出典: PCと標的の間に障害物がなければ射撃が命中する。
  • 出典: キャラクターは体力を持ち、0以下で死亡する。プレイヤーの死亡は戦闘終了となる。
  • 出典: 敵は戦闘音楽に同期して攻撃し、攻撃前にlineまたはareaを表示する。
  • 出典: 非critical damageは攻撃力×攻撃時補正。critical時はさらにcritical倍率を適用する。

GS-03 キルコードと編成

  • 出典: キルコードはリズムパターンと、攻撃または末尾入力の回避などのアクション種別条件から発動する。
  • 出典: スキル種別は直接攻撃、プレイヤーbuff、敵debuff。一部はHPまたは命中対象数も条件にする。
  • 出典: 初期スキルは0、13、1と記載される。スキルツリーは簡単な4/8拍から難しい3/6/1拍へ、単純な効果から複雑な効果へ進む。
  • 出典: 初期装備枠は2。6スキル解放後の特殊ノードで3枠になる。
  • 出典: コマンド末尾が同じノーツのスキルは同時装備できない。
  • 出典: 各スキルは個別のレベルと上限を持ち、改造画面で強化する。

GS-04 音楽と遭遇の同期

  • 出典: 戦闘中は必ず戦闘音楽が流れ、敵と予約アクションは拍へ同期する。
  • 出典: BGMは4小節intro、16小節repeat loop、4小節outroで構成する。loopはCRIにより差し替え可能な2小節blockへ分割する。
  • 出典: 2スキル装備時はoriginal → skill 1 → original → skill 2、3スキル装備時はoriginal → skill 1 → skill 2 → skill 3の順とする。
  • 出典: HUDは現在再生中の音楽要素を識別可能にする。

GS-05 ステージ、ミッション、リザルト

  • 出典: ステージ時間は約2分を目標とし、戦闘に関係する成功条件を用いる。
  • 出典: 成功時はゲームプレイを終了してリザルトを開く。失敗時は演出後にゲームプレイを終了する。
  • 出典: 勝利リザルトはステージ、キャラクター、メイン／サブミッション、経過時間、最大コンボ、ランクを表示する。敗北時はサブミッション／ランクの代わりに攻略Tipsを表示する。どちらも完了と再出撃を提供する。
  • 出典: チュートリアルはステージ0であり、リズムアクション、通常戦闘、ボスを予告する。
  • 矛盾: ステージルール はリザルト完了後の戻り先を、ある箇所ではHome、別の箇所では作戦／Stage Selectとしている。

GS-06 アウトゲームと成長

  • 出典: New Gameはtitle → 最初のstory → battle tutorial → home tutorial → Home。Continueはtitle → Home → Operation → 選択story/stage → mission完了と進む。
  • 出典: β版範囲は、報酬受領、stage/story選択、skill装備、skill-tree解放、進捗保存を要求する。
  • コード: 3つの評価条件をC/B/A/Sランクへ対応付けるが、取得仕様にはその計算式がない。

GS-07 永続化

  • 出典: 永続データは、クリア済みstage node、skill-tree進捗、装備中Kill Chordと順序、Kill Chord別level、optionの5分類を持つ。
  • 出典: β版指針はplatformに適したsave管理と一定の暗号化を要求する。
  • 未解決: schema version、migration、cloud save、複数profile、破損復旧は指定されていない。

GS-08 品質・プラットフォーム制約

  • 出典: PCは60 FPS以上、Androidは30 FPS以上を維持する。
  • 出典: インゲームのロードは3秒以内に完了する。
  • 出典: 15分間のセッションでerrorを発生させず、memory leakをほぼ発生させない。
  • 出典（リポジトリ設計）: RuntimeはUtility、Domain、Application、Adaptor、View、Infrastructure、Compositionへ分離し、段階的初期化と逆順shutdownを行う。

GS-09 導線、ガイダンス、回復

  • 出典: Homeはアウトゲームのhubであり、作戦、研究、改造／編成、設定へアクセスできる。
  • 出典: 作戦画面はbattleとscenario nodeを一つの左→右解放treeで示す。battle detailはmission条件、reward、過去progressを表示し、選択後は出撃前の編成確認を開く。
  • 出典: 改造画面はskill filter、effect／command／level詳細、preview、drag-and-dropまたはclick置換、明示的save、未保存で離脱する際の保存／破棄判断を提供する。
  • 出典: 研究treeは現在parameter、cost、unlock可能／locked状態を表示し、resetを提供する。難しい入力systemが苦手なplayerの救済経路として明記されている。
  • 出典: 設定はscene遷移ではなくoverlayで、決定／取消を提供する。titleはvolume、credit、save data resetを公開する。
  • 出典: β版指針はpause、時間停止、resume countdown、rhythm／skill／mission HUD、enemy attack telegraph、loading progress、controller navigation、mobile向け操作を要求する。
  • 出典: 敗北resultは攻略tipを提示し、tutorialは通常進行前にrhythm action、通常combat、boss combatを予告する。
  • 未解決: data reset確認、音cueのaccessibility代替、remap範囲、font／可読性目標、tutorial完了基準は指定されていない。
