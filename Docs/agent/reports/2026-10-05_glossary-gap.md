## 9. 構造の改善案

用語が数百語になるため、表を DB に寄せる。

| 追加プロパティ | 型 | 内容 |
| --- | --- | --- |
| 区分 | select | 現行の「種類」を**「区分」に改名して使う（決定 2026-10-05）**。選択肢: ゲーム／世界観・設定／開発運用／制作（美術・音・シナリオ）／サービス・ツール／技術／アーキテクチャ |
| 正式表記 | title | 現行の「用語名」 |
| 非推奨表記 | rich_text | 使わない別名・旧称・誤字（対応表の列を移す） |
| 英名・コード上の名前 | rich_text | `ScreenId.StageSelect`、`SkillLevelupPoint` など |
| 同語別物 | relation（自己参照） | 「ワークフロー」「master」のような衝突の相手 |
| 初出ページ | url | 定義の本文がある仕様書ページ |

- **対応表を DB に取り込む。** 用語ページの 1 枚の表は、検索にも検査にも使えない
- **検索への接続**: 非推奨表記を同義語として索引（#2396）に渡し、検索語を正式表記へ広げる。検索のヒット率の向上に直結する
- **検査への接続**: `NotionMarkdownWriter` の push 時に、非推奨表記が本文に残っていれば警告する（最初は警告のみ）
- 追加の順序: ①揺れの決定（2 節） → ②固有名詞（5〜7 節）を一括追加 → ③ゲーム内の語（8 節）を各ページの担当者が追加
