# ハーネスのコンテキスト・トークン消費の棚卸しと削減（2026-11-08、Issue #2753）

## 結論

- セッション開始時にリポジトリが足すコンテキストは、変更前で約5.1kトークンだった（実測）。内訳は `CLAUDE.md`＋`AGENTS.md` 1.27k、スキル一覧の説明 3.28k（skc系 1.80k、uloop系 1.48k）、MCP `spec` のツール定義 0.55k。
- skc系スキルの description を短くし、skc系の一覧は 1.80k → 0.88k トークン（-51%）になった。開始時の合計は約5.1k → 約4.2k（-18%）。
- 代表的な依頼24件でスキルの選び方を確かめ、変更前・変更後ともに24件すべて正しいスキルを選んだ（実測、各1回）。
- Codex への委任プロンプトでは、変更前は `CodeGuidelines.md` の抜粋（約10行）を毎回転載していた。変更後は規則のファイル名と節番号だけを書き、同じ課題でプロンプトが 3,304字 → 2,604字（-21%）になった（実測、各1回）。
- 1タスクを通したトークン量は1回ずつしか測っておらず、ばらつきの方が大きい。減ったとは言えない（下の「代表タスク」）。

## 計測の方法

- 実測: このクラウド環境の Claude Code 2.1.319 を `claude -p` で起動した。開始時の内訳は `/context` の出力、タスクの量は `--output-format json` の `usage` で測った。変更前は `origin/develop`（5f95ac34）の worktree、変更後はこのブランチで、同じ手順を実行した。
- `/context` の Skills 欄には、利用者個人のスキル（claude.ai から同期した分や組み込み分）も入る。この欄の合計（変更前 9.2k、変更後 8.3k）は環境によって変わるので、上の結論ではリポジトリの `.claude/skills` の分だけを数えた。
- 文字数は UTF-8 の文字数で、`python scripts/harness/check_harness.py` が出す。トークンの目安は、日本語の本文が1文字あたり約0.8トークン（`AGENTS.md` 1,546字が1.2k）、英語の description が約0.35トークン（実測値からの換算）。以下で「推定」と書いた値はこの換算による。

## 消費の大きい場所

1. **ツールの出力とファイル本文**: 代表タスクでは入力の総量が14万〜40万トークンになり、開始時の約5kとは桁が違う。何をどれだけ読むかと、往復の回数で総量が決まる。ただし入力の約9割はキャッシュからの読み込みだった（実測）。往復のたびに同じ前置きと履歴を読み直す分である。
2. **会話の履歴**: 1回呼んだスキルの本文は、その後の毎ターンに残る。長いセッションで多くのスキルを呼ぶと、その分だけ残り続ける（推定。今回は長時間セッションを測っていない）。
3. **開始時の固定分**: リポジトリの分は約4〜5kで、上の2つより小さい。ただし全セッションにかかる。

## 今回の変更

- skc系11本と Codex 専用2本の description を、何をするか・いつ使うか・似たスキルとの分け方だけに縮めた（各300字以内）。手順・出力形式・前例の説明は本文に残っている。
- `check_harness.py` に、skc系スキルの description は300字以内という検査を足した。uloop系は uloop ツールが入れるものなので対象外にした。各ツールの一覧の合計文字数も表示する。単体テストを2件追加した（計13件成功）。
- `skc-codex-implement`: 共通の規約をプロンプトに転載しない形に直した。タスクで特に効く規則は、ファイル名と節番号だけを書く。プロンプトの要素に「完了条件」を足し、「制約」は「固有の制約」に改めた。「Codex はこのリポジトリの文脈を持たない」という誤った記述は「会話の文脈を持たない」に直した。
- `codex_runner.py`: プロンプトの末尾に「作業ルートの AGENTS.md と、そこから参照する設計思想・コード規約に従う」を1行足す。Claude が規約を転載しなくても、Codex は規約を参照する。
- `Docs/agent/README.md`: 収録一覧を `index.md` に分けた。資料の選び方には、C#の例（敵の攻撃処理）を1行足した。README にも文字数の上限（4,500字）を設けた。

設計思想・コード規約・安全上の規則・PRの手順は削っていない。`AGENTS.md` も変えていない。

## スキル選択の確認

依頼文24件（skc系12本それぞれに1〜2件、uloop-compile、該当なし）を `claude -p` に渡し、最初に使うスキルを1つ答えさせた。変更前・変更後とも24件すべて期待どおりだった。依頼文は日本語で、description は英語のまま。

## 残っていること・提案

- **uloop系の description（1.48kトークン）**: uloop ツールが `.claude/skills` と `.agents/skills` に同じものを入れている。手で直すと更新で上書きされるので、今回は変えていない。減らすなら、`.claude/settings.json` の `skillOverrides` で使う頻度の低いもの（例: `uloop-hot-reload` 約280トークン、`uloop-simulate-mouse-input` 約160トークン）を `"name-only"` にする方法がある。ただし名前だけでは選ばれにくくなるので、使い方を決めてから行う。
- **PCでの確認**: PC の Claude Code で `/context` と `/doctor` を実行すると、PC 側のスキル一覧が予算を超えて説明が落ちていないかが分かる。この環境では利用者個人のスキルが多く、一覧の合計は 8.3k だった。
- **総量の比較**: タスク全体の比較には、同じ依頼を複数回ずつ流して中央値を比べる必要がある。1回あたり約0.1〜0.2ドルかかる（今回の実測）。
- **Codex の実行**: このクラウド環境には Codex CLI が無く、Codex が `AGENTS.md` を読んだ結果、規約どおりのコードを書くかは確かめていない。PC で Codex に委任したとき、Claude のレビューとコンパイルで確かめる手順は変えていない。
