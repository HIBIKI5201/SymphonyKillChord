# TGS後メンバー入れ替え 権利確認・引継ぎ事項一覧（2026-09-27 作成）

TGS 完了に合わせてメンバーをまとめて入れ替えるため、**抜けるメンバー全員**に確認すること、提出してもらうものを洗い出した。
メンバー構成は Notion「クレジット」ページ（`Docs/NotionBackup/2026-09-22/0034-クレジット-5ca78df0.md`）を参照。

> ⚠️ **最優先は3点**
> 1. **利用許諾の期間を「1年」だけにしない**。販売中のビルドに素材が残るため、期限が来ると差し替えか配信停止が必要になる。「期間内に公開したビルド・宣伝物は期間後も配布・販売を続けてよい」という条項を必ず入れる（§1-2）。
> 2. **CRI Atom Craft のプロジェクト本体がリポジトリに無い**。リポジトリにあるのはビルド済みの `.acf` / `.acb`（`Assets/StreamingAssets/`）だけで、`.atmcproject` と素材WAVが無い。このままだとサウンドは誰も編集できなくなる（§3-1）。
> 3. **高等部（未成年）のメンバーには保護者の同意が要る**。クレジット名簿には高等部の在籍者が複数いる（§8）。

---

## 0. 対象者と回収方法

| 区分 | 対象 | 回収するもの |
|---|---|---|
| A. 全員 | 抜けるメンバー全員 | 権利許諾（§1）、クレジット（§2）、アカウント返却（§4）、連絡先（§6） |
| B. 素材を作った人 | デザイナー、イラスト、UI、3D、モーション、VFX、サウンド、シナリオ、声優、動画、Web | A ＋ 元データ提出（§3）＋ 第三者素材の申告（§1-6） |
| C. 管理権限を持つ人 | ディレクター、リード職、アカウント管理者 | A ＋ 権限移譲（§4） |
| D. 声優 | 3名 | A ＋ 声の扱いに関する追加確認（§1-7） |

- **アンケート（Googleフォーム等）だけで終わらせない**。回答を**同意書**の形（PDF化・日付・氏名・署名またはチェック）にし、チームの共有ドライブに保管する。
- 回答は「はい／いいえ」で選べる形にし、**条件付きの回答は自由記述欄**で受ける。条件付きの回答は個別に合意し、結果を記録する。
- **回答の締切は抜ける日より前にする**。抜けた後は連絡が取れなくなる前提で考える。

## 1. 権利・利用許諾（B・D は必須、A も念のため回答）

### 1-1. 権利の形
- [ ] 著作権は**譲渡**か、本人に残したままの**利用許諾**か
  - 学生作品のため譲渡は現実的でない場合が多い。**利用許諾＋著作者人格権を行使しない**形が一般的。
- [ ] **著作者人格権を行使しない**ことへの同意（これが無いと改変や氏名表示の変更で揉める）
- [ ] 許諾先の名義：チーム名、ディレクター個人、学校／G-Lab のどれか（§7 と整合させる）
- [ ] 後任メンバーや将来の運営者へ許諾を**引き継いでよいか**（再許諾・承継の可否）

### 1-2. 利用期間
- [ ] 期間：1年／2年／無期限／「本作が配信されている間」
- [ ] **期間終了後の扱い**（最重要）
  - 期間中に公開したビルド、ストアページ、PV、SNS投稿は期間後も公開し続けてよいか
  - 期間後も購入者のダウンロードやアップデート配信を続けてよいか
  - 更新するときは誰がどう連絡するか。**連絡がつかなければ自動更新**とするか
- [ ] 期間中に抜けたメンバーの素材を**差し替えずに使い続けてよいか**

### 1-3. 利用範囲
- [ ] ゲーム本体（Steam / Google Play / その他のストア）
- [ ] **有償販売**・収益化（無料配布に限るのか）
- [ ] アップデート、DLC、続編、他機種への移植
- [ ] 宣伝：ストアページ、PV、トレーラー、SNS、公式サイト（`HomePage/`）、プレスキット
- [ ] イベント展示（TGS や今後の出展、学校の展示会や説明会）
- [ ] 学校／G-Lab の広報物への掲載
- [ ] グッズ、サウンドトラック、画集などの二次展開
- [ ] コンテストや賞への応募

### 1-4. 改変の可否（職種ごとに具体的に聞く）
- [ ] 全般：色調整、トリミング、リサイズ、圧縮形式の変更、他の素材との合成
- [ ] イラスト／UI：部分的な修正、表情やポーズの差分追加、レイアウトの変更、文字の差し替え
- [ ] 3D：メッシュやトポロジーの修正、リグの変更、テクスチャの描き直し、LOD の作成、衣装や武器の差分
- [ ] モーション：タイミング調整、ブレンド、リターゲット、キーの追加や削除
- [ ] VFX：パラメータ調整、テクスチャの差し替え、シェーダーの変更
- [ ] サウンド：ループ編集、ステム単位の再ミックス、テンポやキーの変更、短縮版の作成、**音楽同期用のタイミング調整**
- [ ] シナリオ：文章の修正、分岐の追加、ローカライズ（翻訳）
- [ ] 声：音量、EQ、エフェクト、ピッチ変更、切り貼り
- [ ] **後任が作り直した場合、元の素材を削除して置き換えてよいか**
- [ ] 改変したことをクレジットに書く必要があるか（例：「原案：○○」）
- [ ] **生成AIによる改変、AI学習への利用の可否**（特にイラストと声は「不可」とする人が多いので必ず確認）

### 1-5. 本人による利用（ポートフォリオ）
- [ ] 本人がポートフォリオや就職活動に使ってよいか（原則「可」と明示する方が回答者の安心につながる）
- [ ] 公開してよい時期（リリース前は不可、など）
- [ ] 公開してよい範囲（完成画像のみ／制作過程まで／ゲーム画面の動画まで）
- [ ] 本人が同じ素材を他の作品で使うことの可否（キャラクターなど固有の素材は不可、汎用素材は可、など）

### 1-6. 第三者素材の申告（B は必須）
- [ ] 素材に**他人の素材**を含むか：アセットストア、フリー素材、有料素材、フォント、テクスチャ、ブラシ、SE・音源ライブラリ、ソフト音源のプリセット、フォトバッシュ用写真
- [ ] 含む場合：素材名、入手元URL、ライセンスの種類、**商用利用と再配布の可否**、クレジット表記が要るか
- [ ] 購入したライセンスが**個人名義**の場合、抜けた後もチームで使い続けられるか（アセットストアのシート制など）
- [ ] **生成AIで作ったものを含むか**。含む場合は使ったツールと範囲（ストアや学校の規定で申告が要る場合がある）
- [ ] 反映先：`third-party-notices.md` と Notion「使用素材一覧表」（Notion 側は現状ほぼ空）

### 1-7. 声優の追加確認（D）
- [ ] 収録した音声の利用範囲（ゲーム内／PV／SNS／イベント会場で流す）
- [ ] **追加収録やリテイクに応じられるか**、応じられない場合は**別の声優に交代**してよいか
- [ ] 音声合成やAI学習への利用は**不可**とすることの確認
- [ ] 事務所に所属する予定があるか。所属した後の名義や、事務所の許可が要るかどうか
- [ ] 立ち絵や名前と一緒に宣伝してよいか

### 1-8. 対価・収益
- [ ] 報酬は無し（学生制作）で良いかどうかを**明記**する
- [ ] 有償で販売したときの収益分配の有無と方針（未定なら「未定であり、決まったら連絡する」と書く）
- [ ] 収益の受取人（`Docs/ストア仮登録_手順と事前決定事項_2026-08-14.md` §1-3 で「個人名義口座」が未解決）

### 1-9. 撤回・トラブル時
- [ ] 許諾を撤回できる条件（原則は撤回不可、重大な事情がある場合は協議、など）
- [ ] 本人と連絡が取れなくなった場合は許諾が継続するとみなすこと
- [ ] 問い合わせ窓口（チーム側）

## 3. 元データの提出（B）

### 共通ルール
- **提出先は個人のドライブにしない**。チームの**共有ドライブ**にする（学校アカウントは卒業すると削除されるため）。
- 職種ごとのフォルダに `README`（中身、使ったソフトとバージョン、書き出し設定、命名規則、未完成のもの）を付ける。
- 「ゲームに入っているもの」だけでなく、**ボツ案、差分、制作途中のデータ**も可能な範囲で回収する。
- 提出してもらったら、**後任が開けるか実際に確認**してから完了にする。

### 3-1. サウンド（最重要）
現状：リポジトリにあるのは `Assets/StreamingAssets/*.acb`、`SymphonyKillChord.acf`、`*.h` と `Assets/Arts/Audio/CriData/Settings` だけで、**Atom Craft のプロジェクトは無い**。
- [ ] **CRI Atom Craft プロジェクト一式**（`.atmcproject`、WorkUnits、Materials フォルダ、Global Settings）
  - フォルダごと ZIP にする。**マテリアルのパスが切れていない**ことを確認する
  - Atom Craft と ADX LE の**バージョン**
  - ビルドの設定（出力先、ターゲット、エンコード形式、ストリーミングかオンメモリか）
  - キューシートとキューの一覧、命名規則、AISAC・カテゴリ・REACT・バスの設計意図
  - 現在の `.acb` / `.acf` がどのプロジェクトから作られたかの対応表（例：`CueSheet_0` `MusicSyncMock` などの仮名が残っている理由）
- [ ] **元のWAV**（非圧縮、サンプルレートとビット深度を明記）
- [ ] **DAWのプロジェクト**と**パラデータ（ステム）**、MIDI
- [ ] **BPM、拍子、テンポマップ、小節数、ループ位置、ビート同期に使っているマーカーやブロック情報**（音楽同期のゲームなので、これが無いとBGMの差し替えも追加もできない）
- [ ] 使ったソフト音源やプラグインと、そのライセンス（商用に使えるか）
- [ ] SE素材の出どころ（自作か、素材サイトか）
- [ ] ミックスやマスタリングの基準（ラウドネスの目標値など）

### 3-2. ボイス
- [ ] 収録した原本（テイク違いも含む）、編集済みのデータ
- [ ] 台本の最終版とテイク番号の対応表、収録日、収録環境
- [ ] 採用したテイクの一覧

### 3-3. イラスト／キャラクターデザイン
- [ ] レイヤー付きの原本（PSD、CLIP、Procreate など）、キャンバスサイズ、解像度
- [ ] ラフ、線画、塗り分け、差分
- [ ] 設定資料（三面図、カラーパレット、配色コード、設定の文章）
- [ ] 使ったブラシやフォント

### 3-4. UI
- [ ] Figma や PSD の原本、パーツを切り出した画像、9スライスの指定
- [ ] デザインのルール（色、フォント、余白、サイズの規則）
- [ ] 画面遷移やアニメーションの指示書（`Docs/UI発注書_2026-08-31.md` との対応）

### 3-5. 3Dモデル（背景、キャラクター、武器）

- [ ] 高解像度のテクスチャ原本、ベイクに使ったハイポリ
- [ ] リグとウェイト、スケールと軸の設定、書き出し設定（FBX の設定）
- [ ] 命名規則（`Docs/アセット名リスト_命名規則提案.md` と合っているか）

### 3-6. モーション

- [ ] リターゲットの設定、ルートモーションの扱い、フレームレート

### 3-7. VFX／テクニカルアート

## 4. アカウントと権限の移管（C）

| 対象 | やること |
|---|---|
| GitHub（リポジトリの Admin、Actions の Secrets、self-hosted runner、Environments） | オーナーや管理者を後任に追加する。抜ける人の権限を外す時期を決める |
| Unity（Organization、シート、ライセンス、Unity Cloud） | シートの割り当てを付け替える |
| **CRI ADX LE のライセンス登録者** | 登録者が抜ける場合は、名義変更か再登録の要否をCRIの規約で確認する |
| Steam Direct／Google Play Console（**個人名義**） | 名義人が抜けた後の運用。ユーザーの招待と権限、支払い、税務情報、収益の受取 |
| Notion ワークスペース | オーナー権限、ページの所有者（抜けた人の個人ページに仕様が残っていないか） |
| Discord サーバー | オーナー、Bot のトークン、DiscordLogExporter が使っている認証情報 |
| Figma／Canva／Google Drive | ファイルのオーナーを移す（**学校アカウントが持っているファイルは卒業で消える**） |
| SNS（X、YouTube など）、公式サイトのドメイン | ログイン情報、2段階認証の端末、復旧用のメールアドレスと電話番号 |
| 支払い用のカード、サブスクリプション | 誰の名義で何を払っているかの一覧と、引継ぎ先 |
| 各種 APIキーと秘密情報 | 抜ける人が知っている秘密情報は、抜けた後に**再発行**する |

## 8. 未成年のメンバー

- クレジット名簿には**高等部の在籍者**（プランナー、プログラマー、テクニカルアーティスト、ウェブデザイナー、イラストレーター、声優など）がいる。
- 未成年者の権利許諾や同意は、**保護者の同意**が無いと後で取り消される可能性がある。
- [ ] 誕生日から回答時点で未成年かどうかを確認する
- [ ] 未成年の場合は、同意書に保護者の署名欄を付ける

## 9. アンケート設問案（そのままフォームに移せる形）

**基本情報**
1. 氏名／フリガナ／学校・学科・学年／役職
2. 回答時点で18歳未満か（はい → 保護者の同意欄へ）
