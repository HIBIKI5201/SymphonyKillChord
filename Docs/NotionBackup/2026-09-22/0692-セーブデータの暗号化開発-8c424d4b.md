### 結論
セーブデータ（`JsonUtility` のJSON）を **AES-256-CBC で暗号化**して保存するようにした。目的は**覗き見防止**（ファイルを開いても平文が見えない）。鍵は**端末ごとに初回ランダム生成して PlayerPrefs に保存**し、ソース／ビルドには鍵を含めない。
> 💡 
  **改ざん耐性は提供しない。** サーバー使用不可の制約があり、鍵がクライアント内にある以上、デバイス所有者による改ざんは原理的に防げない。本機能は「覗き見防止＋カジュアルな改ざん抑止」と位置づける。本格的な改ざん耐性が必要になった場合はサーバー検証を別途導入する。

### 注意事項
- **鍵を消すと既存セーブは復号不能になる**。鍵は PlayerPrefs（Win=レジストリ等）にあり、これが消える（掃除ツール等）と `.sav` を復号できない。リポジトリ/ビルドに鍵を出さないためのトレードオフ。
- **AES-GCM は Unity 非対応**。`AesGcm` は実行時に `PlatformNotSupportedException` を投げる（Mono/IL2CPP とも）。そのため CBC を採用。
- **改ざん検知（MAC）は実装しない**。CBC のパディング/長さチェックで「壊れたデータ」は概ね復号失敗になるが、これは検知保証ではない。復号失敗時はログを出して新規データとして続行する（プレイヤーが詰まないため）。
- **クロスプラットフォーム共有は不可**。鍵が端末ごとに異なるため、別端末・別OSのセーブは復号できない（クロスセーブは要件外）。
- 拡張子は `.sav`。中身は暗号バイト列で、JSONではない。

### 機能の概要
- **AES-256-CBC 暗号化** — `Aes.Create()`（既定でCBC＋PKCS7）。IVは保存ごとにランダム生成し、`[IV][暗号文]` 形式で保存。
- **端末別ランダム鍵** — 初回起動時に乱数生成し PlayerPrefs に保存。以降はそれを使用。鍵はソース・ビルドに含まれない。
- **原子的な保存** — 一時ファイルへ書いてから `File.Replace`（既存あり）／`File.Move`（初回）で入れ替え。書き込み中断時のデータ消失を防ぐ。
- **復号失敗時のフォールバック** — 鍵紛失・破損などで復号できない場合は新規データとして続行（落とさない）。

### 実装されたコンポーネント説明

#### 全体の流れ
```Plain Text
SaveSystem (static, キャッシュ管理)
  ├─ LoadAsync<T>() → キャッシュ or SaveBase.ReadAsync()
  └─ SaveAsync<T>() → SaveBase.WriteAsync()

SaveBase (基底クラス)
  ├─ ReadAsync()  : ファイル読込 → SaveCryptoUtility.Decrypt → JsonUtility.FromJsonOverwrite
  │                 （復号失敗時はログを出して新規扱い）
  └─ WriteAsync() : JsonUtility.ToJson → SaveCryptoUtility.Encrypt
                    → 一時ファイルに書く → File.Replace で原子的に入れ替え

SaveCryptoUtility (static)
  ├─ Encrypt() : [IV(16)][暗号文]  (AES-CBC, IVは毎回ランダム)
  ├─ Decrypt() : 先頭のIVを取り出して復号
  └─ EnsureKeys() : PlayerPrefs から鍵を読込 / 無ければ生成して保存
                    （ダブルチェックロックでスレッド安全）

保存先 : Application.persistentDataPath/<型名>.sav
鍵     : PlayerPrefs("SaveKey_v2")  ※リポジトリ/ビルドには含まれない
```

#### 保存先（ディレクトリ）
セーブ本体は `Application.persistentDataPath` 直下に `<型名>.sav`（例: `PlayerSaveData.sav`）。
| OS | パス |
|---|---|
| Windows | `C:\Users\<ユーザー名>\AppData\LocalLow\<会社名>\<製品名>\` |
| iOS | アプリの `.../Documents/`（端末ごとにGUIDを含む） |
| Android | `/storage/emulated/0/Android/data/<パッケージ名>/files/`（設定により内部ストレージ） |
正確な場所は実機で `Debug.Log(Application.persistentDataPath)` で確認するのが確実。鍵(PlayerPrefs)は別の場所（Win=レジストリ `HKCU\Software\<会社名>\<製品名>`、iOS=NSUserDefaults、Android=SharedPreferences）。

#### SaveCryptoUtility
- `Encrypt(byte[])` — IVをランダム生成し AES-CBC で暗号化。`[IV][暗号文]` を返す。
- `Decrypt(byte[])` — 先頭16バイトをIVとして取り出し、残りを復号。長さ不正は `ArgumentException`。
- `EnsureKeys()` — `_encryptionKey` を遅延初期化。PlayerPrefs に鍵があれば復元（Base64・長さ検証）、無ければ乱数生成して保存。ダブルチェックロックで競合を防止。

#### SaveBase
- `WriteAsync()` — JSON生成 → 暗号化 → 一時ファイルへ書込 → `File.Replace`／`File.Mov`（初回）。
- `ReadAsync()` — ファイル読込 → 復号 → `FromJsonOverwrite`。復号失敗（鍵紛失・破損等）は `try/catch` で新規データとして続行。

### 既知の限界と将来
- クライアント完結のため**真の改ざん耐性は無い**（鍵が端末にある）。必要になったら**サーバー検証**へ。
- 端末別鍵のため**セーブの端末/OS間移行は不可**。クロスセーブが必要になったら**アカウント＋クラウドセーブ**設計へ。
