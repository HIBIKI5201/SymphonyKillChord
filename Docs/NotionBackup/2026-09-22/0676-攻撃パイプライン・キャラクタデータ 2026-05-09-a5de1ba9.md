## 改修
  - ▶ `AttackExecutor``.``Execute()` に命中判定が含まれていた

####  問題点
      `AttackExecutor``.``Execute()` 内に命中判定処理が含まれており、攻撃計算処理と命中判定処理の責務が混在していた。
      その結果、`AttackExecutor` が「攻撃結果の計算」だけでなく、「攻撃対象に命中しているかどうか」の判定まで担う構造になっていた。
      この構造には以下の問題があった。
      - 攻撃計算と命中判定の責務が分離されていない
      - `AttackExecutor` の責務が肥大化している

####  対応内容
      命中判定処理を `AttackExecutor``.``Execute()` から分離した。
      命中判定は `**Enemy**` / `**Player**` 側で行い、攻撃実行前に命中可否を判断する構造へ変更した。
  - ▶ `CharacterEntity` の `Health` プロパティ公開を削除

####  問題点
      `CharacterEntity` の `Health` が public プロパティとして公開されていた。
      しかし、`**CharacterEntity**`からメンバー変数の_healthからCurrentHealthや`**MaxHealth**`などが公開できる状況であり、`HealthEntity`を外部から直接参照される用途がほとんど存在しておらず、Entity の内部状態を不要に公開している状態になっていた。
      また、一部の公開プロパティについても同様に未使用となっていた。
      この構造には以下の問題があった。
      - Entity の内部状態が過剰に公開されている
      - カプセル化が崩れている
      - 外部から状態変更される危険性が増える
      - Entity の責務境界が曖昧になる

####  対応内容
      `CharacterEntity``.``Health` の public 公開を削除した。
      また、未使用となっていた public プロパティについても整理し、一部を private field 化した。
      これにより、Entity の内部状態を不要に公開しない構造へ変更した。
  - ▶ `CriticalChance` / `CriticalMultiplier` の値制約不足

####  問題点
      `CriticalChance` および `CriticalMultiplier` に値制約が存在せず、不正な値を生成できる状態となっていた。
      具体的には以下の問題が存在していた。
      - `CriticalChance`
        - 負数
        - `**1**` を超える値
      - `CriticalMultiplier`
        - 負数
      これにより、ドメイン上不正な ValueObject が生成可能となっていた。

####  対応内容
      ValueObject 生成時に値制約を追加した。

#### `CriticalChance`
      以下の範囲外の場合は例外を発生させるよう変更した。
```Plain Text
0 <= value <= 1
```

#### `CriticalMultiplier`
      負数が入力された場合は例外を発生させるよう変更した。
```Plain Text
value >= 0
```
      これにより、不正な値を持つ ValueObject が生成されない構造へ変更した。
  - ▶ `Damage` の値チェック処理が重複していた

####  問題点
      `Damage` にて値制約の throw処理と 0補正処理が重複して存在していた。
      その結果、責務が曖昧になり、処理意図が分かりづらい状態となっていた。

####  対応内容
      0補正 処理は残し、不要となっていた throw 処理を削除した。
      これにより、Damage の値補正責務を単純化した。
  - ▶ `AttackResultView` / `DamagePresenter` の未使用整理

#### 問題点
      未使用となっている View / Presenter が存在していた。
      - `AttackResultView`
      - `DamagePresenter`
      特に `DamagePresenter` は旧実装時代のものであり、現在の構造では使用されていなかった。

#### 対応内容

#### `DamagePresenter`
      現在未使用であり、用途も存在しなかったため削除した。

#### `AttackResultView`
      現状未使用ではあるが、将来的に以下の用途で使用する可能性があるため保持した。
      - WorldSpace UI を利用したダメージ演出
      - 攻撃結果表示
      - 演出通知
      これにより、不要コードを整理しつつ、将来的な演出拡張余地を維持した。
  - ▶ 未使用メソッド・プロパティの整理

#### 問題点
      未使用となっている public メソッドおよび public プロパティが複数存在していた。
      特に `CharacterEntity` では、現在使用されていない public API が残存していた。
      この構造には以下の問題があった。
      - 不要な API が増加する
      - 責務が不明確になる
      - 将来的な保守時に混乱を招く
      - カプセル化が崩れる

#### 対応内容
      未使用となっていた public メソッド・プロパティを削除した。

#### 例外対応
      `AttackStepContext` 内の `IAttacker` / `IDefender` は保持した。
      これは、今後以下のような Step 拡張に利用する可能性があるため。
      - 攻撃力依存ダメージ
      - 防御力依存軽減
      - 属性補正
      - 状態異常補正
      - キャラクター固有処理
      これにより、不要 API を整理しつつ、攻撃 Step 拡張性を維持した。
  - ▶ 無効な `BeatType` 設定が静かに握りつぶされる

#### 問題点
      無効な `BeatType` が設定された場合でも、内部で握りつぶされる構造となっていた。
      その結果、設定ミスが実行時まで発見されず、不正な状態が潜伏する可能性があった。

#### 対応内容
      未使用となっていた public メソッド・プロパティを削除した。

#### 例外対応
      無効な `BeatType` が設定された場合に例外を発生させるよう修正した。
      これにより、ScriptableObject の設定ミスを早期に検出できる構造へ変更した。
  - ▶ 被弾イベント対象識別に `**GetHashCode()**`** **を使用していた

#### 問題点
      被弾イベント対象識別に `**GetHashCode()**` を使用していた。
      しかし、`**GetHashCode()**` はオブジェクト識別用途を保証するものではなく、以下の問題が存在していた。
      - ハッシュ衝突の可能性がある
      - 実装依存となる
      - 安定した識別子として扱えない
      - 実行環境によって変化する可能性がある
      その結果、被弾イベント対象判定の安定性に問題があった。

#### 対応内容
      未使用となっていた public メソッド・プロパティを削除した。

#### 例外対応
      対象識別を** **`**GUID**` ベースへ変更した。
      これにより、各 Entity を安定して識別可能な構造へ変更し、イベント対象判定の安定性を向上した。

  [header_4] 使用されていないメソッドやプロパティが存在する
    今後の開発のために設けておいたか確認しておきたい。
    - ▶ CharacterEntityのpublicプロパティ全般
    - ▶ AttackStepContext
      - IAttacker Attacker
      - IDefender Defender
  [header_4] `Damage`にて値のチェック処理が重複している
    　コンストラクターの引数valueが0より小さい場合のif文が2か所あり、throwと0設定処理両方書かれています。
　ダメージ計算は場合によってで0以下になることはあり得るので、throwはせず、0にした方が良いと思います。
  [header_4] `CriticalChance`、`CriticalMultiplier`には値が0以下場合のチェックがない
    　値が0以下の場合のチェックを追加したほうが良いと思います。
　なお、これは初期化段階で設定される値オブジェクトのため、値異常の時throwしたほうが良いと思います。
  [header_4] `CharacterEntity`のプロパティHealthの公開が不必要に見える
    　CurrentHealthとMaxHealthがHealthから値を取得して外へ出しているので、Healthも公開していると、今後Health取得・操作の際の書き方が同一しない可能性があるため、Healthプロパティはprivateフィールドにした方が良いと思います。
  [header_4] `AttackExecutor.Execute()`の命中判定
    　現状は命中判定はこのメソッドの中にあり、命中しなくても、ダメージ計算が行われている。命中しない場合、AttackExecutor.Execute()を呼ばないようにすることが理想的だと思います。
　プレイヤー側は`PlayerAttackController.ExecuteAttack()`の中で、敵側は`EnemyAttackUsecase.ExecuteAttack()`の中で判定する予想です。
　なお、`EnemyAttackUsecase.ExecuteAttack()`は`AttackResult`を返却しているが、現段階戻り値は使われていないため、メソッドはvoidにすることも検討したいと思います。
