### **課題1 [UX] プレイヤーに与えたい感情が言語化されていない**
- このゲームでユーザーがどういう感情を得るのか / 得てほしいのかがわからない。
ここが無いままだと、実装の優先順位も演出の良し悪しも判断する基準がない。
- Sepはなんとなくわかるが、このゲームの感情曲線は何もわからない。
  - どういう体験設計になるのか？
    - 言葉にしたうえで、「その感情のために何が不足しているか」
「自分たちの能力で作れないところはどこか」を洗い出す。
      - プレイヤーがこちらの提示した仮の正解を行ったときに
FBとして演出やSEや結果などを豪華にする。
        - カメラワーク
        - エフェクト（モーション）
        - UI
        - ダメージ感
    - 作れないこと自体は構わない。ただし出来ない部分を別の手段で補完する必要がある。

### **課題2 [ゲームデザイン] 「新しい」を「面白い」と混同していないか**
- 今のゲームは面白いのか？ / 面白いと思える軸があるのか？
  - Rezみたいだと6/14に話したが、おれはRezを良いデザインだとは思ったが面白いと思ったことはない
    - 新しさやスタイリッシュさは面白さを保証しない。「これは面白いのか？ 自分たちは面白いと思えているか？」に、いま自信を持って Yes と言えないなら、それが課題である。
- 手癖でいれた手触りや見た目を面白いと思っているならそれは間違いである。
- これは努力目標であり、解決を期待しないものである。

### **課題3 [人員問題] 人数を活かせているか**
- 集めすぎて不平等じゃね、という話ではない。
  - そもそも人を集められない/魅力を作れないゲームが悪いからだ。
- 一般的には人が多い方が非効率(コミュニケーション面と作業分担面とある)なので、人をうまく使えているかが気になっている。
  - PMという**学生経験では無駄になりやすい**ポジションが複数ないか。
    - プランナーならまだよいが、プログラマーにPMをさせていないか。
    - タスクに遅延が発生したときにどうするか
    - クリティカルパス(遅れてはならないタスク)に信頼できるメンバーをアサインしているか

### **課題4 [スケジュール] ルックと完成度を定義するための情報**
- Septemberと同じく、製品リリース時のルックがないと完成度を定義できない
