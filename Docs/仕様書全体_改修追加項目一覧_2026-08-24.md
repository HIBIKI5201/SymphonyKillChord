# 仕様書全体 改修・追加項目一覧

作成日: 2026-08-24
対象: Notion「Symphony Kill Chord」配下 全2,018ページ
根拠: `Docs/NotionSpecifications`（2026-08-19 取得）の機械集計と全文検索。件数はすべて実測値である

## 0. この資料の位置づけ

同日に作成した [仕様書と実装の差分分析_2026-08-23.md](仕様書と実装の差分分析_2026-08-23.md) は「実装と食い違っている箇所」を扱い、その全項目は Notion へ反映済みである。
本資料はそれとは別に、**仕様書という文書そのものの構造・鮮度・抜け**を洗い出したものである。実装との一致は問わない。

優先度の基準は次のとおりである。

| 記号 | 意味 |
| --- | --- |
| 最高 | 放置すると誤った実装・誤った発注が生まれる |
| 高 | 読む人が必要な情報へ辿り着けない |
| 中 | 体裁・重複・整理の問題 |
| 低 | あれば良い |

## A. ゲームデザイン仕様（`仕様概要/仕様リスト`）

全35ページ。テンプレートは「仕様概要 / 関連ページ / 関連用語 / 仕様意図 / 詳細説明」で統一されているが、埋まっていない節が多い。

### A-1. テンプレートの空欄が常態化している

**実測**（35ページ中）

| 節 | 空のページ数 |
| --- | --- |
| 関連用語 | 32 |
| 関連ページ | 27 |
| 仕様意図 | 12 |
| 詳細説明 | 3 |

「関連ページ」「関連用語」がほぼ全ページで空である。用語リストには85語が登録されているにもかかわらず、仕様ページから1件も参照されていない状態であり、用語集が事実上使われていない。

**対応案**: 全ページを埋めるのは現実的でないため、次の二択のいずれかを決める。

1. 「関連ページ」「関連用語」をテンプレートから外し、必要なページにだけ書く運用へ変える
2. 用語リンクを埋める作業を、ページ単位でタスク化する

`仕様検討フォーラム/仕様概要ページの要素削減方針` というページが既に存在するため、方針の議論は始まっている可能性がある。**先にそのページを確認してから決める。**

**優先度**: 高

### A-2. 「仕様意図」が空のまま実装済みのもの

「なぜそうするのか」が書かれていない仕様が12件ある。実装が進んだあとで意図が失われると、調整の判断ができなくなる。

対象: インゲームHUD / カメラワーク / ゲームフロー / ゲーム起動時機能 / コアメカニクスについて / タイトル画面 / ボス戦闘 / 体験版開発指針 / 作戦画面 / 改造画面 / 研究モック / 設定画面

このうち **コアメカニクスについて** はゲームの根幹であり、意図が空であるのは影響が大きい。

**優先度**: 最高（コアメカニクス）／高（その他）

### A-3. 更新が止まっているページ

最終更新が古い順に、実装が動いた領域と重なるものを挙げる。

| ページ | 最終更新 | 懸念 |
| --- | --- | --- |
| セーブデータ | 2026-04-17 | 「カテゴリーは主に五種類」と書かれているが、実装の`SaveData`は現在5つのサブデータを持ち、そのうち音量設定は2026-08に追加されたものである。列挙の中身が当時のままか要確認 |
| インゲームHUD | 2026-04-18 | 子ページへのリンクのみで、仕様意図・詳細説明が空。この間にHUDは大きく変わっている |
| コンボについて | 2026-04-18 | コンボ表示の実装（`ComboHudView`）は2026-08に変更されている |
| レベルデザイン方針 | 2026-04-18 | ステージ制作が進行した後、更新されていない |
| 研究モック | 2026-04-17 | 「研究画面」（2026-08-18更新）と併存。モック側が役目を終えていないか要確認 |
| カメラワーク | 2026-05-29 | カメラシェイクが2026-08に追加されたが、デザイン仕様側に記述が無い |
| 設定画面 | 2026-05-29 | 「コンフィグ」（2026-08-04）と内容が重なる |

**優先度**: 高（セーブデータ・インゲームHUD・カメラワーク）／中（その他）

### A-4. 重複しているページ

| 組 | 状況 |
| --- | --- |
| 設定画面（5/29）／ コンフィグ（8/4） | どちらも設定項目を扱う。どちらが正本か不明 |
| 研究モック（4/17）／ 研究画面（8/18） | モックと本実装の関係が明示されていない |

**対応案**: 現行でないものへ「このページは終了したフェーズのものである」旨を明記するか、アーカイブへ移す。

**優先度**: 中

## B. システム仕様（`システム概要/システムリスト`）

全70ページ。**2026-08-17〜18に一斉更新された31ページ**が現行のモジュール文書で、リポジトリ側の正本（`Assets/Docs/ScriptsDocs/Modules/NotionModuleDocs/*.md`）と1対1で対応している（31 ↔ 31、確認済み）。残り39ページは性質の異なる文書が混在している。

### B-1. 旧世代の設計メモが現行文書と同列に並んでいる

タイトルに日付が入った、特定時点のスナップショット文書が現行モジュール文書と同じデータベースに並んでいる。

| ページ | 最終更新 | 現行の対応ページ |
| --- | --- | --- |
| プレイヤー　2026-05-08 | 2026-05-13 | プレイヤー |
| 敵関連　2026-05-08 | 2026-05-08 | 敵 |
| 攻撃パイプライン・キャラクタデータ 2026-05-09 | 2026-05-14 | キャラ&バトル |
| カメラ　2026-05-09 | 2026-05-13 | カメラ |
| スキル　2026-05-09 | 2026-05-09 | スキル |
| 音楽同期　2026-05-05 | 2026-05-05 | 音楽 |

**問題**: 検索で先に旧版が出ると、古い設計をそのまま実装してしまう。特に「攻撃パイプライン・キャラクタデータ」は493行と大きく、検索で上位に来やすい。

**対応案**: 冒頭にアーカイブである旨のコールアウトを入れ、現行ページへのリンクを置く。または`システム概要/アーカイブ`へ移す。

**優先度**: 最高

### B-2. 開発計画・調査記事がモジュール文書と混在している

次は「モジュールの仕様」ではなく、計画や技術調査のメモである。

- 7月 リファクタリング / 7月β大改修リファクタリング（いずれも13行。計画期間は終了している）
- ポーズシステム開発 / 設定システム開発 / セーブデータの暗号化開発 / スキルツリー開発について / 装備BGM切り替えシステム / セーブシステム / シーンのチケットシステム
- Adaptive Performance Package（385行）/ GCスパイク対策について / TBDRにおける最適化 / 最適化関連記事まとめ / Android向けのAddressablesとPAD関連記事集 / Android端末からパフォーマンスデータの収集について / Behavior Graphについて
- クライアント部門研修（423行）/ デザイナー向け SourceTreeを用いた作業説明

**対応案**: 3つに分ける。

| 区分 | 移動先 |
| --- | --- |
| 開発計画（終了済み） | アーカイブ |
| 技術調査・最適化記事 | `システム概要/技術リサーチ`（新設） |
| 研修・作業説明 | ワークフロー配下（`デザイナー向け SourceTreeを用いた作業説明`は、ワークフロー改修計画1-1のUnityセットアップ統合の材料でもある） |

**優先度**: 高

### B-3. 「〜開発」ページと現行モジュール文書の関係が不明

`設定システム開発`（283行、6/17）と`セッティング`（147行、8/17）、`セーブシステム`（410行、6/29）と`セーブ`（193行、8/17）のように、旧い「開発」ページのほうが記述量が多い組がある。現行ページへ移すべき内容が旧ページに残っている可能性がある。

**対応案**: 組ごとに突き合わせ、現行ページに無い有用な記述を移してから旧ページをアーカイブする。

**優先度**: 高

### B-4. ページ本体がハブに載っていない

`システム概要`ページ本体は「コード規定 / GitHub運用規定 / 設計思想 / システムリスト / 記法確認用ページ（削除可）」の5リンクのみである。「記法確認用ページ（削除可）」が本番のハブに残っている。

**対応案**: 記法確認用ページを削除する（Notion上での手作業が必要）。あわせて、B-2で新設する区分をハブへ追加する。

**優先度**: 中

## C. 全体構造

### C-1. 用語集が使われていない

用語リストに85語が登録されているが、`仕様リスト`35ページのうち32ページで「関連用語」が空である（A-1）。用語ページ自体の最終更新は2026-05-04で、以降の機能追加（状態効果、スキルエフェクト、戦闘ポーズ等）の語が入っていない可能性が高い。

**対応案**: 2026-08以降に追加された概念の用語を追加し、少なくとも主要仕様ページからは参照する。`Docs/用語集_追加候補.md` がリポジトリに既にあるため、これを起点にできる。

**優先度**: 高

### C-2. 仕様概要とシステム概要の対応が取れていない

同じ機能について、ゲームデザイン側（`仕様リスト`）と実装側（`システムリスト`）の両方にページがあるが、相互リンクが無い。例として「敵」は両方にあり、片方だけを読んでも全体が分からない。

**対応案**: 対応表を1ページ作る。全ページに相互リンクを張るより安く、抜けも見える。

**優先度**: 中

### C-3. ワークフローの改修

別資料 [ワークフローページ改修計画_2026-08-24.md](ワークフローページ改修計画_2026-08-24.md) に分けて記載した。要点のみ再掲する。

- Unity環境構築が3か所へ分散しており、統合ページが必要
- 「オンボーディング」「リリース」「QA」に該当する記述が1件も無い
- ディレクター・シナリオライター・声優のページがリンク1本のみ
- コード規約・Git運用・設計方針がワークフローとシステム概要へ分裂

**優先度**: 高

### C-4. 「名称未設定」のデータベースがルートに並んでいる

ルートページのリンク一覧に「名称未設定」という表示のリンクが4件ある（仕様検討フォーラム / 議事録 / 使用素材一覧表 / マスターデータ / アセットデータベース）。エクスポート上の表示であり、Notion上でも同様かは要確認である。

**優先度**: 低
