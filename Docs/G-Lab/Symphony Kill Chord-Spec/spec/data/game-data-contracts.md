# ゲームデータ契約

ステータス: partial（部分完了）。仕様および実装済み状態の静的証拠のみを対象とする。

## 永続セーブ状態

正式なセーブ仕様は、クリア済みステージノード、スキルツリー進捗、装備中のキルコードと順序、キルコード別レベル、オプションの5分類を要求している。現在の `SaveData` には、ステージ進捗、チュートリアル状態、スキル解放状態、装備中スキル、レベルアップポイントの合計残高が含まれる。シリアライズには Unity の `JsonUtility` を使用し、`Application.persistentDataPath` 配下へセーブ種別ごとに1ファイルを保存する（`Assets/Scripts/Runtime/0.Utility/Savedata/SaveBase.cs`）。

確認できた制約:

- `SavedataSystem` はセーブ種別ごとに書き込みを直列化する。
- 一時ファイルを先に書くが、一時ファイルを移動する前に現在の対象ファイルを削除する。バックアップとスキーマバージョン項目はない。
- デシリアライズ例外はログ出力後に抑止され、呼び出し側からは生成済みの初期値が利用可能なままになる。
- 旧データ識別子の移行処理は別箇所にあるが、これは識別子互換であり、明示的なセーブスキーマ移行契約ではない。
- 調査した `SaveData` 経路には、スキル別レベル、オプション、β版で要求された暗号化が存在しない。

## マスターデータ

ステージ定義はミッションと、スキル強化ポイント／スキル解放・研究ポイントの2種類の報酬量を公開する。スキルツリーのノードアセットは整数の解放コストを持つ。リポジトリ内の設計資料では、敵と攻撃の定義もデータ駆動とする方針である。

検証上の不足:

- アセット参照の欠落は実行時まで判明しない場合が多い。
- 敵攻撃ユースケース3件が、敵／マスターデータの攻撃値ではなく `new Damage(10)` を使用している。
- バージョン付きコンテンツbundleやデータ移行契約は確認できない。

## 識別子

ステージ、ミッション、スキル、ノード、攻撃、キャラクターはドメイン層で型付き識別子を使用する。一方、`PlayerAttackController` は一時的な標的識別子としてエンティティのhash codeを使用しているため、この経路の識別子安定性は保証されていない。
