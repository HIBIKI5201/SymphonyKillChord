# Notion 一元化 移行用ドキュメント

作成日: 2026-09-22
基準: origin/develop `73fefeb45` / Notion 仕様書 公開スナップショット 2026-09-22 取得（ルート「Symphony Kill Chord」配下 1,078 ページ・49 DB。タスクリスト系 DB の行ページは対象外）

## 目的

チームの方針は、仕様・システム・アセットの情報を **Notion 仕様書に一元化し、Unity リポジトリ上のドキュメントは全て削除する**ことである。
2026-09-22 に次のことが決まった（八幡さん）。

- Notion が正本であり、リポジトリは Notion の写し（キャッシュ）とする。
- ツールが読む文書も Notion に置き、リポジトリにキャッシュして使う。
- そのために Notion 側の書き方を見直す。
- 書き込み許可範囲の拡張は後日行う。
- キャッシュは `Library/` に置き、git で管理しない（今の `Docs/NotionSpecifications` も移す）。
- キャッシュは各自が手動で更新し、スキルからは AI が更新する。定期的には取り直さず、必要なときに関連ページの更新日時だけを確かめ、変わったページだけを取り直す（API 制限のため）。
- エージェントのログは `Docs/agent/` で管理する（`Docs/` は gitignore のまま）。不具合ログは GitHub Issue に送る。

この決定を実現する設計案は [02_キャッシュ運用とNotion記述規約.md](02_キャッシュ運用とNotion記述規約.md) にある。
このフォルダはその移行作業の台帳である。中身は次の 2 つである。

1. **Notion に反映すべき項目の一覧**: TGS 対応などで変わった内容、仕様書で厳密に定義されていない仕様、仕様書にあるが実装されていない（または撤回された）内容。
2. **リポジトリ内ドキュメントの棚卸し**: 各文書を Notion へ移すのか、そのまま消すのか、残すのかを判定したもの。

2026-09-22 のセッションでは、このフォルダの作成までを行った。**Notion への書き込みも、リポジトリ文書の削除も、まだ一切行っていない。**
移行作業は [00_移行作業手順書.md](00_移行作業手順書.md) に従って別途行う。

## 読み方

- 各リストの冒頭に**反映先ページ別サマリ**がある。Notion の 1 ページごとに、反映すべき項目 ID がまとまっている。反映作業はこの表の単位で行う。
- 各項目には「種別」「優先度」「反映先（Notion ページパスと page id）」「仕様書の現記述」「実装の実態（根拠のファイル:行・PR 番号・マスターデータ）」「反映内容案」「確認」を書いた。
- 「確認: 要企画確認」の項目は、**実装を仕様として追認するのか、実装を直すのかが決まっていない**。Notion へそのまま書き写してはならない。一覧は [90_未決事項.md](90_未決事項.md) にある。
- 実装パスは、リポジトリルートからの相対パスで書いた。`Runtime/` は `Assets/Scripts/Runtime/`、`Data/` は `Assets/Level/Data/Master/` の略である。
- 行番号は `73fefeb45` 時点のものである。

## 調査の方法と限界

- Notion は公開ページ API（`loadPageChunk` ほか）で全ページを取得し、Markdown に変換して読んだ。画像・埋め込みの中身は読んでいない。DB の行はプロパティまで取得した。
- 実装はコード・マスターデータ（ScriptableObject の YAML）・シーン/プレハブの YAML・2026-08-15〜09-22 にマージされた PR 506 件の本文を読んで判断した。**Unity の実行・実機確認はしていない。**「要実機確認」の項目は挙動をまだ確かめていない。
- 領域は 6 つに分けて調べた。境界にある項目は複数のリストに出ることがあり、その場合は「関連: 他領域」と注記してある。
- 前回の同種調査（`Docs/仕様書と実装の差分分析_2026-08-23.md`、`Docs/仕様書全体_改修追加項目一覧_2026-08-24.md`）の指摘は、Notion で反映を確認できたものは除き、未反映のものは再掲した。

## 最優先で対応すべきもの（移行作業とは別に、すぐ）

1. **公開 Notion ページに API キーが平文で載っている。** 「シナリオCSV～ドライブ同期～」に Google API キー、「シーンのチケットシステム」に apiKey がある（[40](40_チュートリアル・体験版・シナリオ.md) SC-06、[50](50_基盤・ツール・規約.md) TL-21）。公開サイトなので誰でも読める。ページから削除し、キーを失効・再発行する。このフォルダにはキーの値を転記していない。
2. **既に壊れている参照がある。** `.coderabbit.yaml` が存在しない `Assets/Docs/AGENTS.md` を指し、`notion-spec-diff-check` スキルが存在しない差分分析（2026-07-27 版）を前例として指している（[01](01_ドキュメント棚卸し.md) の「既に壊れている参照」）。
