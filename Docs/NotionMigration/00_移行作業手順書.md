# Notion 一元化 移行作業手順書

作成日: 2026-09-22
対象: origin/develop `73fefeb45` / Notion 公開スナップショット 2026-09-22 取得（1,078 ページ・49 DB）

この手順書は、本フォルダの反映項目リストを Notion 仕様書へ適用し、その後 Unity リポジトリ上のドキュメントを削除するまでの作業を定義する。
今回のセッションで行ったのは**移行用ドキュメントの作成まで**であり、Notion への書き込みとリポジトリからの削除はまだ一切行っていない。

## 1. 着手前の準備

### 1.1 読むもの

1. [README.md](README.md) — 本フォルダの構成と各ファイルの役割
2. [90_未決事項.md](90_未決事項.md) — 企画・リードの判断が必要な項目。**「移行前に決める」は段階 0 で必ず決める**
3. 担当する領域の反映項目リスト（10〜60）

### 1.2 Notion の書き込み経路と権限

Notion 本体への書き込みは次の 2 経路がある。

| 経路 | 使いどころ | 注意 |
| --- | --- | --- |
| Notion 上で手作業 | DB の行追加・プロパティ変更、ページ削除・移動、画像の貼り付け、書き込み許可範囲外のページ | 最も確実。DB 系はこちら |
| `SinfoniaOperator/NotionMarkdownWriter.exe`（`/notion-spec-write` スキル） | 本文の追記・書き換え、新規ページ作成 | pull → 編集 → dry-run → **人の承認** → `--confirm` の順を必ず守る |

NotionMarkdownWriter が書き込めるのは `SinfoniaOperator/sinfonia-operator.env.json` の `NOTION_WRITE_ALLOWED_ROOTS` の配下だけである。2026-09-22 時点の許可範囲は次のとおり。

| page id | ページ |
| --- | --- |
| `27d7c2c6-cc02-819a-9547-f211f355dfec` | 仕様概要（DB「仕様リスト」35 件を含む） |
| `27d7c2c6-cc02-818d-95ec-c1dc9a3c6761` | システム概要（コード規定・GitHub 運用規定・設計思想） |
| `27d7c2c6-cc02-81ee-963f-f0e4195b52e0` | DB「システムリスト」（75 件） |
| `2ef7c2c6-cc02-8001-b4f0-d69b499c64f0` | ワークフロー |
| `3407c2c6-cc02-80a8-8e99-ebbfb7733e1c` | DB「マスターアセットリスト」 |

**用語、サウンド、ストーリー、ビジュアル、アセットデータベース、使用素材一覧表、仕様検討フォーラム、議事録、クレジットは許可範囲外**である。
反映項目の反映先がこれらの場合は、(a) Notion 上で手作業する、(b) 許可範囲に追加する PR を出す、のどちらかを選ぶ（[90_未決事項.md](90_未決事項.md) の D-03）。
許可範囲の追加はリポジトリの変更としてレビューされる前提の設定なので、作業者が勝手に追記しない。

ツールには Notion API のトークン（`NOTION_TOKEN`、`SinfoniaOperator/sinfonia-operator.secrets.json`、gitignore 対象）が要る。無い場合は管理者から受け取る。

### 1.3 文体

仕様書ライティング規則（Notion「仕様書 ガイド / 仕様書 ライティング規則」）に従う。要点は、である調・文末句点（リスト項目と括弧内は付けない）・H1 に背景色。
反映項目リストの「反映内容案」は要点の箇条書きであり、そのまま貼らずにこの規則で文章化する。

## 2. 段階 1: スナップショットの取り直し

反映項目リストは 2026-09-22 時点の Notion と develop を突き合わせたものである。作業開始日までに双方が更新されていると、既に反映済みの項目を二重に書いたり、消えた記述を前提にしたりする。

### 2.1 Notion 側

どちらか一方を使う。

- **トークンあり**: リポジトリルートで `./SinfoniaOperator/NotionMarkdownExporter.exe --output "Docs/NotionSpecifications" --no-assets`
  - 出力は gitignore 対象のローカルミラー。約 2,000 ページ（タスク DB を含む）。差分更新なので 2 回目以降は速い。
- **トークンなし**: 本フォルダの `tools/crawl-public-notion.js` を Node.js 18 以上で実行する（公開ページを認証なしで取得。今回のスナップショットはこれで取った）。
  - `node Docs/NotionMigration/tools/crawl-public-notion.js <出力先>` で、出力先（省略時は `./notion-snapshot`）に 1 ページ 1 ファイルで書き出し、`_INDEX.tsv` と `notion-index.json` にページ一覧を出す。約 20 分。**出力先はリポジトリ外（またはgitignore 対象）にする。**
  - タスクリスト・時間割・休暇日 DB の行ページは辿らない（数千件あり仕様ではないため）。

取り直したら、[notion-page-index_2026-09-22.tsv](notion-page-index_2026-09-22.tsv) と `last_edited` を比べ、**2026-09-22 以降に更新されたページ**を一覧にする。そのページを反映先とする項目は、適用前に現記述を読み直す。

### 2.2 実装側

```bash
git fetch origin
git log --oneline 73fefeb45..origin/develop
```

73fefeb45 以降のマージで、反映項目の「実装の実態」が変わっていないかを確認する。変わっていたら項目の記述を直してから反映する。

## 3. 段階 2: 反映項目の適用

### 3.1 進め方

1. 領域別リスト（10〜60）を 1 ファイルずつ担当者に割り当てる。1 ファイルの中では **優先度「最高」→「高」→「中」→「低」** の順に処理する。
2. 各項目の「確認」欄で分岐する。
   - `事実のみ` — そのまま文章化して反映してよい。
   - `要企画確認` — 仕様意図の判断が要る。**企画（プランナー）に確認してから反映する**。実装を仕様として追認するのか、実装を直すのかが決まっていないものを含む。後者なら反映せず Issue を立てる。
   - `要実機確認` — 実機（またはエディタ）で挙動を見てから書く。
3. 反映したら、項目見出しの直下に次の 1 行を追記してコミットする（本フォルダは削除までの作業台帳を兼ねる）。

   ```
   - 状態: 反映済 2026-MM-DD <担当者> <Notion ページ URL>
   ```

   見送る場合は `- 状態: 見送り 2026-MM-DD <担当者> <理由>`。
4. 1 ページに複数の項目が載る場合は、[各リストの「反映先ページ別サマリ」] で同じページの項目をまとめ、1 回の編集で反映する（NotionMarkdownWriter の pull〜push を 1 回で済ませる）。

### 3.2 種別ごとの書き方

| 種別 | Notion 側の処理 |
| --- | --- |
| 変更反映 | 古い記述を書き換える。経緯が必要なら「変更履歴」トグルに「2026-09 TGS 対応で X→Y（PR #nnnn）」の形で残す |
| 未定義仕様 | 該当節に数値・条件・例外時挙動を追記する。数値はマスターデータ（ScriptableObject）が正本である旨とアセットパスを添える |
| 仕様のみ | 記述を消さず、冒頭に「未実装」「体験版では無効」「撤回」などの状態を明記する。撤回なら企画確認のうえ削除 |
| リポ文書から移植 | 新規ページまたは既存ページの節として移す。移した先の URL を [01_ドキュメント棚卸し.md](01_ドキュメント棚卸し.md) の該当行に書く |
| 構造 | ページ統合・削除・移動は Notion 上で手作業。削除はゴミ箱送りで 30 日は戻せる |

### 3.3 システムリスト（モジュール文書）の扱い

現行運用では `Assets/Docs/ScriptsDocs/Modules/NotionModuleDocs/<Module>.md` が**正本**で、`scripts/notion/sync_module.py` で Notion の「システムリスト」各ページへ反映している（`.claude/skills/notion-spec-write/references/module-docs.md`）。
リポジトリ文書を全削除する方針はこの運用と正面から衝突する。段階 0 で次のどちらにするかを決める（[90_未決事項.md](90_未決事項.md) の D-01）。

- **A. Notion を正本にする（方針どおり）** — 最後に一度だけ正本から Notion へ同期し（`sync_module.py`）、以後は Notion を直接編集する。`NotionModuleDocs/`・`scripts/notion/split_module_doc.py`・`sync_module.py`・module-docs.md の運用節を削除または書き換える。
- **B. モジュール文書だけはリポジトリに残す** — コードと同じ PR で更新できる利点を取る。この場合「全削除」の例外として明記する。

A を選ぶ場合、同期前に NotionModuleDocs と Notion の各ページの差を確認する（20・50 の各リストに差分項目がある）。

## 4. 段階 3: リポジトリ文書の移植

[01_ドキュメント棚卸し.md](01_ドキュメント棚卸し.md) の「推奨処置」で分岐する。

| 推奨処置 | 作業 |
| --- | --- |
| Notion 移行後に削除 | 「移行内容」に書かれた情報を Notion へ移し、移行先 URL を記入する。移したら削除対象リストに入れる |
| Notion 移行不要・そのまま削除 | 陳腐化・実装済みの計画書など。**削除前に一度だけ担当者に確認**し、削除対象リストに入れる |
| リポジトリ残置を推奨 | ツール・AI・ビルドが読むもの。段階 0 の決定（D-02）に従う。残すなら「全削除」の例外として README に列挙する |
| 要判断 | 段階 0 で決める |

計画書（`Assets/Docs/*計画書.md` 等）を移すときは、計画そのもの（手順・工数）ではなく**確定した仕様と設計判断の理由**だけを移す。実装済みの手順は移さない。

## 5. 段階 4: 参照の付け替え

削除すると壊れる参照は [01_ドキュメント棚卸し.md](01_ドキュメント棚卸し.md) の「削除すると壊れるもの」と [50_基盤・ツール・規約.md](50_基盤・ツール・規約.md) の該当項目に列挙した。削除 PR の前に、少なくとも次を確認する。

```bash
# 削除対象パスの一覧を deletion-list.txt に 1 行 1 パスで作ってから
while read -r p; do
  name=$(basename "$p")
  git grep -n -F "$name" -- . ':!Docs/NotionMigration' | grep -v -F "$p:" || true
done < deletion-list.txt
```

特に注意するもの:

- `.claude/skills/`・`.codex/skills/`・`.agents/skills/`・`AGENTS.md`・`.gemini/GEMINI.md` が読むリポジトリ文書（コード規約・設計思想・モジュール文書・QA シート等）。削除するなら、スキル側を Notion URL 参照へ書き換えるか、スキル自体の手順を変える。
- `SinfoniaOperator/spec-search-priority.json` などツールの設定に書かれたパス。
- C# の Editor ツール・CI（`.github/workflows/`）が読む文書やデータ。
- Unity の `.meta`。`Assets/` 配下の文書は `.meta` と対で消す。フォルダごと消すならフォルダの `.meta` も消す。

## 6. 段階 5: 削除 PR

- ブランチを切り、削除は **1 PR** にまとめる（main / develop 直 push 禁止）。
- PR 本文に、削除したファイルと移行先 Notion URL の対応表を貼る（01 の表から生成）。
- CSV などのデータ（`Assets/StreamingAssets/ScenarioAuthoring/*.csv`、`CreditMembers.csv` など）は**ドキュメントではなくゲームが読むデータ**なので削除対象にしない。
- `README.md`・`third-party-notices.md`・フォントの `OFL.txt` などライセンス・リポジトリ案内は残す（ライセンス表記は配布物の義務）。
- マージ前に Unity でコンパイル（`/uloop-compile`）し、Addressables のビルドエラーが出ないことを確認する。文書を Addressables に登録している場合はグループからも外す。

- 全項目の状態が `反映済` / `見送り` になったら、本フォルダ `Docs/NotionMigration/` を削除する PR を出す（段階 5 の PR に含めてもよい）。

## 付録 A. 反映項目の書式

