## 2. 原稿の読み方

各原稿は次の順に並んでいる。
- 冒頭: page_id / Notion パス / スナップショットの最終更新 / 書き込み許可 / 処置
- 判定: 信頼性、整合性、変更点、織り込んだ反映項目、出典、要確認
  - 変更点は「旧 → 新」の形で、節の名前を添えてある。
- 適用する本文: Notion にそのまま貼れる完成版

処置の種類は次のとおり。

| 処置 | 意味 |
| --- | --- |
| 本文置き換え | 「適用する本文」でページ本文を置き換える |
| 追記のみ | 指定された節に、「適用する本文」を足す |
| 統合 | 統合先のページに内容を移し、このページはリンクだけにする（または削除） |
| アーカイブ推奨 | 冒頭に「アーカイブ（現行仕様ではない）」と書くか、アーカイブ用の親ページへ移す。どちらにするかは要企画確認 |
| 削除推奨 | 本文が空など |
| 変更不要 | 索引にだけ載せ、原稿は無い |

`db-<DB の id>.md` は、DB の行ごとの更新表である（列: 行 / プロパティの現在値 → 正しい値 / 根拠 / 追記する本文）。DB の行とプロパティは NotionMarkdownWriter では書けないので、Notion 上で手作業する。

書き方は、現行ページのレイアウトと口調に合わせてある（2026-09-22 八幡さんの指示）。既存の節構成・見出し・絵文字・表の列は変えていない。

**見出しの段について:** 調査に使ったスナップショット（`tools/crawl-public-notion.js` の出力。リポジトリには入れていない）は、取得スクリプトの都合で Notion の見出しを 1 段下げて記録している（Notion の H1 が `##`）。原稿は Notion 上の実際の段に戻してある。

`【要確認: …】` の箇所は、確かめないまま本文を確定させてはいけない。判定の「要確認」にも同じものが載っている。

## 3. 適用の手順

[../00_移行作業手順書.md](../00_移行作業手順書.md) の段階 2 に従う。そのうえで、次の点に注意する。

1. **適用前に、ページが変わっていないか確かめる。** 原稿冒頭の「スナップショットの最終更新」と、Notion 上の最終更新を比べる。新しくなっていたら、差分を読んでから原稿を直す。
2. **書き込み許可「可」のページ**は、NotionMarkdownWriter で pull → 原稿を反映 → dry-run → 承認 → `--confirm` の順に進める。本文置き換えは `push --whole` を使う。
   **書き込み許可「不可」のページ**（用語・サウンド・ストーリー・アセットデータベース など）は、許可範囲を広げるまで Notion 上で手作業する（D-03）。
3. **【要確認】を先に解く。** 各領域の `_INDEX.md` と原稿の「要確認」を担当者に回す。企画の判断が要るものは [../90_未決事項.md](../90_未決事項.md) の第 2 部と重なる。
4. **適用したら**、原稿冒頭の処置の下に `- 状態: 反映済 2026-MM-DD <担当者>` を追記してコミットする。
