## 概要
> 💡 **モジュール概要**
> 体験版（Demo）ビルド専用のランタイムを常駐させ、ホーム滞在時間・体験版全体時間の二つのタイマー管理、期限切れの通知、ホーム時間切れ時の強制出撃、全体時間切れ・最終ステージクリア時の専用終了シーンへの遷移、終了シーンの演出、終了時のセーブデータ削除を司るモジュールである。`KillChord.Demo`という独立アセンブリで構成され、`KILLCHORD_DEMO`スクリプティング定義シンボルが有効な場合のみコンパイルされる。

#### 🧩 Composition初期化情報
> `DemoRuntimeBootstrap`は他モジュールのような`~Initializer`＋`Order`によるComposition層のパターンを採らない。`[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]`が付与された静的メソッド`CreateInstance()`自体がエントリポイントであり、シーン初期化フローの外側から独立して起動する。
| 項目 | 内容 |
|---|---|
| **エントリポイント** | `DemoRuntimeBootstrap.CreateInstance()`（`RuntimeInitializeOnLoadMethod`、`AfterSceneLoad`） |
| **生成方法** | Addressablesアドレス`"DemoRuntime"`のプレハブをロードし、`Instantiate`後に`DontDestroyOnLoad`で常駐化する |
| **アセンブリ制約** | `KillChord.Demo.asmdef`の`defineConstraints`に`KILLCHORD_DEMO`を指定しており、当該シンボルが有効なビルドでのみアセンブリごとコンパイルされる |
| **公開する ServiceLocator登録型** | `DemoRuntimeBootstrap.Start()`が`IDemoSession`（`DemoSessionState`本体）と`IStageResultExitPolicy`（`DemoStageResultExitPolicy`）の2つを登録する |
| **DemoEndシーンのInitializer** | `DemoEndSceneInitializer` = 0 / `DemoEndSequenceInitializer` = 30（通常の`~Initializer`＋`Order`のパターン） |

#### 📥 依存しているもの
- `**OutGame/StageSelect**`
  - *依存箇所*: `StageSelectModuleContainer`（`StageTree`、`TryForceBattleSortie`）
  - *詳細*: ホーム制限時間切れを検知すると、通知の後、ホームチュートリアルを強制完了させ、解放済みのバトルステージのうち前提をたどった距離が最も長いものを`TryForceBattleSortie`で要求する。作戦画面はそのステージを選んで詳細を表示し、戻る・装備変更・設定・ステージマップ・別ステージの選択を無効にして出撃だけを許す。ロード中は保留し、ロード後に最新の解放状態から選び直す
- `**OutGame/Screen**`
  - *依存箇所*: `OutGameUIEvent`（`OnHomeTutorialStarted`、`OnHomeTutorialForceCompleteRequested`）、`IScreenStateRepository`
  - *詳細*: ホームチュートリアルの開始通知を受けてからホームタイマーを動かす。ホーム制限時間切れでホームチュートリアルの強制完了を要求する。表示中の画面IDを取得してタイマーの位置を変える
- `**InGame/Result**`
  - *依存箇所*: `IStageResultExitPolicy`（拡張点となる抽象で、詳細はResultモジュール側の文書を参照）
  - *詳細*: `DemoStageResultExitPolicy`がこの抽象を実装し、体験版全体時間切れ、または最終ステージ（ステージツリー上で最も深いバトルノード。体験版のツリーでは`stage_04`、表示名「3」）クリア時に、通常のリザルト遷移先を体験版終了シーンへ差し替える
- `**Persistent/Savedata**`
  - *依存箇所*: `SaveStore`、`SaveData.Tutorial.Phase`、`SaveData.StageProgress`
  - *詳細*: `Tutorial.Phase`が`HomeStarted`以上のときにホームタイマーを開始し、最終ステージのクリア判定にも`SaveData`を参照する。体験版終了シーン到達時には`SaveStore.DeleteAsync<SaveData>()`でセーブデータを削除する
- `**Persistent/Load**`
  - *依存箇所*: `EventNotificationView`、`LoadingScreenController`
  - *詳細*: 期限切れの通知を常駐の通知Viewで出す。ロード中は開始・強制出撃・終了遷移を保留する
- `**Persistent/SceneManagement**`
  - *依存箇所*: `SceneTransitionUsecase`、`SceneTransitionController`、`ISceneInitializationReadiness`
  - *詳細*: 全体時間切れのとき、戦闘中なら戦闘シーンとInGameをアンロードしてから、それ以外は現在のシーンから、体験版終了シーン（`DemoExperienceConfig.EndSceneName`）へ遷移する。シナリオからの戦闘出撃中は保留する。終了シーンの初期化完了は`DemoEndSceneInitializer`が`ISceneInitializationReadiness`へ通知する
- `**InGame/Sequence**・**OutGame/Scenario**・**InGame/Battle**`
  - *依存箇所*: `SequenceModuleContainer`、`SelectedScenarioState`、`SelectedBattleStageState`
  - *詳細*: リザルト表示中・シナリオ再生中かの判定（タイマーの位置）と、全体タイマーの開始地点（冒頭シナリオ・チュートリアル戦闘）の判定に使う
- `**Persistent/Addressables基盤**`
  - *依存箇所*: `KillChord.Runtime.InfraStructure.Addressables`の拡張メソッド、`UnityEngine.AddressableAssets.Addressables`
  - *詳細*: 自身のプレハブ（アドレス`"DemoRuntime"`）と`DemoExperienceConfig`（アドレス`nameof(DemoExperienceConfig)`）をAddressables経由でロードする

#### 📤 依存されているもの
- `**InGame/Result**`
  - *参照箇所*: `StageResultInitializationModule.Ready()`（Order 400）が`ServiceLocator.TryGetInstance<IStageResultExitPolicy>`で任意解決し、`StageResultController`のコンストラクタへ渡す
  - *詳細*: 体験版ビルドで`DemoRuntimeBootstrap`が`IStageResultExitPolicy`を登録済みの場合のみ、Resultモジュール側の遷移先解決に体験版固有の分岐が加わる。未登録（非体験版ビルド）の場合は`null`のまま扱われ、通常の遷移ロジックにフォールバックする

## 詳細

### 🧅レイヤー情報
`KillChord.Demo`は独立アセンブリであり、既存の6層（Domain / Application / Adaptor / View / Infrastructure / Composition）へ厳密には分割されていない。実態に近い区分として以下の役割で構成される。

#### ① Domain
当モジュールでは使用していない。

#### ② Application
当モジュールでは使用していない。

#### ③ Adaptor
当モジュールでは使用していない。`DemoStageResultExitPolicy`はResultモジュール所有の`IStageResultExitPolicy`（Adaptor層の抽象）を実装するが、実装クラス自体はDemoモジュール内では層分けせず配置されている。

#### ④ View
`DemoTimerView`がホームタイマー・全体タイマーの残り時間表示を担う。Canvasの表示切り替え（`_session.IsStarted`でオンオフ）も含む。開始前・タイトル・DemoEndではCanvasごと非表示にする。
- 文言は `全体  MM:SS` / `ホーム  MM:SS` で、コードに日本語で直接書いている（英語設定でも日本語で出る）。秒は切り上げて表示する
- ホームの行は、OutGame内でホームタイマーが有効なときだけ表示する
- パネルは幅 240。ホームの行があれば高さ 116、無ければ 66。改造画面でホームの行があるときだけ、2つを横に並べて 480 × 66 にする
- 位置は左下が基準で、左端は 24（改造画面だけ 320）。下端は表示中の画面で変わる。優先順位はリザルト → シナリオ → OutGameの画面 → 戦闘

- 当初の体験版方針はプレイ時間5分を目安としていた（[[体験版仕様]]の「当初の体験版方針」）
- 全体タイマーは、開始地点に着いた時点で動き始める。シナリオ＝冒頭シナリオのロード完了時、チュートリアル＝チュートリアル戦闘のロード完了時、ホーム＝ホームタイマーと同時。開始地点より後から再開した場合は、再開した地点で動き始める
- ホームタイマーは、`Tutorial.Phase`が`HomeStarted`以上で、ホームチュートリアルの開始通知を受けた後に有効になる。OutGameにいる間（`StageSelectModuleContainer`が登録されている間）だけ進み、**OutGameに入るたびに0に戻る**
- どちらのタイマーも`Time.unscaledDeltaTime`で進む（ポーズ中も進む）
- タイトルシーンがロードされている間はタイマーを止めて隠し、タイトルに入った時点でセッションをリセットする

期限切れのときは、常駐の`EventNotificationView`で通知を出してから後続の処理へ進む。通知は3秒表示して0.5秒でフェードし、非スケール時間で進む。ゲーム時間は止めず、入力と後続の遷移を通知が終わるまで待たせる。タイトルに戻ったり破棄されたりしたら通知を取り消す。

| 通知 | キー | 日本語 | 英語 |
|---|---|---|---|
| 全体の期限切れ | `ui.notification.demo_expired` | お時間になりました。体験版を終了します。 | Time is up. The demo will now end. |
| ホームの期限切れ | `ui.notification.home_expired` | ホームタイマーが終了しました。ミッションに移動します。 | The home timer has expired. Moving to the mission. |

- タイトルからの手動のセーブデータリセットで出る通知（`ui.notification.save_reset`）は、DemoEndでの自動削除では出さない

体験版の終了は次の2つの経路で起こる。
- 全体の期限切れ: 通知の後、どこにいてもすぐDemoEndへ移る。戦闘中なら戦闘シーンとInGameをアンロードしてから移る。**リザルトを待たない**。ロード中・シナリオからの戦闘出撃中・通知の表示中は保留する。ホームの期限切れと重なったら全体を優先し、ホーム側の後続（強制出撃）は取り消す
- 最終ステージのクリア: リザルトの「完了」「リトライ」で、`DemoStageResultExitPolicy`が遷移先をDemoEndに差し替える

DemoEndに入ると`SaveData`全体を削除する。`SaveData`にはスキル解放・編成・ステージ進行・チュートリアル進行のほか、音量・所持リソース・環境設定（言語・明るさ・振動など）も含まれるため、**設定も体験者ごとに初期値へ戻る**（タイトルからの手動リセットは音量を保持する）。タイトルへ戻ると初期スキル（skill_00 / skill_13）を補完し、戦闘ごとに装備を読み直す。

### 設計方針
`Assets/Docs/チュートリアル基盤・体験版システム実装計画書.md`（2026-09-08）で決め、実装に採用された方針である。
- チュートリアルと体験版を同じ機能にしない。チュートリアルは製品本体の機能として`Runtime`に実装し、体験版の時間制限と強制出撃だけを体験版専用アセンブリに置く。リリース版から体験版の機能を外しても、初回チュートリアルは残る
- 体験版は専用アセンブリ（`KillChord.Demo`、`defineConstraints: KILLCHORD_DEMO`）で分離する。シンボルは体験版のBuild Profileだけに設定する。`Runtime`から`KillChord.Demo`への参照は禁止する。リリース版では体験版のアセンブリ自体が作られず、シーンにMissing Scriptも残らない
- Release / Demo のステージデータは Addressables の Group で排他的に切り替え、同じ論理アドレスを使う。Planner Master Data Window は別の種別のデータへフォールバックしない（詳細は [[SourceDataProvider]] を参照）

▶ 背景（計画書から変わった方針）
- 計画書 2.1・4.6 は「両タイマーを初回ホーム到達時に同時に開始し、シーン遷移ではリセットしない」としていた。実装では、全体タイマーの開始地点を選べるようにし（#1706）、ホームタイマーはOutGameに入るたびにリセットする
- 計画書 4.6・4.7 は「全体の期限では戦闘やリザルトを強制終了せず、次のリザルト操作を終了シーンへ差し替える」「最終ミッションのクリアでは通常リザルトを挟まずに終了する」としていた。実装では、全体の期限で通知の後すぐ終了し、最終ステージのクリアはリザルトの操作で終了する
- 計画書 4.5 は「体験版の初期化 Module を OutGame の初期化に参加させる」としていた。実装では、常駐プレハブ（`DemoRuntimeBootstrap`）が独立して動く
- 計画書の`DemoExperienceConfig`にあった強制出撃先ステージID・最終ステージIDは削除し、ステージツリーから自動で決めるようにした

# ④ DemoEnd 演出シーケンス {color="gray_bg"}

体験版終了シーン（`Assets/Level/Scenes/Demo/DemoEnd.unity`）に入ってから、タイトルへ戻るまでの流れである。背景に`Stage_02`を追加ロードし、インゲームの開始演出と同じDollyカメラでキャラクターを映すムービーを流した後、案内UI（タイトルイラストとホームページのQR）を出す。攻撃入力でタイトルへ戻る。一定時間での自動復帰は無い。
```Mermaid
sequenceDiagram
    autonumber
    participant SceneInit as DemoEndSceneInitializer (Order 0)
    participant SeqInit as DemoEndSequenceInitializer (Order 30)
    participant Loading as LoadingScreenController
    participant Bgm as DemoEndBgmView
    participant Movie as DemoEndMovieView
    participant EndView as DemoEndView
    participant Input as PlayerInputView

    SceneInit ->> SceneInit: 背景シーン Stage_02 を Additive でロード
    SceneInit ->> SceneInit: ISceneInitializationReadiness へ初期化完了を通知
    SeqInit ->> Loading: ロード画面が閉じるまで待つ
    SeqInit ->> Bgm: Play(BGM_Ingame)
    SeqInit ->> Movie: PlayAsync()（Timeline DemoEndMovie、約9.5秒）
    Movie -->> SeqInit: 再生終了
    SeqInit ->> EndView: ShowBlackoutImmediate()
    SeqInit ->> EndView: ShowEndUiAsync(1秒でフェードイン)
    par BGMのフェードアウト
        SeqInit ->> Bgm: 10秒後に3秒でフェードアウト
    and 入力待ち
        SeqInit ->> Input: 1秒後から攻撃入力を受け付ける
        Input -->> SeqInit: 攻撃入力
        SeqInit ->> SeqInit: タイトルへ遷移
    end
```
演出の設定値は `DemoEndSequenceConfig` にある（体験版（TGS 2026）設定）。

| 戻り先のシーン | Title | — | 同上 |
| BGM | BGM_Ingame | — | 同上 |
| 案内UIからBGMフェードアウト開始まで | 10 | 秒 | 同上 |
