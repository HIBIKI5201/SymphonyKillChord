## 判定

- 信頼性: 陳腐化 — 図の流れが現行と違う。
  - 判定は「前提ノードと UnlockCost」ではなく、選んだノードまでの未解放の先祖ノード全部のコスト合計で行い、先祖もまとめて解放する（`SkillTreeService.TryGetTotalCost`、`SkillTreeController.OnSkillNodeSelected` / `OnSkillUnlocked`）（OG-111）
  - 解放の前に確認ダイアログ（`UnlockConfirmDialogView`）を出す。「このウィンドウを表示しない」にチェックすると、画面を閉じるまで確認を省く
  - 保存は `SavedataSkillUnlockRepository` ではなく `SkillTreeService.SaveSkillUnlockData` が `SaveStore` へ直接行い、解放ポイントは `ResourceInventoryData` に入る
  - 解放後に編成枠ボーナスを再計算し、解放演出を再生し、`OutGameUIEvent.OnOwnedSkillChanged` で改造画面へ知らせる
  - 「ポイント不足・前提未達」の分岐は、Controller がポイント不足のときは何もしない形（`OnSkillUnlocked` の先頭で return）。前提未達という判定は無い

## 適用する本文

未解放のノードを選ぶと、そのノードまでの未解放の先祖ノード全部のコスト合計を必要ポイントとして示す。解放ポイントが足りていれば、確認ダイアログの後に経路上のノードをまとめて解放し、セーブデータへ反映する。確認ダイアログで「このウィンドウを表示しない」にチェックすると、画面を閉じるまで確認を省く。
```Mermaid
sequenceDiagram
    autonumber
    actor Player as プレイヤー
    participant View as SkillNodeView
    participant Init as SkillTreeInitializer
    participant Ctrl as SkillTreeController
    participant Service as SkillTreeService
    participant Dialog as UnlockConfirmDialogView
    participant Store as SaveStore

    Player ->> View: ノードを選択
    View ->> Ctrl: OnSkillNodeSelected(nodeId)
    Ctrl ->> Service: TryGetTotalCost（未解放の先祖ノードを経路として集め、コストを合計）
    Ctrl -->> View: 詳細パネルに必要ポイントと解放後のステータスを表示
    Player ->> Init: 解放ボタン
    alt 確認を省く設定になっていない
        Init ->> Dialog: Show(GetUnlockConfirmation())
        Player ->> Dialog: 解放を確定
    end
    Init ->> Ctrl: OnSkillUnlocked()
    alt 解放ポイントが足りている
        Ctrl ->> Ctrl: 経路上のノードを根本から順に解放し、ポイントを減らす
        Ctrl ->> Service: CalculateSkillSlotBonus（編成枠ボーナスの再計算）
        Ctrl -->> View: 解放演出を順に再生し、ノードと接続線の表示を更新
        Ctrl ->> Service: SaveSkillUnlockData（解放済みノード・スキル・解放ポイント）
        Service ->> Store: SaveAsync<SaveData>()
        Ctrl -->> Init: OnOwnedSkillChanged（改造画面の一覧と編成枠を更新）
    else 解放ポイント不足
        Note over Ctrl: 何もしない
    end
```
