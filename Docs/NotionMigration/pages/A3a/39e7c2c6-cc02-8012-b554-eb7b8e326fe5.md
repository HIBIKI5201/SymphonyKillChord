## 概要
> 💡 **モジュール概要**
> アウトゲーム内の画面遷移（Home/StageSelect/SkillTree/SkillBuild/Setting）を、ルールベースの履歴スタック（Replace/Overlay/Reset）で管理するナビゲーション基盤モジュールである。各画面のコンテナ（表示/非表示の器）を本モジュールが所有し、中身の構築は各機能モジュール（StageSelect/SkillTree等）が担当する。Titleシーンの画面（Title/Menu/Credit）も同じ仕組みで遷移する。

|---|---|
| **モジュール名** | Screen |
| **カテゴリ** | OutGame |
| **ステータス** | 実装済み |
| **最終更新日** | 2026-09-22 |

## 詳細

### 🧅レイヤー情報

#### ① Domain
画面ID（`ScreenId`）と、画面ごとの遷移方針（`ScreenTransitionType`/`ScreenTransitionRule`）という、Unity非依存の純粋な定義を保持する。

#### ② Application
表示・戻る・ホームリセットの3つのUseCaseと、履歴スタックを管理する`ScreenTransitionState`を実装する。

#### ③ Adaptor
`ScreenController`が用途別メソッドでUseCase群をラップし、`ScreenPresenter`/`ScreenViewApplicator`が遷移結果を実際のView表示/非表示へ変換する。

#### ④ View
画面基底クラス`ScreenViewBase`と、各画面の薄いコンテナ・戻るボタンを担当する。`OutGameUIEvent`もこの層に属し、OutGameシーン全体のイベントハブとして機能する。

#### ⑤ Infrastructure
`ScreenRuleData`（ScriptableObject）が画面ごとの遷移ルールをデザイナー向けに公開し、`ScreenRuleRepository`が実行時の辞書に変換する。

#### ⑥ Composition
`ScreenInitializer`（Order 100）が5画面の名前付きUI Toolkitコンテナ（`HomeContainer`・`StageSelectContainer`・`SkillTreeContainer`（内部の`PlayerStatus`を含む）・`SkillBuildContainer`・`SettingContainer`）を解決し、全画面のView・Adaptor・Application・Infrastructureスタックを手動DIで一括構築する。体験版の強制出撃中（作戦画面が操作制限中）は、研究画面・改造画面を開く要求を無視する。設定画面からタイトルへ戻る処理も担当する。

### 🔌 拡張ポイント
> 現状、ポリモーフィックな拡張ポイント（`SubclassSelector`等）はない。新しい画面を追加する場合は、`ScreenId`への値追加、`ScreenRuleData`アセットへのルール追加、`ScreenViewRegistry`への登録が必要である（Enum+データ追加、コード側の登録漏れは起動時に検知されにくいため注意）。ルールが登録されていない画面を表示しようとすると`KeyNotFoundException`になる。`ScreenId`の既存値の番号はアセットにシリアライズされているため、値を削除せず予約値として残す。

### 📋 画面ごとの遷移ルール
値の正本は各ルールアセットである。「戻る」は履歴スタックを1つ戻し、履歴が空なら何もしない。
| 画面 | 遷移種別 | 履歴に積む | 正本 |
|---|---|---|---|
| Home | Reset | しない | `Assets/Level/Data/Master/OutGame/Screen/OutGameScreenRuleData.asset` |
| StageSelect（作戦） | Replace | する | 同上 |
| SkillTree（研究） | Replace | する | 同上 |
| SkillBuild（改造） | Replace | する | 同上 |
| Setting（設定） | Overlay | する | 同上 |
| Title | Reset | しない | `Assets/Level/Data/Master/OutGame/Screen/TitleScreenRuleData.asset` |
| Menu | Overlay | する | 同上 |
| Credit | Replace | する | 同上 |

### 👥 クレジット画面の制作メンバー一覧
クレジット画面（`CreditScreenView`）に並ぶ制作メンバーは、コードへ直接書かず、CSVアセットから読み込んでいる。`TitleSceneInitializer`が`MemberCsvRepository`と`MemberListPresenter`を組み立てて`ShowMemberListUseCase`を実行する。
```Mermaid
sequenceDiagram
    autonumber
    participant Init as TitleSceneInitializer
    participant UseCase as ShowMemberListUseCase
    participant Repo as MemberCsvRepository
    participant Parser as MemberCsvParser
    participant Presenter as MemberListPresenter
    participant View as CreditScreenView

    Init ->> Repo: CSVテキストを渡して生成
    Init ->> UseCase: Execute()
    UseCase ->> Repo: 制作メンバー一覧を要求
    Repo ->> Parser: CSVを解析
    Parser -->> Repo: MemberData の一覧
    Repo -->> UseCase: MemberData の一覧
    UseCase ->> Presenter: 一覧を出力
    Presenter ->> View: MemberViewDTO へ変換して反映
```
メンバーを増減させる場合はCSVアセットを編集するだけでよく、コードの変更は要らない。
- 名簿の正本はNotionの「クレジット」ページである。CSVはNotionに合わせる（#1971）。
- CRIWAREのロゴとADX LEの著作表記もクレジット画面に載せる（未実装、#1970）。
- CSVは`Assets/Level/Data/Master/OutGame/Screen/CreditMembers.csv`で、Titleシーンの`TitleSceneInitializer`に割り当てている。
- 列は「名前,役職,所属」の順である。
- `#`で始まる行と空行は無視する。
- カンマを含む値は`""`で囲む。
