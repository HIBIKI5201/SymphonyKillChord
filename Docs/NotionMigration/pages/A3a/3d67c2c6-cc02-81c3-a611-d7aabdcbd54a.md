## 判定

- 信頼性: 一部古い — 生成から登録までの順序（プレハブのロード → `Instantiate` + `DontDestroyOnLoad` → Config のロード → `Configure` → `IDemoSession` 登録 → `DemoTimerView.Initialize` → `IStageResultExitPolicy` 登録 → `sceneLoaded` 購読）は実装どおり（`DemoRuntimeBootstrap.cs:40-150`）。一方で、二重生成の防止と、購読直後に現在のシーンを 1 回処理する手順が無い
- 整合性:
  - 実装との差: `CreateInstance` は、生成中・`IDemoSession` 登録済み・シーンに `DemoRuntimeBootstrap` がある場合は何もしない（`:42-48`、ロード後にも再確認 `:68-72`）。`SubsystemRegistration` で静的状態をリセットする（`:33-38`）
  - 実装との差: `sceneLoaded` を購読した直後に、現在のアクティブシーンで `HandleSceneLoaded` を 1 回呼ぶ（`:142-144`）。タイトルならセッションをリセットし、DemoEnd ならセーブを削除する
  - 実装との差: Config 名は `DemoExperienceConfig`（Addressables アドレスも同名。`:739`）
- 変更点:
  - 冒頭の説明文: 二重生成を防ぐことを追記
  - シーケンス図: 二重生成の確認と、購読直後の `HandleSceneLoaded`（現在のシーン）を追加

## 適用する本文

シーンロード後に自動生成され、設定ロードと各種サービスの登録を行う。すでに生成済み（`IDemoSession`が登録済み、またはシーンに`DemoRuntimeBootstrap`がある）の場合は何もしない。
```Mermaid
sequenceDiagram
    autonumber
    participant Unity as Unityランタイム
    participant Boot as DemoRuntimeBootstrap
    participant Addressables as Addressables
    participant SL as ServiceLocator

    Unity ->> Boot: RuntimeInitializeOnLoadMethod (AfterSceneLoad)
    Boot ->> Boot: 生成中・生成済みなら終了
    Boot ->> Addressables: プレハブ "DemoRuntime" をロード
    Addressables -->> Boot: プレハブ返却
    Boot ->> Boot: 生成済みでないことを再確認
    Boot ->> Boot: Instantiate + DontDestroyOnLoad
    Boot ->> Addressables: DemoExperienceConfig をロード
    Addressables -->> Boot: Config返却
    Boot ->> Boot: DemoSessionState.Configure(config)
    Boot ->> SL: IDemoSession を登録
    Boot ->> Boot: DemoTimerView.Initialize(sessionState)
    Boot ->> SL: IStageResultExitPolicy を登録 (DemoStageResultExitPolicy)
    Boot ->> Boot: SceneManager.sceneLoaded を購読
    Boot ->> Boot: 現在のシーンで HandleSceneLoaded を1回実行（タイトルならセッションをリセット）
```
