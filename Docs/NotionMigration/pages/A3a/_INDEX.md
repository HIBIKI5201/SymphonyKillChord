## 領域全体で見つかった矛盾・重複

1. **戦闘準備画面の残骸（PR #1839 で廃止済み）。** 戦闘準備（+子）、出撃 ①、ステージセレクト ①、スクリーン（`BattlePreparationScreen`）、Demo ②（`BattlePreparationScreen.SetForcedSortieMode`）、システム概要の DB 行の概要が、廃止済みの画面を前提にしていた。全て直した。`ScreenId.BattlePreparation` / `ScreenId.Options` は enum に値だけ残り、`DemoTimerView.cs:61` も戦闘準備の位置（80）を持っている。仕様概要 / 作戦画面（3437c2c6-cc02-8012-a919-ddcccde97581、OG-101）は別担当
2. **初回の導線（第1話 → チュートリアル戦闘）が古いまま。** 旧記述の `TryPrepareTutorialBattleSortie` / `IsTutorialCompleted` による判定はコード上に無い。仕様は接続ごとの遷移モード `StageAdvanceMode` で決まり、第1話 → チュートリアル戦闘（`StageBind_S01.B00`）と stage_01 → 第2話（`StageBind_B01.S02`）が `AutoAdvance`、ほかは `ManualSelection`（Master・Demo とも）。第1話の後はそのままチュートリアル戦闘へ進む（40_ の TU-12・SC-07 のとおり）。タイトルから始めたときは出撃ボタンを経由しないため、`TryStartTutorialSegment` が同じ遷移を行う（実装上の補足）。タイトル ①、ステージセレクト（+②）、Tutorial ②、シナリオシステム（+①）をこの説明にそろえた。ステージセレクト ② と Tutorial ② は同じ流れを扱っていて重複している
3. **セーブの実体。** 実行時のローダーは `SaveDataConfig.asset` が指すフレームワーク側の `JsonUtilitySaveDataLoaderStrategy` で、自前の `PersistentFileSaveDataLoaderStrategy` は未使用（commit c8f1cea47 で切り替わった）。保存は平文で、「セーブデータの暗号化開発」（38e7c2c6-cc02-806b-a89a-e3598c424d4b、担当外）の「AES で暗号化するようにした」と食い違う（OG-014・OG-015）→ 決定（2026-09-22 八幡）No.24: 製品版で暗号化する（未実装と明記。実装修正）。No.25・26: タイトルのリセットでは音量・言語・リズム判定オフセットを、DemoEnd の削除では言語と音量を残す（未実装と明記。実装修正）
4. **規約と運用の食い違い。** コード規定の「AI によるファイル変更はサマリー・コメント・タイポに留める」（CG-002）と、`AGENTS.md` の AI エージェント運用（agent ブランチ 40 件、機能実装・CI 改修を含む）が食い違う（RL-07）。コード規定の中でも、順序 15「プレフィックスが Handle」と命名 CG-035「サフィックスが Handler」が矛盾し、実装には両方ある（284 件 / 142 件）→ 決定（2026-09-22 八幡）No.7: CG-002 を「AI も実装・PR 作成を行う。レビューは人が行う」に直した。No.8: メソッド名は `Handle〇〇`、クラス名は `〇〇Handler`（CG-035）
5. **GitHub 運用規定の命名。** 旧記述「feature/レイヤー/作業名/作業者」は実態（2 階層目は demo / release / research などの段階）とも、`クライアント部門 Unityプロジェクト開発規定`（34a7c2c6-cc02-8007-a640-cc8a457ddd69）の `feature/[段階]/[プロダクト名]/[個人名]` とも合わない。実態に合わせて直した → 決定（2026-09-22 八幡）No.6: `feature/[段階]/[プロダクト名]/[個人名]`（レイヤーなし）。`agent` は個人名の位置に入れ、`agent/…` は旧運用。hotfix は残す。designer / develop 系は【要確認】
6. **設計思想と実装。** 実フォルダ・asmdef にある `0.Utility` 層が無かった。ServiceLocator の取得はリポ版で「`TryGetInstance` が標準」だが、実装は `GetInstance` が多い（61 件 / 18 件）→ 決定（2026-09-22 八幡）No.9: 必須の依存は `GetInstance`、無くてもよい依存は `TryGetInstance`（DP-302・CG-056）。ServiceLocator の登録型も、スキル編成・スキルツリー・ステージセレクトの 3 ページで実装と違っていた
7. **体験版の数値。** 全体 420 秒・ホーム 90 秒（`DemoExperienceConfig.asset`）に対し、仕様概要 / 体験版仕様（3127c2c6-cc02-80f1-8e59-cd14d6751814、担当外）は「5 分目安」。全体の期限切れで戦闘中でもすぐ DemoEnd へ移る挙動は、実装計画書 4.6 / 4.7 と逆。→ 決定（2026-09-22 八幡）: 現状（420 秒・90 秒・即時遷移・設定も削除・QR はホームページ）を体験版（TGS 2026）の仕様とする。→ 決定（2026-09-22 八幡）No.26: DemoEnd の削除では言語と音量を残す（設定も削除、を改めた。未実装と明記）。No.29: QR はホームページへの QR
8. **重複・構造。** セッティングの本文と子 ① に同じ音量フロー図がある（構成変更になるため残した）。Tutorial の本文リンクがリポの相対パスでリンク切れだった（[[セーブ]] へ張り替え）。システム概要の DB に、リファクタリング資料・「〜開発」・旧モックが現行のモジュール文書と区別なく並ぶ（RL-14、アーカイブの方法は【要確認】）
9. **データの不備（担当外への申し送り）。** `SkillNodeData-N7.asset` に `_hasSkillSlotBonus` が無く、編成枠が 3 に増えない可能性がある（OG-110）
10. **改造画面・用語・チュートリアル。** → 決定（2026-09-22 八幡）No.23: 改造画面は取得済みのキルコードだけを表示する（未解放も表示しているのは実装の不具合）。No.22: スキルツリーの先祖一括解放は実装どおり。No.3: 「研究ポイント」→「解放ポイント」（UI 文言は実装修正）。No.27・28: チュートリアル中の一時的な装備差し替えと、作戦・改造・研究のチュートリアルは未実装と明記
