## 判定

- 信頼性: 一部古い — リザルト経由の経路（`StageResultController` → `DemoStageResultExitPolicy.TryGetDestinationScene` → DemoEnd）は、最終ステージをクリアしたときの経路として残っている（`DemoStageResultExitPolicy.cs:122-147`）。一方で、全体の期限切れはリザルトを待たずに `DemoRuntimeBootstrap` が直接 DemoEnd へ移す経路になっており、図に無い（DM-02）。「初期化完了を `ISceneInitializationReadiness` へ通知」は `DemoEndSceneInitializer` へ移った（DM-11）。削除の範囲（設定も消える）が書かれていない（DM-08）
- 整合性:
  - 実装: `Update` で全体の期限切れを検知すると `TryTransitionToEndScene` を呼ぶ（`DemoRuntimeBootstrap.cs:182-186`）。通知（`ui.notification.demo_expired`）の後、戦闘中なら `SceneTransitionUsecase.UnloadThenChangeSceneAsync` で戦闘シーンと InGame をアンロードしてから、それ以外は `ChangeSceneAsync` で DemoEnd へ移る（`:470-541`）。ロード中・シナリオからの戦闘出撃中・通知の表示中は保留する（`:643-648`）。ホームの通知の表示中なら、それを取り消して全体を優先する（`:473-477`）
  - 実装: DemoEnd の `sceneLoaded` でセッションを終わらせ、`SaveStore.DeleteAsync<SaveData>()` を呼ぶ（`:442-452,689-709`）。削除に失敗したら次の機会にやり直す
  - 削除の範囲: `SaveData` はスキル解放・編成・ステージ進行・チュートリアルのほか、音量・所持リソース・環境設定も持つ（`Assets/Scripts/Runtime/1.Domain/Persistent/Savedata/SaveData.cs:25-35`）。手動リセット（`タイトル / ② セーブデータリセットフロー` 3bf7c2c6-cc02-81f0-9a6f-c0324aa6f38d）は音量を保持するが、DemoEnd では保持しない（#1426、#1818）
  - 計画書 4.7（全体の期限では戦闘を中断せず、次のリザルト操作で終了）とは逆の挙動（DM-02、DM-13）
  - 通知: セーブリセットの通知（`ui.notification.save_reset`）は DemoEnd の自動削除では出さない（DM-04）
- 変更点:
  - 冒頭の説明文: 終了の 2 経路（全体の期限切れはすぐ、最終ステージのクリアはリザルト経由）と、削除の範囲を書いた
  - シーケンス図: 全体の期限切れの経路（通知 → 戦闘シーンのアンロード → DemoEnd）を追加。旧: 「Boot ->> Boot: 初期化完了をISceneInitializationReadinessへ通知」 → 新: `DemoEndSceneInitializer` が通知する。リザルト経由の分岐を「最終ステージクリア済み」だけに直した（全体の期限切れの場合もポリシーは true を返すが、通常はその前に直接遷移する）
- 織り込んだ反映項目: DM-02, DM-08, DM-04（自動削除では通知を出さない点）, DM-11（通知の担当）

## 適用する本文

体験版は次の2つの経路で専用終了シーン（DemoEnd）へ移る。終了シーンの到達を検知して、セーブデータを削除する。
- 全体の期限切れ: 通知の後、どこにいてもすぐDemoEndへ移る（リザルトを待たない）。戦闘中なら戦闘シーンとInGameをアンロードしてから移る。ロード中・シナリオからの戦闘出撃中・通知の表示中は保留する
- 最終ステージのクリア: リザルトの「完了」「リトライ」で、`DemoStageResultExitPolicy`が遷移先をDemoEndに差し替える

削除するのは`SaveData`全体である。スキル解放・編成・ステージ進行・チュートリアル進行のほか、音量・所持リソース・環境設定（言語・明るさ・振動など）も初期値に戻る。この自動削除ではセーブリセットの通知は出さない。タイトルへ戻ると初期スキルを補完する。
