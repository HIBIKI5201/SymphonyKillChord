## 適用する本文

## Notion 仕様書の運用（正本とキャッシュ）
> 💡 **このページについて**
仕様書の正本がどこにあり、リポジトリ側の写し（キャッシュ）をどう扱うかをまとめたページである。人もAIも、このルールに従って仕様を読み書きする。

## 正本とキャッシュ
**仕様の正本はNotionである。** リポジトリ上の仕様の文書は、Notionの写し（キャッシュ）として扱う（2026-09-22決定）。
コード規約やQA対応表のように、AIのスキルやツールが読む文書もNotionに置く。リポジトリにはそのキャッシュを置き、ツールはキャッシュを読む。
| 種類 | 置き場 | git |
|---|---|---|
| 正本 | Notion | — |
| 全体の写し | 今は`Docs/NotionSpecifications/`。`Library/NotionSpecifications/`へ移す予定 | 管理しない |
| ツール用のキャッシュ | `Library/NotionCache/`（予定） | 管理しない |
| キャッシュの対応表（page idと置き場の対応） | `SinfoniaOperator/notion-cache-map.json`（予定） | 管理する |
| AIエージェントの記録 | `Docs/agent/` | 管理しない |
| 不具合ログ | GitHubのIssue | — |
`Library/`はUnityが作るフォルダで、もともとgitの対象外である。Unityの不具合対処で`Library/`を消すとキャッシュも消えるが、取り直せばよい。
ツール用のキャッシュは、Notionのページ名ではなくpage idで置き場を決める。Notion側でページ名を変えたり移動したりしても、キャッシュの置き場は変わらない。

## 仕様を直すとき
- 仕様はNotionで直す。キャッシュのファイルを直接編集しない（次の取得で上書きされて消える）
- 仕様を変える実装のPRでは、同じPRの中でNotionの該当ページも直す【要確認: 記述規約W-22の採用をディレクターに】
- ツールから参照されるページを削除・統合するときは、先にキャッシュの対応表に載っていないかを確かめる
- 書き方は仕様書 ライティング規則に従う（記述規約W-08〜W-06を含む）

## キャッシュを取り直すとき
キャッシュは、**各自が手で取り直す**か、**スキルからAIが取り直す**。GitHub Actionsなどで定期的に取り直すことはしない。
Notion APIにはリクエスト数の制限（平均で毎秒3回程度）がある。今のNotionMarkdownExporterは、更新されたページだけ本文を取り直すが、更新を確かめるためのリクエストをページごとに1回ずつ送る。そのため全体の写しを取り直すと、変更が無くても約2,000回のリクエストになり、すぐ制限に掛かる。

### AIが取り直す手順
AIは、作業で仕様を読む前に次を行う。
1. 作業に必要なページを選ぶ。1回の作業で数件〜十数件とし、全ページを対象にしない
2. 選んだページについて、Notion側の最終更新日時だけを取る（本文は取らない）
3. 手元のキャッシュの最終更新日時と比べる
4. 変わったページと、キャッシュが無いページだけ本文を取り直す
5. 取れなかった場合（トークンが無い・ネットワークが無い・制限に掛かった）は、手元のキャッシュで作業を続け、使ったキャッシュの取得日時と、確かめられなかったことを依頼した人に伝える。キャッシュも無ければ作業を止め、トークンの設定を頼む
AIは、読んだページとその取得日時を作業報告に書く。
指定したページだけを確かめる・取り直す機能は、NotionMarkdownExporterに追加する予定である。

### 手で取り直す
`SinfoniaOperator/NotionMarkdownExporter.exe`を実行する。初回は全ページを取るため数十分かかる。取り直しが必要なときだけ実行する。
Notionのトークンは`SinfoniaOperator/sinfonia-operator.secrets.json`に各自で置く。このファイルはgitの対象外であり、トークンを持たないメンバーはキャッシュを作れない。トークンの値をNotionやDiscordに貼らない。

## キャッシュを読めないもの
GitHub上で動くツールは、各自のマシンにあるキャッシュを読めない。
- CodeRabbit
- GitHub Actions
- クラウドで動くAIセッション
これらには、NotionのURLを示すか、読む対象から外す。

## 記録の置き場
- AIエージェントやスキルが書き出す記録（仕様書と実装の差分レポート、QAの証跡など）は`Docs/agent/`に置く。`Docs/`はgitの対象外なので、各自のマシンにだけ残る
- 不具合ログは、リポジトリのGitHub Issueに送る。現象・再現手順・原因・対処・再発防止を本文に書く。起票の仕方はQA・バグ報告のページにある
- 記録は仕様ではない。仕様に関わる結論が出たら、記録に書いたままにせず、Notionの該当ページに書く
