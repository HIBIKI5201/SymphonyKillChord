## 社内ツール
> 💡 **このページについて**
プロジェクト独自に作られたツールの一覧である。何ができるか・誰が使うかだけをここに書き、詳しい使い方は各ツールの解説ページへ委ねる。

## Unityエディタ内のツール
メニューの`Window/KillChord/`と`Tools/`にまとまっている。
| ツール | メニュー | 主な利用者 | 内容 |
|---|---|---|---|
| PlannerMasterDataWindow | `Window/KillChord/PlannerMasterDataWindow` | プランナー | マスターデータをコードを触らずに追加・編集する |
| KillChordDebugger | `Window/KillChord/KillChordDebugger` | 全員 | 実行中の状態を確認するデバッグ用ウィンドウ |
| TicketSystem | `Window/KillChord/TicketSystem` | プログラマー | シーンのチケットシステムの管理 |
| SinfoniaOperator | `Window/KillChord/SinfoniaOperator` | プログラマー | エディタからSinfoniaOperatorを操作する |
| AutoBuilder | `Tools/AutoBuilder` | プログラマー | ローカルでのプレイヤービルド |
| Import CSV | `Tools/Import CSV` | プランナー・シナリオライター | CSVの取り込み |
| DriveImportSync | `Tools/DriveImportSync/Sync Now` | シナリオライター | Google Driveとの同期 |
| Addressables 検証 | `Tools/Addressables/Validate Keys` `Tools/Addressables/Validate Store Build Settings` | プログラマー | Addressablesのキーとビルド設定の検証 |
| Source Data Provider | `Tools/Source Data Provider/Rebuild All DataID Hashes` `Tools/Source Data Provider/Migrate SpawnPositionPair Ids` | プログラマー | DataIDのハッシュ再構築とデータ移行 |
| フォント検証 | `Tools/Build/Validate Fonts` | プログラマー・UI担当 | フォント設定と必須の日本語グリフを検証する。ビルド前にも自動で走り、失敗するとビルドが止まる |
| Localization セットアップ | `KillChord/Localization/チュートリアル用テーブルをセットアップ` `KillChord/Localization/UI共通テキスト用テーブルをセットアップ` | プログラマー | ローカライズ用のテーブルを作る |
| Build Profile 切り替え | メインツールバーの「KillChord/Build Profile」 | プログラマー | アクティブなBuild Profileを切り替える。製品版（Release）か体験版（Demo）かは、アクティブなBuild Profileで決まる |
DriveImportSyncは、Service AccountのJSON鍵で認証し、配置先を`Assets/`配下に限る。設定は`ProjectSettings/KillChord/DriveImportSettings`にある。鍵そのものはリポジトリに含めない。

### PlannerMasterDataWindow
プランナーがマスターデータを編集するための入口である。ステージ・スキル・敵・ミッションといったデータは、このウィンドウか、直接ScriptableObjectを編集することで変更できる。手順はマスターデータ運用ガイドにまとまっている。
[[マスターデータ運用ガイド（プランナー向け）]]
ウィンドウのツールバーの「Variant」は、表示するデータと新しいデータの作成先（製品版か体験版か）を切り替えるだけである。ビルドにどちらのデータが入るかは、Build Profileで決まる。

### Source Data Provider
マスターデータのIDを管理する仕組みである。IDの付け方の規約（`DataID`）は、上記のマスターデータ運用ガイドに記載している。`Rebuild All DataID Hashes`は、IDのハッシュが実際のデータとずれた際にプログラマーが実行するものであり、**プランナーが通常操作で使うものではない**。

### Inspector と Project ウィンドウの拡張
メニューから開くツールのほかに、次の拡張が常に動いている。
- マスターデータのInspectorプレビュー: キャラクターのレーダーグラフ、Waveのマップ、ステージツリーのグラフなどを、対象アセットを選んだときのInspectorに表示する（`Assets/Editor/Scripts/Inspectors/SourceData/`）
- Projectウィンドウのバッジ: Addressablesに登録済みのアセットと、Source Data ProviderのCollectionに登録済みのアセットに印を付ける。両方に登録されているアセットには両方の印が付く。PlannerMasterDataWindowを開いていなくても表示される

### AIデバッグQAツール
QAシートの項目をエディタ上で確かめるための、Editor専用のツールである（`Assets/Editor/AIDebugPlay/`）。実行中のゲームの状態をJSONで取り出す、戦闘のイベントを記録する、決めた時間だけ観測する、拍を指定して攻撃する、ができる。主にAIエージェントがスキル`ai-debug-qa`から使う。
QAシートの項目との対応と、判定上の注意はQAのページにまとめている。
[[QA]]

## SinfoniaOperator
DiscordとNotionの管理を行う、別ソリューションのツール群である。リポジトリの`SinfoniaOperator/`配下にある。
| 実行ファイル | 内容 |
|---|---|
| SinfoniaOperator | DiscordとNotionのタスク・スプリント管理を行う本体。GitHub Actionsで毎日7時（JST）に自動実行される。仕様検索Botとしてサーバー上でも動いており、Discordの`/branches`で削除できるリモートブランチを一覧できる |
| NotionMarkdownExporter | Notionの仕様書全体をMarkdownとしてリポジトリへ書き出す |
| NotionMarkdownWriter | リポジトリ側からNotionのページを更新・作成する |
| DiscordLogExporter | Discordのログを書き出す |
詳細はシステム概要側のページを参照する。
[[SinfoniaOperator]]
> ⚠️ **NotionMarkdownExporterは初回に全ページを取得する**
初回は1,800ページ以上を取得する重い処理である。2回目以降は更新されたページだけ本文を取り直すが、更新の有無を確かめるためのリクエストは全ページ分かかる。仕様書の内容が古いと感じた程度で全体を回さず、必要なページだけを取り直す。取り直し方はNotion 仕様書の運用のページにまとめている。

## 書き出された仕様書の扱い
`Docs/NotionSpecifications/`配下にあるMarkdownは、NotionMarkdownExporterが自動生成した**読み取り専用のコピー**である。ここを編集してもNotionには反映されない。Notionを直したい場合は、Notion上で編集するか、NotionMarkdownWriterを使う。
仕様の正本はNotionであり、リポジトリ側の文書はNotionの写し（キャッシュ）である（2026-09-22決定）。書き出し先は、git管理外の`Library/NotionSpecifications/`へ移す予定である。
[[Notion 仕様書の運用（正本とキャッシュ）]]

## AIエージェント向けの設定とスキル
リポジトリには、AIエージェント（Claude Code・Codexなど）が読む設定とスキルが入っている。AIに作業を頼むときは、これらが使われる。
| 置き場 | 読むもの | 内容 |
|---|---|---|
| `AGENTS.md` | すべてのAIエージェント | コード規約・設計思想の参照先、仕様書の参照先、AIのブランチとPRの運用 |
| `.claude/skills/` | Claude Code | コード規約チェック、Codexへの実装委譲、仕様書と実装の差分調査、Notion仕様書への書き込み、マスターデータ作業、ローカルビルド、Unity操作（uloop）、AIデバッグQAなど |
| `.codex/skills/` | Codex | コードレビュー、Unity操作（uloop）、AIデバッグQA |
| `.agents/skills/` | Codexなど | Unity操作（uloop）、AIデバッグQAの共有スクリプト |
AIのブランチ名とPRの出し方は、クライアント部門 Unityプロジェクト開発規定の「GitHub運用規定」にまとめている。
