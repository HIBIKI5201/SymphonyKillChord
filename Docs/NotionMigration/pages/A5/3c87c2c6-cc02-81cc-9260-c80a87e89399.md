## Unityセットアップ
> 💡 **このページについて**
役職を問わず、プロジェクトのUnity環境を用意するための手順をまとめたページである。役職ごとに追加で必要な作業は、後半のトグルにまとめている。

## 前提
作業を始める前に、次のアカウントが揃っている必要がある。揃っていない場合はリードへ連絡する。
| 用途 | 必要なもの |
|---|---|
| リポジトリ | GitHubアカウント（本プロジェクトのリポジトリへ招待済みであること） |
| 仕様書 | Notionアカウント |
| 連絡 | Discordアカウント（自分の役職チャンネルへ参加済みであること） |
| 配布物 | Google Driveへのアクセス |

## 手順1 UnityHubとエディタ
Unityのバージョンは以下を使用する。プロジェクトの`ProjectSettings/ProjectVersion.txt`と一致している必要がある。
```
6000.3.10f1
```
インストール時に、以下のモジュールを追加する。
```
Android Build Support
```
Android Build Supportは、Androidビルドを自分で行わない役職でも入れておく。プロジェクトのビルドターゲットがAndroidであるため、モジュールが無いとプロジェクトを開いた際に警告が出る。

## 手順2 リポジトリの取得
SourceTreeを使ってリポジトリをクローンする。SourceTree自体の使い方は次のページを参照する。
[[デザイナー向け SourceTreeを用いた作業説明]]
クローン先のパスに日本語や空白を含めないこと。Unityのビルドや一部のツールがパスの解決に失敗する原因になる。

## 手順3 初回起動
クローンしたフォルダをUnityHubから開く。初回はアセットのインポートに時間がかかるため、完了するまで待つ。
初回起動で注意することは次のとおりである。
- `Library`フォルダはリポジトリに含まれていない。初回起動時に生成されるため、この時間はかかるものである
- インポート中にUnityを強制終了しないこと。中断すると`Library`が壊れ、削除して再生成が必要になる
- コンパイルエラーが出た場合、手順4が済んでいない可能性が高い。R3やZLinqなどのNuGetパッケージも、手順4で入れるフォルダ（`Assets/AssetStoreTools/`）に置かれるためである

## 手順4 AssetStoreToolsの導入
AssetStoreToolsはライセンスの都合でリポジトリに含めていない（`.gitignore`で除外している）。そのため、クローンしただけでは不足しており、各自で導入する必要がある。
1. Google Driveのプログラマーフォルダにあるunitypackageをダウンロードする
2. ファイル名は`Export_AssetStoreToolsPackage_[日時]`の形式である。**日時が最も新しいものを選ぶ**
3. Unityへドラッグしてインポートする
> ⚠️ **リポジトリに含まれないため、更新は自動で入らない**
他のメンバーがAssetStoreToolsの中身を更新した場合、Pullでは反映されない。新しいunitypackageが共有されたら、各自で入れ直す。

`Assets/AssetStoreTools/`には次のものが入っている。
| 種類 | 例 | 入る理由 |
|---|---|---|
| 外部アセット | Asset Storeなどから入れた素材 | ライセンスの都合でリポジトリに含められない |
| NuGetパッケージ | R3、ZLinq、Google.Apis、System.Runtime.CompilerServices.Unsafe など（一覧は`Assets/Settings/Nuget/packages.config`） | `Assets/NuGet.config`の`repositoryPath`が`AssetStoreTools`になっている |
| 内製素材 | 14号のテクスチャ（`_drive/3D/キャラクター/Soldier14`）、制作中のUI（`WIP/`） | 【要確認: リポジトリへ移すかをディレクターに】 |
`Assets/SymphonyKillChord/`も`.gitignore`で除外されている。【要確認: 用途をリードプログラマーに】

## 手順5 動作確認
次がすべて満たされていればセットアップは完了である。
- Consoleにコンパイルエラーが出ていない
- タイトルシーンを開いて再生モードに入れる
- メニューの`Window/KillChord/`に各ツールが並んでいる
エラーが残る場合は、Consoleの最初のエラーメッセージを添えてDiscordの自分の役職チャンネルで相談する。

## 役職ごとの追加手順

### プログラマー
外部パッケージを勝手に追加しないこと。導入の申請フローが決まっている。
[[パッケージ導入手順]]
作業を始める前に、コード規定・GitHub運用規定・設計思想の3つに目を通す。いずれもシステム概要ページの直下にある。

### キャラモデラー・背景モデラー
- 触るシーン: `Level/Scenes/Develop/Designer/`に自分の作業フォルダを作り、その中へシーンを置く
- モデルのインポート先: `Arts/Models/`に新しいフォルダを作ってインポートする（fbx、texture、material等）
- それ以外のアセット: `Level/Scenes/Develop/Designer/`の作業中フォルダへインポートする
現在の`Arts/Models/`は次のフォルダに分かれている。
| フォルダ | 中身 |
|---|---|
| `Arts/Models/Symphony/` | Symphonyのモデル |
| `Arts/Models/Soldier14/` | 14号のモデル |
| `Arts/Models/Weapons/` | 武器のモデル |
| `Arts/Models/Backgrounds/` | 背景のモデル（小物は`Props/`） |
Google DriveからダウンロードしたZIPを展開したフォルダ（名前に日時が付いたもの）を、そのままUnityへ持ち込まない。【要確認: 規則として定めるかをディレクターに】

### エフェクトデザイナー・モーションデザイナー
作業フォルダの扱いはモデラーと同じく`Level/Scenes/Develop/Designer/`配下である。納品の形式と提出先は、各職種の納品ページを参照する。

### プランナー
マスターデータの編集には専用ウィンドウを使う。メニューから次を開く。
```
Window/KillChord/PlannerMasterDataWindow
```
開いたら、最初にツールバーの「Variant」で製品版（Release）と体験版（Demo）のどちらを表示しているかを確かめる。
データの追加・変更の手順は、システム概要側のマスターデータ運用ガイドにまとまっている。
[[マスターデータ運用ガイド（プランナー向け）]]
