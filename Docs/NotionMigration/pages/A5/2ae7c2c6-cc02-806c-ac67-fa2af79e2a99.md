## 記述規約（ツールが読む前提の書き方）
仕様書はAIのスキルやツールにも読まれる。Notionから書き出したキャッシュを機械が読んでも意味が崩れないよう、上記の原則に加えて次の規約を守る。
ツールが固定の置き場で読むページ（コード規定・設計思想・QAシートなど）には必須とする。その他の仕様ページも、この規約に沿って書く。【要確認: 採用と適用範囲をディレクターに】
規約はIDで参照する。IDは変えない。
ただし、読む人の認知負荷を増やさないことを、以下の規約より優先する（2026-09-22決定）。
- 既存ページの節構成・見出し名・順番・絵文字・表の列構成・口調をそのまま使い、情報は既存の節の中に足す
- 同じ種類のページは、同じ種類の既存ページのテンプレートに揃える
- W-12・W-10・W-18・W-20は、既存の書き方を崩す場合は使わない。ツールが参照するページと、数値が多い箇所に限って使う
- 言い回しを整えるだけの書き換えはしない

### ページの構成
| ID | 規約 | 理由 |
|---|---|---|
| W-08 | 1ページに1つの主題だけを書く。ツールが読むページには、別の主題を子ページとして混ぜない | キャッシュは1ページ単位で取るため |
| W-12 | ページの冒頭に「このページについて」の短い節を置き、何の正本か・対象読者（人・AI・ツール名）・最終確認日と確認した実装のコミットまたはバージョンを書く | 読んだ側が鮮度と適用範囲を判断できるようにするため |
| W-10 | 規則・仕様の本文と、背景・経緯・議論を分ける。背景は末尾の「背景」トグルに入れる | ツールが判定に使うのは本文だけである。経緯が本文に混ざると、過去の案を現行ルールと誤読する |
| W-11 | 体験版だけの値やTGS限定の設定には「体験版（TGS 2026）設定」と明記し、通常の値と並べる | 体験版の値と製品版の値を区別できるようにするため |

### 使うブロック
| ID | 規約 | 理由 |
|---|---|---|
| W-14 | 使ってよいブロックは、見出し・段落・箇条書き・番号付きリスト・表（シンプルテーブル）・コード・引用・コールアウトとする。トグルはW-16の用途に限って使う | Markdownに変換しても意味が崩れないため |
| W-15 | 同期ブロック・リンクドデータベースビュー・画像だけの説明・カラム・埋め込みに本文を入れない | 変換で内容が落ちる、または参照先の内容が取れないため |
| W-16 | 規則そのものをトグルの中に隠さない。トグルは背景・補足・参考画像に使う | 人が読むときに見落とすため。変換結果の構造も崩れやすい |
| W-17 | 重要な情報をメンション（@ページ・@人）だけで表さない。ページ名や役割名を文字で書く | 変換後にメンションがIDだけになることがあるため |

### 識別子と数値
| ID | 規約 | 理由 |
|---|---|---|
| W-18 | ツールや他の文書から参照される規則・項目には、変えないIDを振る（例: コード規約`CG-012`、QA`CBT:4-3`、仕様条項`BT-JUST-01`）。参照は見出し名ではなくIDで行う | 見出し名は書き換えられるため |
| W-19 | IDを持つ項目は、表の1列目か見出しの先頭にIDを置く | ツールがIDを機械的に拾えるようにするため |
| W-20 | 数値パラメータは表で書く。列は「名前 / 値 / 単位 / 正本のアセットまたはコード」とする | 値の置き場が分かれば、実装と突き合わせられるため |
| W-21 | 正本がマスターデータ（ScriptableObject）にある値は、Notionには「現在値」として書き、正本のアセットパスを添える | 値の正本が2か所に分かれるのを防ぐため |

### 運用
| ID | 規約 | 理由 |
|---|---|---|
| W-13 | APIキー・トークン・パスワード・スプレッドシートIDなどの秘密情報を書かない。置き場所（例`sinfonia-operator.secrets.json`）だけを書く | 公開ページに載るうえ、キャッシュに入ると各自のマシンにも複製されるため |
| W-23 | ページを削除・統合するときは、キャッシュの対応表（`SinfoniaOperator/notion-cache-map.json`）に載っていないかを先に確かめる | page idで結び付けているため、ページを消すとキャッシュの取得が失敗する |
| W-22 | 仕様を変える実装PRでは、同じPRの中でNotionの該当ページも更新する。PRテンプレートに「Notionの更新先（URL）」の欄を足す | 実装が先に進んで仕様書が遅れるのを防ぐため |
| W-24 | キャッシュファイルを直接編集しない。直したいときはNotionを直し、キャッシュを取り直す | 次の取得で上書きされて消えるため |
| W-25 | ツールがリポジトリへ書き出した記録（`Docs/agent/`）に仕様の結論を残したままにしない。結論はNotionの該当ページに書く | 記録は正本ではないため |
正本とキャッシュの扱いは、ワークフローのNotion 仕様書の運用のページにまとめている。
