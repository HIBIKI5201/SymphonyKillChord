### ステージの種類
- バトルパート
- シナリオパート
の二種類存在する。

#### ステージの進行方法
作戦画面では、
ツリー/ノード形式で、そのステージをクリアすると隣のノードが解放されていく。
作戦画面のノードは
- バトルパート
- シナリオパート
は同じツリー内に存在している。
ステージの解放順は左から右にノードが解放されていく
ステージの解放は
解放されているノード内の最も右にあるステージをクリアすることで次のステージが解放される。
（解放されているノードと解放予定のノードはパートが異なることがある）
- ノードは、ステージのつながりの順に、左から右の列へ自動で並べる
- 次のステージへの進み方はステージのつながりごとに決める
  - 手動選択：クリアした後、ホーム画面に戻り、プレイヤーが作戦画面で次のステージを選ぶ
  - 自動遷移：クリアした後、ホーム画面を挟まずに次のステージを始める
  - リザルトの後の行き先も、この進み方で決まる（[[リザルト]]）

### ノードの表示と操作
- ノードの状態
  - 未解放：選べない
  - 未クリア：黒の太い円
  - クリア済み：緑の円
  - 選択中：円を隠して牙の形の枠を表示する（マウス・コントローラー共通）
- 画面を開いたときに選ぶノード
  - 解放済みのうち、最も先の列にあるノード
  - すべてクリアしているときは、最後にクリアしたノード
- 画面を開いたときに新しくクリアしたステージがあれば、次のノードが解放される演出を再生する
- 選んでいるノードの上に、サブミッションの達成状況を星で表示する
- 詳細
  - ノードを選ぶと、画面の右から詳細がスライドインする
  - 詳細を開いている間は、閉じるまでフォーカスが詳細の外に出ない
  - 詳細の外をクリックすると選択を解除する
- 作戦画面から設定画面を開くボタンがある

### 却下・保留した案

- 戦闘中のミニマップ: 却下（フォーラム「ミニマップ」0253）。代わりにステージ選択の画面でマップを出す案は、実装されておらず採否の記録もない。
- ステージ選択後の戦闘準備画面（キルコード編成の確認）: 2026-06-02 に採ったが、2026-09-16 に廃止し、2026-09-18 にコードを削除した。決定 No.35 で追認した。廃止の理由は記録なし。編成の確認は詳細パネルの「編成」欄と「編成」ボタンで行う。
- バトルとシナリオのノードの表示方法（同じノード / 別画面 / 同じ画面で別ノード / 詳細からシナリオへ飛ぶ）: フォーラム「作戦画面のレイアウトについて」の結論欄が空で、採否の記録がない。現行は同じツリーに置く形である。 Discord では、2026-04-21 にリードプランナーがパターン 1（1 つのツリーに並べる図）を想定すると答えたが、2026-04-25 にディレクターが差し戻しており、結論は出ていない。
- 「ミッションセレクト」という用語: 採らない。「ステージセレクト」にした（フォーラム 0295）。
- 報酬の各欄にどのリソースを出すか（データを新形式へ移すか、表示を全リソース対応にするか）: 両方を行うことにした。データを新形式へ移し、全リソースを表示する（決定（八幡）R44、#1987）。
- 体験版の解放ポイントの総量とスキルツリーのコストの釣り合い: 企画で調整することにした（決定（八幡）R45、#2063）。
- 製品版のツリーでシナリオを初期解放にするか: 未決のため保留。2026-04-21 の想定では「バトルをクリアした後にシナリオを必ず見る」（シナリオはバトルのクリアで解放）としていた（Discord 進捗共有「アウトゲーム」）。
