## 仕様概要
「クリアしたかどうか」というメインミッションと、
その「質（スコア）」を評価するサブミッションを完全に独立した項目として定義する。
これにより、一つのステージに対して多様な評価軸を持たせることが可能になる。
これらのミッションはステージ開始時にプレイヤーに与えるもの。

## 詳細説明

#### ミッションの発令タイミング
- ステージ開始時

### メインミッション

#### **成功条件**
- 敵をn体討伐せよ
- n秒間生存せよ
- ボスを討伐せよ
など上記のうち一つをメインミッションとしてプレイヤーに課す。
現状の実装では、次の種類の条件を使える。
- 経過時間（n秒間生存せよ）
- 敵の撃破数（敵の種類のキーごと）
- 殲滅（最後のウェーブまでの全ての敵を撃破）
- 行動の回数（回避・攻撃・キルコード・移動・ロックオン・拍子ごとの攻撃・敵の攻撃）
- 条件の組み合わせ（And / Or）
- 目標を順に達成するシーケンス（チュートリアルで使用）
- シナリオ再生の完了
ボス討伐の専用条件は無い。ボス用の敵キーを使った撃破数条件で作る。

#### 条件達成時
- ステージクリア

#### 失敗条件
- n秒以内にステージをクリアせよ
- 死亡する
現状のミッションデータで使っている失敗条件は「死亡する」だけである。時間制限は設定できるが使っていない。

#### 条件達成時
- ステージ失敗

#### 撃破数の数え方
- 撃破数の条件は、敵の HP が 0 になった瞬間に数える。そのため、死亡演出の途中でクリアが成立することがある。
- 次のウェーブの出現と殲滅の条件は、最後の敵の死亡演出が終わってから判定する。
この 2 つは同じタイミングで行う（未実装。現状は上のとおりずれている）。【要確認: HP が 0 になった瞬間と死亡演出の後のどちらに揃えるかを企画に】

### サブミッション

#### **条件**
- nダメージ以内の被弾でクリアしろ
- n種類以上の銃を使いクリアしろ
- n分以内にメイン条件を達成する
- n回分コンボを達成する
などの上記のうち重複有りで三つをサブミッションとしてプレイヤーに課す。
現状の実装にある条件は、クリア時間・被ダメージ・コンボ数・武器の種類数の 4 種である。
サブミッションは各ステージ 3 個とする。現状のミッションデータでは、次のステージが 2 個である。【要確認: 2 個のステージを 3 個にするかを企画に（仮データのため、製品版のデータを作るときに解消する可能性がある）】

| ステージ | ミッション | サブミッションの数 |
| --- | --- | --- |
| ステージ 01・03・04 | AllKill | 3 |
| ステージ 02 | Durability | 3 |
| ステージ 05〜09 | Test（仮データ） | 2（30 秒以下・60 秒以下のクリア） |
| ボス | Test（仮データ） | 2（同上） |
| チュートリアル | Tutorial | 0 |

#### 判定と表示
- 判定はメインミッションの終了時に確定する。
- プレイ中に失敗が確定した条件（被ダメージが上限を超えた、など）は、その時点で失敗の表示になる。
- HUD では各サブミッションを「失敗 / 挑戦中 / 成功」の 3 状態で表示する。

#### 条件達成時
- 達成するごとにリザルトでのランクが１上昇する
**リザルト例）**
- メイン条件のみ達成＝Cランク
- メイン条件＋ランク条件１つ＝Bランク
- メイン条件＋ランク条件２つ＝Aランク
- メイン条件＋ランク条件３つ＝Sランク

### ミッションの多様性
これらのステージの成功条件および失敗条件を「ミッション」と呼ぶ。
ミッションはステージごとに設定される。
各ステージのミッションの割り当ては [[ステージルール]] の「ステージ別の構成」に記載する。
現状、敵の種類のキーは全ての敵で共通の「赤い兵士」1 種だけである。そのため、敵の種類別の撃破数条件は作れない。【要確認: 敵の種類別の条件が必要かを企画に】

## 仕様意図

複雑なルールや複数の条件を詰め込むのではなく、基本条件（クリア）とスコア条件（ランク）に構造を分けることで、プレイヤーが直感的にルールを理解しやすくするようにするため。
プレイヤーに単なるクリア体験のみでなく、それ以外にも達成感を感じられる要素を入れるため。
サブミッションを複数にした理由はプレイヤーが初めてプレイした際に、必ずどれか一つのランク条件は達成できるようにさせるため。プレイヤーに成功体験を提供するため。
「n 秒以内に敵を全滅させる」のような条件は「n 秒以内」と「敵を全滅せよ」に分けて設定できるようにし、メイン条件とサブミッションを自由に付け替えられるようにする（付け替えるのはレベルデザインのときのプランナーで、プレイヤーではない。サブミッションはステージごとに固定する）。ゲーム性の広がりを重視するためである（フォーラム「ゲームルールの成功条件の複数化」）。
クリア条件は戦闘に関するものにする。音楽に合わせて戦闘するゲームであるコンセプトに基づくためである（フォーラム「ゲームルール」）。
