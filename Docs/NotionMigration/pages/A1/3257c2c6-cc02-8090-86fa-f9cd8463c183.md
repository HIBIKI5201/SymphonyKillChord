## 仕様概要
インゲームで表示されるUIについて。
現行（体験版 TGS 2026 時点）のHUDは次の要素で構成される。
- HPの数値（現在/最大）とHPバー
- コンボ数
- メインミッションと評価項目（サブミッション）
- キルコードのリストとキルコードの入力の進捗
- クロスヘアとリズムガイド
- ロックオン中の敵の体力（レティクル＋体力バー）と、ロックオン候補の表示
- 画面外の敵の方向マーカー
- コントローラーの操作案内
- 体験版タイマー（体験版のみ）

各要素の詳細は[[戦闘UI]]と[[リズムUI]]に記載する。
（HUDの実体は `Assets/Level/Prefabs/Master/InGame/InGameCanvas.prefab`）

#### 表示タイミング
ゲームの状態ごとのHUDの表示は次の通りである。

| 状態 | HUDの表示 |
| --- | --- |
| ロード中 | 表示しない（ロード画面） |
| ステージ開始演出 | 表示しない（演出の開始でHUDのCanvasを非表示にする） |
| 戦闘中 | 表示する |
| クリア・ゲームオーバー演出 | 【要確認: 演出中のHUD表示を実機で確認】 |
| リザルト | 表示しない（HUDのCanvas群を無効化する） |
| ポーズ中 | 表示したまま、ポーズウィンドウを重ねる |

#### ポーズ画面
- ポーズの操作
  - キーボードはEsc、ゲームパッドはStart（Menu）で開く
  - もう一度同じボタンを押すか、UIのキャンセル操作で閉じてゲームに戻る
- ポーズできないタイミング
  - ステージ開始演出の再生中
  - 戦闘終了からリザルト表示までの間
- ポーズ中の挙動
  - ゲーム内の時間を止める（弾幕も停止する）
  - BGMを一時停止する
  - 入力はポーズ画面の操作だけを受け付ける
- ボタン
  - リスタート（開いたときの初期選択）：ステージを最初からやり直す
  - タイトルへ戻る
- 未実装の要素
  - HUD上のポーズボタン、オプション、ミッションの同時表示、再開時のカウントダウンは仕様に残すが、未実装である

## 仕様意図

インゲーム中に必要なUIだけを置く。
視覚情報が多すぎるとリズムなどのゲームプレイに集中がそがれてしまうため、構成要素は最小限にする。

### 却下・保留した案

- ロックオン時だけ敵の身体の中央に小さな HUD を出し、リズム UI を Symphony の横にコンパクトに置く案: 却下。理由の記録なし。提案の理由は「現状の HUD が大きく、敵に被ると見づらい」「リズム UI を目で追いやすくしたい」（フォーラム「ロックオンHUDについて」3527c2c6-cc02-8056-ab65-c8353f7590f0）。
- UI のトンマナを黒・白・暗い灰色・赤の 4 色にし、彩度を減らす案: 却下。理由の記録なし。提案の理由は「音楽に乗って戦うことが最も重要なので、視覚的な負担を減らしたい」（フォーラム「UIトンマナ修正」3787c2c6-cc02-80df-9ff2-f6503823b367）。
- ジャストの表示色、ダメージ表記（クリティカルの背景、ジャスト時の文字色）の更新: フォーラム「UI周りの更新」3cc7c2c6-cc02-80b5-a56c-ceeffdc3a6e3 では検討中のままだったが、Just は数字の色を変え、クリティカルは数字の背景に専用の絵を出すことに決めた（決定（八幡）R34）。キルコード専用の表示（「スキル」種別）は仕様から外した。
- ポーズ画面の HUD 上のポーズボタン・オプション・ミッション表示・再開時カウントダウン: 未実装のまま仕様に残す（議事録「インゲームUI会議」3497c2c6-cc02-80ca-a3ce-c9c6efa93af8、決定（八幡）No.34）。
- 敵が近くにいないときに判定バー（リズムUI）を半透明にする: 採らない。半透明にしない実装を追認した（決定（八幡）R3、[[リズムUI]] 参照）。
- 入力履歴 UI（3 小節分を画面上部に表示）: 会議で話し合われたが、採否の記録なし（議事録「インゲームUI会議」）。
