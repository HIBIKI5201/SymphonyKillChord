# 仕様概要 {color="gray_bg"}
プレイヤーが敵キャラクターに対してダメージを受けずに連続で攻撃を与えた際に1コンボとなる。

# 詳細説明 {color="gray_bg"}
プレイヤーは敵に攻撃を与える＝１コンボとして定義
しかし敵からのダメージを受けるとコンボが途切れてしまう。
例として
  敵に攻撃を与える＝1コンボ
  ↓
  再び攻撃を与える＝２コンボ
  ↓
敵からの攻撃を受ける＝**コンボが途切れて０になる**
  ↓
  敵に攻撃を与える＝１コンボ
といった流れとなる。

### コンボが増える条件
- 攻撃1回が敵に命中すると1増える。
- 多段攻撃（8拍子の3ヒットなど）も、攻撃1回として1だけ増える。

### コンボが0に戻る条件
- 攻撃が空振りしたとき（対象がいない、範囲内に敵がいない）
- [[リズム判定]] のリズムタイムアウト（前回の入力から2小節）になったとき
- プレイヤーがダメージを受けてHPが減ったとき
  - バリアで全部吸収してHPが減らなかったときは0に戻らない。
  - 現状の実装では、スキル5で自分のHPを消費したときもHPの減少として扱い、0に戻る。【要確認: スキル5のHP消費を被ダメージとして扱う（0に戻す）か、キルコード発動として扱う（0に戻さない）かを企画に】

### コンボが0に戻らない場面
- キルコードの発動では0に戻らない。
  - 現状の実装では、通常攻撃のダメージを出さないキルコード（スキル1・3・5・7・13）が発動した攻撃は、キルコードが当たってもコンボが0に戻る。これは実装の不具合である。

### コンボの値を参照する場面
- 1プレイのリザルト画面（最大コンボの表示）
- プレイヤーの現在のコンボ数表示
- コンボに応じたランク評価
  - 現状: コンボを条件にする評価の仕組みはあるが、ステージのミッションでは使っていない。【要確認: 実装するかを企画に】
- キルコードの発動
  - 現状: キルコードの発動条件は拍子の並びだけで、コンボ数は使わない。【要確認: この項目を残すかを企画に】

### コンボの表示
- 3コンボ以上で表示し、0〜2コンボでは表示しない（閾値の正本は `Assets/Level/Scenes/Master/InGame.unity` の `_comboVisibleCount`）。
  - 現状の実装は4コンボ以上で表示している。
- 表示位置は画面の右端から内側に寄せた位置である（[[戦闘UI]] 参照）。

# 仕様意図 {color="gray_bg"}

インゲームのランク付けの際に、コンボ数などに応じた条件も追加するため。
また、ランクのほかにも、プレイヤーの実力や能力を実際に目でわかりやすく表示するための一機能として実装する。
コンボ数がメインのゲームではないため、コンボ数の表記に差分などは付けない（フォーラム「インゲームUIの構成要素」）。

## 却下・保留した案

- コンボ数に応じてキルコードの攻撃力・クリティカル率・スペシャル技のチャージを上げ、攻撃 SE を音階で変える案: 却下。理由の記録なし（フォーラム「コンボによる能力の追加」3257c2c6-cc02-8033-8370-d664177c0a91）。
- 最大コンボに応じた報酬、コンボ数に比例して攻撃力と被ダメージを上げる案、コンボが増えるほど音色を変える案: 候補として挙げたまま保留。採否の記録なし（フォーラム「コンボについて」3227c2c6-cc02-8025-9deb-c7c73e491c62）。音色の案は「コンボによる能力の追加」でも再び出て、却下された。
- コンボに応じたランク評価: 仕様意図にあるが、ミッションのデータでは使われていない。実装するかは【要確認: 企画に】。
- コンボ表示を 4 コンボ以上とする実装: 3 コンボ以上とした（決定（八幡）No.20）。
