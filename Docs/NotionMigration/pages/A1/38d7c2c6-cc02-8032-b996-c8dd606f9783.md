# **詳細説明** {color="gray_bg"}

## **成立条件**
[[リズム判定]] における通常の拍子判定に加えて、
そのタイミングが理論値にどれだけ近かったかを追加で評価する。
理論値は「直前の入力の時刻＋判定した拍子の理論上の間隔」である。曲の拍の格子は基準にしない。

### 判定方式は小節比方式（BPM連動）である。
- 判定幅は小節長に対する割合で決まり、BPMに比例して変わる（判定幅＝小節長×0.03125）。
- 直前の入力からの経過時間を1小節の長さで割った値（小節比）が、拍子ごとのJust範囲に入っていればJust判定成立とする。
- 範囲は開始を含み、終了を含まない。秒数はBPMに比例して変わる。
- 範囲の正本は `Assets/Level/Data/Master/InGame/Music/RhythmJudgmentDefinitionAsset.asset` の `JustStartNormalized` / `JustEndNormalized` である。

| 拍子 | 理論上の間隔（BPM84、秒） | Just範囲（小節比） | Just範囲（BPM84、秒） | 理論値からのズレ |
| --- | --- | --- | --- | --- |
| 8拍子 | 0.357 | 0.121875〜0.153125 | 0.348〜0.438 | -8.9ms〜+80.4ms |
| 6拍子 | 0.476 | 0.146875〜0.178125 | 0.420〜0.509 | -56.5ms〜+32.7ms |
| 4拍子 | 0.714 | 0.246875〜0.278125 | 0.705〜0.795 | -8.9ms〜+80.4ms |
| 3拍子 | 0.952 | 0.321875〜0.353125 | 0.920〜1.009 | -32.7ms〜+56.5ms |
| 2拍子 | 1.429 | 0.496875〜0.528125 | 1.420〜1.509 | -8.9ms〜+80.4ms |
| 1拍子 | 2.857 | 0.996875〜1.028125 | 2.848〜2.938 | -8.9ms〜+80.4ms |

- 範囲の幅はどの拍子も0.03125小節（BPM84で約89ms）である。この幅はTGS対応（2026-09-16）で1.25倍に緩和した値であり、Master データのため製品版と体験版で共通である。
- 早入力と遅入力は対称ではなく、遅れ側に偏っている。8・4・2・1拍子はほぼ遅れ側だけに幅がある。
- 6拍子だけは早い側に寄っている。3拍子は前後の両側に幅があるが、遅れ側のほうが広い。【要確認: 6拍子だけが早い側に寄っていることが意図どおりかを企画に】
- 8拍子の範囲の終わり（0.153125）と6拍子の範囲の始まり（0.146875）は重なっており、重なった区間では8拍子のJustになる。
- 前回の入力がない場合（最初の入力、曲頭オフセットより前）はJustにならない。
- 1小節を過ぎた入力は、通常の拍子判定では1拍子に丸めるが、Just判定には丸める前の経過を使う（1拍子のJustが1小節を過ぎても続かないようにするため）。

## **ダメージへの反映**
[[ダメージ計算]] の計算式に「Justダメージ倍率」として組み込まれる。計算式と計算の順序は [[ダメージ計算]] を正とする。
- Just判定成立時の倍率は**200%**とする（＝基礎ダメージ2倍）。
- Justダメージ倍率は武器（拍子ごとの攻撃定義）ごとに設定する。設定場所は `Assets/Level/Data/Master/InGame/Battle/PlayerAttack_Beat*.asset` の `_justDamageMultiplier` である。
- クリティカル判定とJust判定は独立した別軸の判定であり、
両方成立した場合は式の通り両方の倍率が乗算される。
- キルコード発動時のダメージにも同じ式がそのまま適用される。
（詳細は次項「キルコード（スキル）発動条件・ノーツ種別への影響」参照）

## **キルコード（スキル）発動条件・ノーツ種別への影響**
Just判定は、リズム判定で記録されるノーツの種類やキルコードの発動条件
（コマンドパターン判定）そのものには**影響しない**。
- リズム判定で記録される「ノーツ」の種類（1〜8拍子に対応するノーツ）は、
Just成立の有無にかかわらず通常通り記録される。
- キルコードのコマンド判定ロジック（どの順番でどの拍子・アクションが入力されたか）
自体は、Just成立の有無に左右されない。
一方で、
**キルコードの発動条件を満たした最後の入力がJust判定に成功していた場合、
そのキルコードのダメージにもJustダメージ倍率（200%）が乗算される。**
- キルコードは全てのジャンル（攻撃／バフ／デバフ）で敵にダメージを与える処理を
持つため、このJustボーナスはジャンルを問わず全てのキルコードに適用される。
- キルコードが発動するたびに最後の入力のJust成否がそのまま判定対象になる。
- ダメージへの反映は通常攻撃時と同じ計算式（[[ダメージ計算]] ）に、
キルコードの基礎ダメージ量を当てはめる形で行う。
  - キルコードは最後の入力の拍子の攻撃定義のJustダメージ倍率を使う。

## **演出（フィードバック）**
- **クリティカル成立** → **SE**で表現する（クリティカル専用の効果音を再生）。
- **Just成立** → **エフェクト**で表現する。現状の実装は以下の組み合わせである。
  - **リズムUIの演出**
    - [[リズムUI]] のゲージ上のビートを0.2秒フラッシュさせ、伸ばしてから戻す（伸び64を0.12秒、戻り0.45秒）。
  - **画面演出**
    - 画面全体に拍子の色のVignetteを出す（強さ1.0、0.4秒）。Justでない攻撃では強さ0.3、0.2秒である。
  - **ゲームパッドの振動**
    - Justの攻撃（キルコードを含む）のときだけゲームパッドを短く振動させる（低周波0.35、高周波0.6、0.12秒）。振動の強さは設定画面で変えられる（[[設定画面]] 参照）。ゲームパッドが無いときは振動しない。
  - 演出値の正本は `Assets/Level/Data/Master/InGame/Music/ACLikeRhythmGuideEffectConfig.asset` と `Assets/Level/Data/Master/InGame/Haptics/GamepadHapticsConfig.asset` である。
  - **スローモーション**
    - プレイヤーと敵のアニメーションだけにスローモーションをかける。未実装である。
  - **ヒットマーカー**
    - 着弾時のヒットマーカーの色を変える。未実装である。
- 両方成立時は、クリティカルのSEとJustのエフェクトが同時に再生されることで
「両方成立した」ことがプレイヤーに伝わる。
専用の複合演出アセットを別途用意する必要はない。
- 色を指定するチュートリアルの課題中は、指定した色の拍子でJustしたときだけ「Perfect」と表示し、振動する（[[チュートリアル]] 参照）。

- ▶ 背景
  - 判定を1か所に統一したとき（2026-09-12、PR #1513）に決めた実装上の要件（統一と緩和の経緯は「仕様意図」の「経緯」に記載する）
    - Just範囲はマスターデータ（`RhythmJudgmentDefinitionAsset`）に集約する
    - 範囲は開始を含み、終了を含まない
    - Just範囲と通常の拍子範囲が重なる場合はJust範囲の拍子を優先し、リズムUIの表示と攻撃の拍子を一致させる
    - 判定を読んでも状態は変わらない。入力の履歴を更新する前に1回だけ判定し、その結果を攻撃・キルコード・多段ヒット・演出に渡す
    - 履歴が無いとき・曲頭オフセット前はJustにしない。1小節を過ぎてもJustが続かないようにする
  - 回帰確認の観点: 6拍子それぞれの範囲の始まりと終わり、繰り返しの読み取り、最初の入力、1小節の超過、巻き戻し、空振り、キルコードの発動、多段ヒット、リズムUIの更新順とレイアウト変更

# **仕様意図** {color="gray_bg"}

リズムゲームとしての精度を追求したいプレイヤーに対して、
大まかなリズムに乗るだけでもプレイ可能な間口の広さを保ちつつ、
より正確なタイミングを取れる上級者には明確な追加リターン（ダメージ倍率）を
与えることで、コアメカニクスをやり込む動機付けを行う。
※このゲームは初心者でもクリアできる設計方針（[[レベルデザイン方針]] 参照）だが、
　Just判定はその上に積む上級者向けの精度報酬として位置づける。
各数値・仕様判断の意図は以下の通り。
- **判定ウィンドウを小節の長さに対する割合で決める**
  判定幅は小節長に対する割合で決まり、BPMに比例して変わる（詳細は「成立条件」）。
  プレイテストの結果次第で調整の余地は残す。
  2026-09-22 に、固定値方式（±0.1 秒）から実装どおりの小節比方式に改めた（決定 No.10）。固定値方式にした当初の意図は「却下・保留した案」に残した。
- **Justダメージ倍率を200%にした意図**
  シビアな判定をプレイヤーに視認できる目標で与え、
そのシビアさにあった報酬を強化することでプレイヤーの攻撃の操作に対し
簡潔かつ強力な達成感やくやしさを押し付けることができると考えたため。
- **演出のチャンネルを分けた意図**
  クリティカル判定とJust判定は独立した別軸の判定であり、同一攻撃で両方が成立するケースもある。
  専用の合体演出を別途用意するコストをかけずに両方の成立をプレイヤーへ伝えるため、判定の種類ごとにフィードバックのチャンネル（SE／エフェクト）を分けて割り当て、それぞれが同時に再生されることで自然に重畳表現させる。
