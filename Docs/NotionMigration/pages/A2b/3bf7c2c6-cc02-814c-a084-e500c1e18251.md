## 判定

- 信頼性: 一部古い — 既定の経路は実装と一致する。ただし、敗北 Tips の出どころ（`MissionDefinition.DefeatTips`、空なら既定文）と、敗北時にも戦闘時間・最大コンボを表示すること、ポリシーが遷移先を返した場合の分岐が無い。確認は 73fefeb45
- 整合性: 実装との矛盾: Note の「選択状態はクリアしない」は既定経路だけの話で、ポリシーが遷移先を返した場合（体験版の終了条件など）はクリアする（`StageResultController.RetryAsync`）。同じ `RetryAsync` はポーズ画面の「リスタート」からも呼ばれる（シークエンス ④ 3c67c2c6-cc02-81f3-b9fa-c1775a59771d）
- 変更点:
  - 図: `PresentDefeat` の説明を 旧: 「DefeatTipsからランダムに1件選択」「ランク・サブミッションは空」 → 新: Tips の出どころと既定文、時間・コンボは表示することを追記
  - 図: ポリシー分岐（`opt`）を追加し、Note を既定経路の説明に限定
  - 図の後: ポーズ画面からも同じ `RetryAsync` を使う旨の 1 文を追加
- 織り込んだ反映項目: HD-22（システム概要側）
- 出典: `Runtime/3.Adaptor/InGame/Result/StageResultPresenter.cs`（PresentDefeat / SelectDefeatTip）、`StageResultController.cs`（RetryAsync）、`Runtime/6.Composition/InGame/UI/PauseWindowInitializer.cs:190-194`
- 要確認: なし

## 適用する本文

```Mermaid
sequenceDiagram
    autonumber
    participant Seq as InGameSequenceDirector (Sequenceモジュール)
    participant Presenter as StageResultPresenter
    participant View as StageResultView
    actor Player as プレイヤー
    participant Controller as StageResultController
    participant Policy as IStageResultExitPolicy (任意)
    participant SceneUC as SceneTransitionUsecase

    Seq ->> Presenter: PresentDefeat()
    Presenter ->> Presenter: MissionDefinition.DefeatTipsからランダムに1件選択（空なら既定文）
    Presenter ->> View: Apply(StageResultDTO)（ランク・サブミッションは空、戦闘時間・最大コンボは表示）
    Seq ->> View: Show()
    Player ->> View: リトライボタン押下
    View ->> Controller: RetryAsync()
    alt ポリシーが遷移先を返した
        Controller ->> Policy: TryGetDestinationScene(Retry)
        Controller ->> SceneUC: UnloadThenChangeSceneAsync(battleScene, inGameScene, 遷移先)
        Controller ->> Controller: 成功時にSelectedBattleStageState / SelectedMissionStateをクリア
    else 既定
        Controller ->> SceneUC: UnloadThenReloadSceneAsync(battleScene, inGameScene)
        Note over Controller: SelectedBattleStageState/SelectedMissionStateはクリアしない（同じステージを再挑戦）
    end
```

同じ`RetryAsync`は、戦闘中のポーズ画面の「リスタート」からも呼ばれる（シークエンスの「④ 戦闘ポーズフロー」を参照）。
