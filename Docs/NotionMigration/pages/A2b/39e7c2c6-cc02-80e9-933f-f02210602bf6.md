## 概要

> 💡 **モジュール概要**
> ロックオン対象（ターゲット）の登録・選択・現在位置取得を一元管理するモジュールである。旧Cameraモジュールに内包されていたロックオン機能がリファクタリングにより独立し、Camera・Player・Enemy・UI・Skillなど複数モジュールから利用されるハブ的な存在になっている。

|---|---|
| **モジュール名** | Target |
| **カテゴリ** | InGame |
| **ステータス** | 実装済み |
| **最終更新日** | 2026-09-22 |

#### 📥 依存しているもの

- `**Character&Battle**`
  - *依存箇所*: `CharacterEntity`、`AttackDefinition`
  - *詳細*: `TargetEntityRegistry`がターゲットIDと`CharacterEntity`を対応付け、`TargetAreaHit`が範囲判定の結果として`CharacterEntity`を返す。`TargetAreaQuery`は扇形の半角を`AttackDefinition`の上下限（0〜180度）でクランプする
- `**EventBus イベント（0.Utility/Persistent）**`
  - *依存箇所*: `EOnLockOnAcquired`
  - *詳細*: `TargetingSystem`が、現在と異なる敵へ新たにロックオンが成立したときに発火する

#### 📤 依存されているもの

- `**Camera**`
  - *参照箇所*: `ITargetSystemViewModel`（`TargetSystemModuleContainer`経由）
  - *詳細*: ロックオン入力・攻撃入力での対象選択（`ChangeTarget`）、左右切替（`TrySwitchTarget`）、非ロックオン時の候補更新（`UpdateCandidate`）、攻撃が命中した敵への付け替え（`TrySetCurrentTarget`、ロックオンSEは鳴らさない）、現在ターゲット位置の取得に使用する。`TargetSystemController`は経由しないため、カメラ操作によるロックオンでは`OnTargetLocked`は発火しない
- `**Player**`
  - *参照箇所*: `PlayerInitializer`、`PlayerView`
  - *詳細*: `PlayerInitializer`がContainerを取得して`PlayerAttackController`（Battle）を生成する。`PlayerView`は`EOnLockOnAcquired`を購読してロックオンSEを鳴らす
- `**Battle**`
  - *参照箇所*: `PlayerAttackController`（`TargetSystemController`, `TargetAreaQuery`）
  - *詳細*: 攻撃対象を解決する。ロックオン対象が無ければ候補を対象へ昇格させる（このとき`OnTargetLocked`が発火する）。当たり判定として、ロックオン対象の方向へ扇形範囲の対象を取得する。射程外にも減衰付きで命中させるため、探索距離は射程ではなく上限1000mを使う
- `**Enemy**`
  - *参照箇所*: `EnemyLifeCycle`、`BossLifeCycle`（`TargetSystemController`, `TransformTargetable`）
  - *詳細*: 敵1体ごとに`TransformTargetable`を生成し、`TargetSystemController.RegisterTarget`で`TargetingSystem`と`TargetEntityRegistry`の両方へ登録する。死亡・プールへの返却時に登録を解除する。Containerの取得は`EnemyInitializer`が行う
- `**UI**`
  - *参照箇所*: `HUDEnemyHealthPresenter`（`TargetSystemController`）、`EnemyDirectionIndicatorPresenter`（`ITargetSystemViewModel`, `ITargetBoundsViewModel`）
  - *詳細*: `HUDEnemyHealthPresenter`がロックオン中の敵の体力と、候補の敵の位置を表示のために参照する。`EnemyDirectionIndicatorPresenter`が画面外の敵を指し示すため、対象のBoundsを参照する
- `**Reticle**`
  - *参照箇所*: `ReticleHudPresenter`（`ITargetSystemViewModel`）
  - *詳細*: 登録済みターゲットから、ロックオン中と候補を除いた生存敵を取り出してレティクルを表示する
- `**Skill**`
  - *参照箇所*: `SkillTargetResolver`（`ITargetSystemViewModel`, `TargetEntityRegistry`, `TargetAreaQuery`）、`SkillEffectContextFactory`、`SkillCrosshairProgressController`、`Skill_08` / `Skill_09` / `InfectionOnHitEffect`（距離クエリ）
  - *詳細*: スキル発動時のターゲット解決と、範囲スキルの対象列挙に使用する。スキルエフェクトの出現位置に現在ターゲットを使い、スキル照準UIはロックオン中かどうかで表示を切り替える。`Skill_09`は`IPlayerTargetRangeQuery`で射程内判定を、`Skill_08`と`InfectionOnHitEffect`は`ITargetRadiusQuery`で周囲の敵の列挙を行う
- `**Buff**`
  - *参照箇所*: `CriticalDamageFieldBuff`（`IPlayerTargetRangeQuery`）
  - *詳細*: 対象がプレイヤーの周囲の範囲内にいるかを判定する
- `**Mission**`
  - *参照箇所*: `MissionProgressRecorderController`（`TargetSystemController.OnTargetLocked`）
  - *詳細*: ロックオン成立を「ロックオン」行動としてミッションへ通知する
- `**Music / リズムガイド**`
  - *参照箇所*: `RhythmGuidePresenter`、`ACLikeRhythmGuideInitializer`（`TargetSystemController`）
  - *詳細*: ロックオン中かどうかでリズムガイドの表示を切り替える

## 詳細

### 🧅レイヤー情報

#### ① Domain

当モジュールでは使用していない。

#### ② Application

`IPlayerTargetRangeQuery`と`ITargetRadiusQuery`の2つのインターフェースだけを置く。スキル効果やバフ（Application層）が、Adaptor層のターゲットシステムへ直接依存せずに距離判定を行うための抽象である。

#### ③ Adaptor

`TargetSystemController`がターゲット選択ViewModelとEntityレジストリを仲介し、他モジュールからの主要な窓口になる。`TargetEntityRegistry`がターゲットIDと`CharacterEntity`の対応を管理する。`TargetAreaQuery`は登録済みターゲットへの扇形範囲検索を提供し、攻撃判定と範囲スキルの対象列挙に使われる。`PlayerTargetRangeQuery`と`TargetRadiusQuery`は、Application層の距離クエリをXZ平面で実装する。

#### ④ View

`TargetingSystem`がターゲットの登録・選択・位置取得を一元管理し、視界範囲内にいる、最もHPが低い、または距離が近い敵を選ぶ選択アルゴリズムを実装する。【要確認: HP と距離のどちらを優先するかを企画に】同じ選定で次の3つを扱う。

- ロックオン対象の選択（`ChangeTarget`）
- 未ロック時の「候補」＝今攻撃したらロックオンする敵の更新（`UpdateCandidate`、カメラが毎フレーム呼ぶ）
- 左右切替（`TrySwitchTarget`。指定方向を基準に選び直し、現在と別の敵が選ばれたときだけ切り替える）【要確認: 左右切替の選び方は仕様に定義が無い。方向基準のままとするかを企画に】

現在と異なる敵へ新たにロックオンが成立したときは`EOnLockOnAcquired`を発火する。ID指定の付け替え（`TrySetCurrentTarget`）では、引数で発火を止められる。`TransformTargetable`が実際のUnity `Transform`をラップして対象化し、Colliderがあればその`Bounds`を公開する。

#### ⑤ Infrastructure

当モジュールでは使用していない。

#### ⑥ Composition

`TargetSystemInitializationModule`（Order 100、他モジュールより早期に初期化）が`TargetSystemInitializer`経由でターゲットシステムを構築し、`TargetSystemModuleContainer`として公開する。

### 🔌 拡張ポイント

> 現状、ポリモーフィックな拡張ポイント（`SubclassSelector`等）はない。新しい対象種別を追加する場合は`ITargetable`を実装した新しいクラスを作成し、`TargetSystemController.RegisterTarget(targetable, entity)`で登録する（Enumやswitch文への追記は不要）。`TargetingSystem`だけに登録して`TargetEntityRegistry`へ登録しないと、ロックオンはできるが、範囲判定・距離クエリでは`CharacterEntity`を解決できずに対象から外れる。
