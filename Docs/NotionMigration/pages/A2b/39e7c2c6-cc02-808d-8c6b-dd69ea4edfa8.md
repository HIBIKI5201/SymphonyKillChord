## 概要
> 💡 **モジュール概要**
> ステージクリア／ゲームオーバー時のリザルト画面表示と、そこからOutGameへの帰還・InGameの再挑戦（リトライ）を司るモジュールである。Sequenceモジュールから呼び出され、Mission・StageSelectの情報を集約して表示する。リトライの処理はポーズ画面（UIモジュール）からも使われる。

| 項目 | 内容 |
|---|---|
| **モジュール名** | Result |
| **カテゴリ** | InGame |
| **ステータス** | 実装済み |
| **最終更新日** | 2026-09-22 |

---

### 🏗️ クラス

| クラス名 | レイヤー | 役割・機能 |
|---|---|---|
| `**StageResultController**` | Adaptor | `CompleteAsync`（OutGameへ帰還）/`RetryAsync`（InGame再読込）のシーン遷移を実行。任意の`IStageResultExitPolicy`が登録されている場合、遷移先シーン名をポリシー側の判定結果へ差し替える。リトライでポリシーが遷移先を返したときは、再読込ではなくそのシーンへ遷移し、選択状態をクリアする |
| `**IStageResultExitPolicy**` | Adaptor | 製品固有の終了条件に応じて、リザルト遷移先シーンを差し替える拡張ポイントの契約 |
| `**StageResultExitAction**` | Adaptor | リザルト画面から選択された遷移操作を表すenum（`Complete`/`Retry`） |
| `**StageResultPresenter**` | Adaptor | `PresentVictory(MissionEvaluationResult)`/`PresentDefeat()`で`StageResultDTO`を構築しViewModelへ反映。メインミッションの判定文言（`達成`/`失敗`）と既定の敗北Tipsは日本語の定数で持つ。敗北Tipsは`MissionDefinition.DefeatTips`からランダムに1件選び、空なら既定文を使う |

| `**StageResultType**` | Adaptor | `Victory`/`Defeat`を表すenum |
| `**IStageResultViewModel**` | Adaptor | Adaptor→View境界の抽象（`Apply(in StageResultDTO)`） |
| `**StageResultView**` | View | ボタン押下ハンドリング、勝敗UIの出し分け、サブミッション行の生成を行うMonoBehaviour。表示時にインゲームHUDのCanvas群を無効化し、勝利時は文字表示Timelineを再生する。ボタンのフォーカス表現も持つ |

| `**StageResultMissionItemView**`** / **`**StageResultMissionItemViewModel**` | View | サブミッション1行分の表示 |

#### 📥 依存しているもの

- `**Mission**`
  - *依存箇所*: `MissionRuntimeService`（`MissionModuleContainer`経由）, `MissionEvaluationResult`, `StageRankCalculator`
  - *詳細*: `MaxComboText`/`BattleTimeText`は`MissionRuntimeService.MissionProgress`から、ランクは`StageRankCalculator.Calculate(evaluationResult.AchievedCount)`から算出する。敗北Tipsは`MissionDefinition.DefeatTips`から取る
- `**StageSelect**`
  - *依存箇所*: `SelectedBattleStageState`, `SelectedMissionState`
  - *詳細*: ステージ名・遷移先シーン名の取得、および`CompleteAsync`成功時の選択状態クリアに使用する。完了の遷移先は`SelectedBattleStageState.ReturnSceneName`で、出撃時にOutGame側が設定する
- `**Persistent/SceneManagement**`
  - *依存箇所*: `SceneTransitionUsecase`
  - *詳細*: `CompleteAsync`は`UnloadThenChangeSceneAsync`、`RetryAsync`は`UnloadThenReloadSceneAsync`を呼ぶ（ポリシーが遷移先を返したリトライは`UnloadThenChangeSceneAsync`）

#### 📤 依存されているもの

- `**Sequence**`
  - *参照箇所*: `StageResultModuleContainer.Presenter`, `StageResultModuleContainer.Controller`, 自らFindする`StageResultView`
  - *詳細*: `InGameSequenceDirector`がクリア/ゲームオーバー演出の最後に`PresentVictory`/`PresentDefeat`を呼び、`StageResultView.Show()`でリザルト画面へ切り替える。ステージのロードに失敗したときは、`SequenceInitializationModule`が黒画面のまま`CompleteAsync`を呼んでOutGameへ戻す（シナリオバトルの専用出撃ではPersistent側に任せる）
- `**UI（ポーズ画面）**`
  - *参照箇所*: `StageResultModuleContainer.Controller`
  - *詳細*: `PauseWindowInitializer`がポーズ画面の「リスタート」で`RetryAsync`を呼ぶ。遷移に失敗した場合はポーズ状態へ戻す

## 詳細

### 🧅レイヤー情報

#### ① Domain

当モジュールでは使用していない（`MissionEvaluationResult`等はMissionモジュールのDomain型を利用する）。

#### ② Application

当モジュールでは使用していない。

#### ③ Adaptor

`StageResultController`がシーン遷移を、`StageResultPresenter`が評価結果からDTOへの変換を担当する。

#### ④ View

`StageResultView`が勝敗UIの出し分け・ボタン処理・サブミッション行生成を行い、`StageResultViewModel`がリアクティブなデータバインドを担う。表示演出は`ResultTextSlideIn`とその設定クラス群へ切り出され、Inspectorから有効・無効と時間を調整できる。

`Show()`では、インゲームHUDのCanvas群（`_inGameCanvas`）のGameObjectを無効化し、カーソルを表示する。

勝利時の文字表示は、Timeline `StageResultReveal.playable`（固定長3秒）の`_revealProgress`カーブで上から順に出す。文字表示が終わってから数値のカウントアップを始める。クリア演出全体の流れ（黒帯・正面カメラ）は、シークエンスの「② クリア→保存→リザルト表示フロー」を参照する。

| 名前 | 値 | 単位 | 正本 |
|---|---|---|---|
| 文字表示Timelineの長さ | 3 | 秒 | `Assets/Arts/Animation/Timelines/StageResultReveal.playable` |
| スライドインの距離 | 600 | px | `InGame.unity`の`StageResultView`（`ResultTextSlideInSetting`） |
| スライドインの時間 | 0.35 | 秒 | 同上 |
| スライドインの間隔 | 0.06 | 秒 | 同上 |
| スライドインのフェード | あり | — | 同上 |
| カウントアップの時間 | 1 | 秒 | `InGame.unity`の`StageResultView`（`ResultCountUpSetting`）、イージング OutCubic |

ボタン操作は次のとおりである。

- ナビゲーションはExplicitで、完了から左でリトライ、リトライから右で完了へ移る
- 表示時の初期選択は完了ボタン
- 選択中のボタンは文字をシアンにし、1.1倍に拡大する
- 決定キーのアイコン表示は一度追加されたが、現在は生成していない

見出しの文言は英語固定のSerializeField（勝利`Mission Complete`／敗北`Mission Failed`）で、Localizationを参照していない。メインミッションの判定文言（`達成`/`失敗`）と既定の敗北Tipsは、Presenterの日本語定数である。【要確認: 英語固定のままにするか、ローカライズ対象にするかを企画に】

#### ⑤ Infrastructure

当モジュールでは使用していない。

#### ⑥ Composition

`StageResultInitializationModule`（Order 400）がPresenter/Controllerを構築し、`StageResultModuleContainer`として公開する。`Ready`では`ServiceLocator.TryGetInstance<IStageResultExitPolicy>`で拡張ポリシーの有無を確認し、見つかった場合のみ`StageResultController`のコンストラクタへ渡す（見つからない場合は`null`のまま既定の遷移動作になる）。現在のポリシー実装は、体験版の`DemoStageResultExitPolicy`（最終ステージのクリア後や全体の制限時間切れのとき、リザルトの操作を体験版終了へつなぐ）だけである。詳細は体験版のページを参照する。

### 🔌 拡張ポイント

| 拡張したいこと | 実装する場所 | 追加登録の要否 |
|---|---|---|
| 表示項目を追加したい | `StageResultDTO`へフィールドを追加し、`StageResultPresenter`で値を設定、`StageResultViewModel`と`StageResultView`へ反映先を足す | 不要 |
| 演出の時間や有無を変えたい | `StageResultView`のInspectorにある`ResultTextSlideInSetting` / `ResultCountUpSetting`、勝利時の文字表示は`StageResultReveal.playable` | 不要（コード変更なし） |
| リザルトからの遷移先を製品固有の条件で差し替えたい | `IStageResultExitPolicy`（Adaptor）を実装し、`ServiceLocator`へインスタンスを登録する | 必要（`ServiceLocator.TryGetInstance<IStageResultExitPolicy>`が`StageResultInitializationModule.Ready`実行時点で解決できるよう、それより前に登録を済ませる必要がある。未登録の場合はサイレントに無視され、`CompleteAsync`は`ReturnSceneName`、`RetryAsync`は`UnloadThenReloadSceneAsync`という既定の遷移にフォールバックする。リトライでポリシーが遷移先を返した場合は、そのシーンへ遷移して選択状態をクリアする） |
