## 適用する本文

計測はMission側で行われ、当モジュールはその結果を受けて表示する。コンボ数を変えたのと同じ処理の中で、`MissionProgressRecorderController`が`ComboHudPresenter`を呼ぶ。

```mermaid
sequenceDiagram
    autonumber
    participant Attack as PlayerAttackController
    participant Entity as CharacterEntity (プレイヤー)
    participant Music as MusicSyncService
    participant Recorder as MissionProgressRecorderController (Mission)
    participant Progress as MissionProgress (Mission)
    participant Presenter as ComboHudPresenter
    participant VM as ComboHudViewModel
    participant View as ComboHudView

    alt 攻撃を実行した
        Attack -->> Recorder: OnAttackExecuted(攻撃名, 命中したか)
        alt 命中した
            Recorder ->> Progress: IncrementCombo()
        else 命中しなかった
            Recorder ->> Progress: ResetCombo()
        end
    else HPが減った
        Entity -->> Recorder: OnHealthChanged(変化量 < 0)
        Recorder ->> Progress: RecordDamageTaken() / ResetCombo()
    else リズムタイムアウト
        Music -->> Recorder: OnRhythmTimedOut
        Recorder ->> Progress: ResetCombo()
    end
    Recorder ->> Presenter: Present(現在のコンボ数)
    Presenter ->> VM: Apply(ComboDTO)
    VM -->> View: ComboCount の変化を通知
    alt コンボ数が表示閾値以上
        View ->> View: 数字を更新し、揺れ演出を再生
    else 表示閾値未満
        View ->> View: 表示ルートを非表示にする
    end
    Note over Progress: 最大コンボはリザルトの評価条件にも使われる
```

### コンボ数が変わる契機

| 契機 | コンボ数 | 補足 |
| --- | --- | --- |
| 攻撃が命中した | +1 | 多段攻撃（8拍の3ヒットなど）も攻撃1回につき+1 |
| 攻撃が命中しなかった | 0に戻す | ロックオン対象なし、範囲内に敵がいない場合 |
| 通常攻撃のダメージをスキップするキルコードが発動した | 0に戻す（現状） | 本来の仕様では、キルコード発動ではコンボをリセットしない。現状は攻撃が「命中しなかった」として通知されるため0に戻る（不具合） |
| プレイヤーのHPが減った | 0に戻す | 被ダメージとして記録する。現状はキルコードによるHP消費も含む。【要確認: キルコード（スキル 5）のHP消費を被ダメージとしてリセットするか、キルコード発動としてリセットしないかを企画に確認】 |
| リズムタイムアウト | 0に戻す | 最後の入力から一定小節（`TimeoutBarCount`）入力が無いとき |

コンボ数が3以上のときに画面へ表示する。現状は表示閾値が4で、4未満のコンボ数は画面に出さない（不具合）。
