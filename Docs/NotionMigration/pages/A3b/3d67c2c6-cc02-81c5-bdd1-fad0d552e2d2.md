```Mermaid
sequenceDiagram
    autonumber
    actor Engineer as エンジニア / CI

    participant BuildSettings as GameDataVariantBuildSettings

    Engineer ->> Toolbar: Release_* または Demo_* の Build Profile を選ぶ
    Toolbar ->> BuildSettings: ApplyActiveProfile()
    BuildSettings ->> Profiles: SynchronizeActiveProfileScenes()
    Profiles -->> Profiles: Demo の場合、Profileのシーン一覧をグローバルのシーン一覧＋Demo/DemoEnd.unity に揃える
    BuildSettings ->> Profiles: GetActiveVariant()
    Profiles -->> BuildSettings: Profileのシンボルに KILLCHORD_DEMO があれば Demo、無ければ Release
    BuildSettings ->> BuildSettings: Apply(variant)
    BuildSettings ->> Addr: GameData.Release / GameData.Demo / GameData.Shared をEnsureGroup
    BuildSettings -->> Addr: 選択中Variantのgroupだけ IncludeInBuild=true（Sharedは常にtrue）
    Note over BuildSettings: Editorの起動・再読み込み時にも<br/>アクティブなProfileで同じApply()を行う
    Engineer ->> Processor: Player ビルド開始
    Processor ->> Processor: PrepareForBuild（callbackOrder -1000、Addressablesのビルドより前）
    Processor ->> BuildSettings: Apply(variant) を再実行
    Processor -->> Engineer: 種別とコンパイル済みコードの不一致・Groupの設定不備・必須エントリの欠落があれば BuildFailedException
```
> Planner Master Data Windowのツールバー「Variant」（`EditorPrefs`にユーザー単位で保存）は、Windowに表示するSourceAssetと、新規アセットの生成先（`Assets/Level/Data/Master/`か`Assets/Level/Data/Demo/`か）を切り替えるだけで、ビルド成果物には影響しない。`SourceDataProviderRepositoryResolver`は選択中VariantのGroupからSourceAssetを解決するため、Windowに出るデータはVariantごとに異なる。データそのものをRelease/Demo間で出し分けたい場合は、対象ScriptableObjectの所属Addressables GroupをGameData.Release / GameData.Demo / GameData.Sharedのいずれかへ振り分けることで、ビルド成果物の含有可否を制御する。版ごとに内容が違うものは、同じアドレスでGameData.ReleaseとGameData.Demoの両方に置く。
> 必須エントリは`StageTreeAsset` / `EnemyMissionKeyRepository` / `MissionDefinitionRepository`で、Demoではさらに`DemoRuntime` / `DemoExperienceConfig`である。CIは`-gameDataVariant release|demo`を渡し、AutoBuilderがその種別のBuild Profileを集めてビルドする。体験版（TGS 2026）のビルドはWindowsだけで行う。
