## ID 統一の対象と除外
2026-07 に、マスターデータのIDを手書きの連番・文字列から`DataID`（文字列ID＋焼き込み済みハッシュ）へ統一した。Domain層のIDはintを包む値オブジェクトで、値はハッシュである。
| 対象 | CollectionKey | Domain層のID |
|---|---|---|
| ステージ（`BattleStageAsset` / `ScenarioStageAsset`、Bindの接続元・接続先） | `StageAsset` | `StageId` |
| 敵ミッションキー（`EnemyMissionKeyAsset`） | `EnemyMissionKey` | `EnemyMissionKey` |
| ミッション（`MissionDefinitionAsset`、`BattleStageAsset`からの参照） | `Mission` | `MissionId` |
| スキル（`SkillTemplateAsset`、ノードの解放スキル、初期所持・初期装備） | `Skill` | `SkillId` |
| スキルツリーノード（`SkillNodeData`） | `SkillNode` | `SkillNodeId` |
| シナリオのアニメーション・立ち絵・背景（各カタログの要素） | `ScenarioAnimation` / `ScenarioPortrait` / `ScenarioBackground` | `AnimationId` / `PortraitId` / `BackgroundId` |
| ステージ演出（`StageEffectAssetBase`と`StageEffectView`の対応付け） | `StageEffect` | なし（InfraとViewが同じCollectionKeyを選ぶことでハッシュが一致する） |
その後、敵Wave定義（`Wave`）、個別の敵データ（`EnemyData`）、キャラクター（`Character`）、リソース（`GameResource`）なども同じ仕組みで追加した。全一覧は親ページの「登録済み CollectionKey 一覧」にある。
次のものは意図的に`DataID`にしていない。
| 対象 | 除外理由 |
|---|---|
| `MissionEvaluationId` | 重複チェックにのみ使用され、IDからインスタンスを取得する用途がない |
| `SkillNodeBindData.NodeName` | UI Toolkit要素名としてのキーであり、ゲームデータのIDではない |
| `BossAttackEntryAsset.AttackIndex` | 配列の位置参照であり、authoring IDではない |
| `CharacterAnimationPlaybackMap._oneShotIndices` | View層の再生インデックス管理 |
| `ScreenId` | enumのため対象外 |
セーブデータへの影響は次のとおりである。
- ステージクリア・スキル解放・スキル編成のセーブ値はint型のままで、保存される値の意味が「手書きの連番」から「ハッシュ値」に変わった。スキーマは変えていない。
- 旧セーブデータとの互換は取らない（未リリースのためリセットを許容した）。
- 文字列IDを変更するとハッシュが変わり、既存のセーブデータに保存された値と一致しなくなる。
