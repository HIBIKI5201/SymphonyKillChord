## 結論
装備しているスキルの構成に応じて、戦闘中 BGM のフレーズを **CRI セレクターで小節ごとに切り替える**仕組みを実装した。曲自体は差し替えず、原曲フレーズと各スキル専用フレーズを、音楽的に同期させたまま小節単位で入れ替える。
切り替えの順番（シーケンス）は装備スキル数に応じて構築する。
- **2スキル装備時** — `[原曲, スキル1, 原曲, スキル2]` のループ
- **3スキル装備時** — `[原曲, スキル1, スキル2, スキル3]` のループ
- **それ以外の個数** — `[原曲, スキル1, スキル2, …]` のループ（常に原曲へ戻れる並びにする）
- **スキルが無いとき** — セレクターを操作せず、通常 BGM のまま再生する

1 区切り（シーケンスを 1 つ進める間隔）は既定で 4 小節である。
本実装では、音楽同期の拍（`MusicSyncState.CurrentBeatRx`）を購読し、小節が変わった瞬間だけ区切りを判定して、次に鳴らすセレクターラベルを CRI に予約する。実際の音の切り替えは CRI 側のブロック境界で反映される。

## 注意事項
- CRI への切り替え要求は `MusicPlayer.SetSelectorLabel` にまとめた（研究版の暫定クラス `MusicPlayerExtension` は廃止した）。インゲーム側からは出力ポート `IBgmSelectorPlayer` を通して呼ぶ。
- **ビート同期情報がキューに埋め込まれていないと、CRI のコールバックは一切発火しない**。後述の案A を採用する場合は AtomCraft 側のオーサリングが前提となるため、**サウンド／デザイナーさんと要相談**。
- 小節判定に使う「拍」は `MusicSyncState` が「再生時間 ÷ BPM」から算出した値を参照している。この BPM はオーサリングデータ由来ではなく、**現状は手入力のテスト値**（`MusicSyncView` の `_testBpm`）である。プロジェクト全体の音楽同期がこの「手動 BPM ＋ 時間計算」方式で統一されている。
- セレクター名（`Selector_BGM`）と各ラベル名（`SelectorLabel_S00` 等）は CRI の ACB 定義と完全一致している必要がある。一致していないと切り替わらない。
- 対応表の原曲ラベルが未設定だと、原曲フレーズの位置に空ラベルが送られてしまう。未設定のときは初期化時に警告が出る。
- 対応表に無いスキルは切り替えの並びから除外され、初期化時に警告が出る。このとき、装備数と小節構成が食い違う。
- 対応表・音楽同期・`MusicPlayer` のどれかが欠けていても、ゲームの初期化は止めず、通常 BGM で再生する。
- InGameScene に `EquipmentBgmInitializer` を初期化モジュールとして配置する。

## 機能の概要
装備スキルからセレクターシーケンスを構築し、小節ごとに切り替えるサービスを実装した。主な特徴は以下の通り：
- **スキル構成からのシーケンス構築** — 装備スキルIDを対応表でラベル名に変換し、スキル数に応じたループ配列を生成する
- **小節同期での切り替え** — 拍ストリームを購読して小節の変わり目を検出し、次に鳴らすラベルを CRI に予約する。切り替えは次のブロック頭で音楽的に揃って反映される
- **データ駆動の対応表** — スキルID → セレクターラベル名の対応を `ScriptableObject`（`BgmSelectorLabelTableAsset`）で外部設定でき、コード変更なしに割り当てを変えられる
- **出力ポートによる分離** — セレクター操作は `IBgmSelectorPlayer`（Adaptor）を通して常駐シーンの `MusicPlayer` へ依頼する

## 実装されたコンポーネント説明

### 全体アーキテクチャ
```Plain Text
EquipmentBgmInitializer (初期化モジュール, Order 250)
  └─ Build() : SkillBuildDefinition から装備スキルIDを集める（ID昇順）
               → BgmSelectorLabelTableAsset を SkillBgmSelectorTable に変換
               → BgmSelectorSequence を構築し、EquipmentBgmService / EquipmentBgmController を生成

EquipmentBgmController
  └─ Start() : 初期ラベルを適用し、MusicSyncState.CurrentBeatRx を購読
       拍 → 小節番号（拍 ÷ 4）→ 小節が変わった時だけ EquipmentBgmService.TryResolveLabel()

EquipmentBgmService
  └─ TryResolveLabel(小節番号) : 区切り（既定4小節）が変わったら次のラベルを返す

IBgmSelectorPlayer（実装: MusicPlayer）
  └─ SetSelectorLabel(selector, label) : CRI の SetSelectorLabel を呼び、再生中なら反映する
       │
       ▼
CRI ── セレクター切替 ──▶ 次ブロック頭で反映
```

### EquipmentBgmInitializer
インゲームの初期化モジュール（Order 250）。ServiceLocator から `SkillBuildDefinition`・`MusicPlayer`・`MusicSyncState` を取得し、装備 BGM 切り替えを組み立てる。
- 装備中のスキルIDを集めて昇順に並べ、対応表でラベル列に変換する
- 対応表が無い・依存が欠けているときは警告を出し、通常 BGM のまま初期化を続ける
- インスペクタで対応表（`BgmSelectorLabelTableAsset`）と、1 区切りの小節数（既定 4）を設定する
---

### EquipmentBgmService
シーケンスと 1 区切りの小節数を持つ中核ロジック。自前の毎フレーム更新は持たない。
- `InitialLabel` — 最初に鳴らすラベル（シーケンスの先頭）
- `TryResolveLabel(measureIndex, out label)` — 小節番号を 1 区切りの小節数で割り、区切りが変わったときだけ次のラベルを返す
---

### MusicPlayer / IBgmSelectorPlayer
`IBgmSelectorPlayer` はセレクターラベルの切り替えを依頼する出力ポートで、常駐シーンの `MusicPlayer` が実装する。`MusicPlayer.SetSelectorLabel` は CRI の `SetSelectorLabel` を呼び、再生中であれば再生中のプレイバックへ反映する。未再生のときは設定値が次の再生に引き継がれる。
---

### BgmSelectorLabelTable
スキルID と CRI セレクターラベル名の対応表。Domain の `SkillBgmSelectorTable` と、Inspector で編集する `BgmSelectorLabelTableAsset` に分かれている。原曲ラベルと、スキルIDごとのラベルエントリ一覧を持つ。
コードを変更せず、アセット上でスキルとラベルの割り当てを編集できる。
現在の対応表（`Assets/Level/Data/Master/InGame/Music/BgmSelectorLabelTableAsset.asset`）は次のとおり。
| スキルID | セレクターラベル |
|---|---|
| （原曲） | `SelectorLabel_S00` |
| `skill_01` | `SelectorLabel_S01` |
| `skill_02` | `SelectorLabel_S03` |

上記以外のスキルのラベル割り当ては未定である。【要確認: 残りのスキルのラベル割り当て 企画・サウンド】

## 切り替えタイミングの方式と将来の選択肢
研究版では Update で毎フレーム小節の切り替えを確認する方式を採っていた。本実装（PR #943）では**案B（既存の拍計算を R3 ストリームで購読）を採用**し、`EquipmentBgmController` が `MusicSyncState.CurrentBeatRx` を購読している。新しいループを足さず、既存の 1 本のクロックに相乗りする形である。案A は今も選択肢として残す。

### 案A: CRI のビート同期コールバック
AtomCraft 側でキューにビート同期情報（BPM・拍子・オフセット）を埋め込めば、小節／拍が進むたびに CRI からコールバックを受け取れる。`barCount`（小節数）が直接取れるので、自前の小節計算も `MusicSyncState` 依存も不要になる。
- イベント: `CriAtomExPlayer.OnBeatSyncCallback`
- コールバック情報: `CriAtomExBeatSync.Info`（`barCount` / `beatCount` / `bpm` / `numBeats` / `label` など）
- 購読対象は `MusicPlayer.AtomSource.player`。コールバックはメインスレッドの更新タイミングで呼ばれるため、`SetSelectorLabel` 等をそのまま呼べる
（既存のコード例を残す）
**前提:** ビート同期情報がキューに無いと `OnBeatSyncCallback` も `GetBeatSyncInfo` も一切発火しない。採用には AtomCraft のオーサリング＋ ACB リビルドが必要で、サウンド／デザイナーさんと要相談。

### 案B: 既存の拍計算を R3 ストリーム化して購読（採用）
`MusicSyncState` が毎フレーム計算している拍を `CurrentBeatRx` として公開し、「小節が変わった時だけ」流す。`EquipmentBgmController` は自前の Update を持たず購読するだけで済む。AtomCraft 側の追加作業は不要である。
```C#
_subscription = _musicSyncState.CurrentBeatRx
    .Select(static beat => ToMeasureIndex(beat)) // 拍 ÷ 4 で小節番号へ変換
    .DistinctUntilChanged()                      // 小節が変わった瞬間だけ発火
    .Subscribe(OnMeasureChanged);                // 区切りが変わったらラベルを適用
```

### 方式比較
| 方式 | 追加作業 | 備考 |
|---|---|---|
| Update（研究版） | なし | 実コストほぼゼロ。本実装では使っていない |
| 案A CRI ビート同期 | **サウンド: ACB オーサリング必須** | 最も正確。キューにビート同期情報が必要 |
| 案B R3 ストリーム（採用） | コア層（`MusicSyncState`）改修 | 既存ループ再利用・新規依存なし |
オーサリング対応（サウンド側依頼）が必要な案A には着手していない。
