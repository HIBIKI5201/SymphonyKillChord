## 適用する本文

# 🎮 マスターデータ運用ガイド（プランナー向け） {color="gray_bg"}
> 💡 **このドキュメントについて**
このドキュメントは、プログラマー向けの設計書とは別に、**プランナーがコードを触らずにゲームのマスターデータ（ステージ・スキル・敵・ミッション等）を追加・変更・削除する方法**をまとめたものです。Unityエディタでの操作を前提にしています。
---

## 📋 前提知識

### マスターデータとは
このゲームのステージ構成・敵の強さ・スキル内容・ミッション条件などは、**ScriptableObject**というUnityのデータアセットとして管理されています。ほとんどの調整はC#のコードを一切書かず、Unityエディタ上でこれらのアセットを作成・編集するだけで完結します。
マスターデータの実体は `Assets/Level/Data/Master/` 以下にあります。体験版（TGS 2026）だけで使うデータは `Assets/Level/Data/Demo/` 以下にあります。新しいアセットを作る際は、既存の近いアセットと同じフォルダに保存してください。

### アセットの作り方（共通操作）
1. Unityエディタのプロジェクトウィンドウで、保存したいフォルダを右クリック
2. `Create` メニューから、このドキュメントに記載された **メニューパス**（例: `KillChord/Mission/MissionDefinition`）を選択
3. 生成されたアセットの名前を分かりやすいものに変更する（例: `Mission_Stage05`）
4. インスペクターで各項目を設定する
5. 必要に応じて、後述の「一覧アセットへの登録」を行う

後述の「Planner Master Data」画面の「データを追加」を使うと、決められたフォルダにアセットを作って一覧へ自動登録できます。

### 「プランナーメモ」欄について
多くのアセットには `プランナーメモ` という、ゲームには一切影響しないメモ欄が用意されています。仕様の意図や調整履歴を書き残す用途で自由に使ってください。

### ⚠️ 「要エンジニア」の表記について
このガイドでは、**プランナーだけで完結する作業**と、**エンジニアにコード変更を依頼する必要がある作業**を明確に分けて記載しています。後者には次のマークを付けています。
> 🔧 **要エンジニア**: プログラマーへの依頼が必要な作業です。

### 製品版と体験版のデータ
製品版と体験版（TGS 2026）でデータを出し分けるため、一覧アセットはAddressablesの3つのGroupに分けて登録されています。ビルドには `GameData.Shared` と、ビルドする版のGroupだけが入ります。
| Group | 入れるもの |
|---|---|
| `GameData.Shared` | 製品版と体験版で共通のデータ |
| `GameData.Release` | 製品版だけのデータ（ファイルは `Assets/Level/Data/Master/`） |
| `GameData.Demo` | 体験版だけのデータ（ファイルは `Assets/Level/Data/Demo/`） |
- 版ごとに内容が違うデータは、**同じアドレスで** `GameData.Release` と `GameData.Demo` の両方に置きます（例: `StageTreeAsset`、`MissionDefinitionRepository`、`EnemyMissionKeyRepository`）。
- 同じアドレスを `GameData.Shared` にも残すと、製品版側と重複してビルドが失敗します。
- どちらの版をビルドするかはBuild Profileで決まります。Planner Master Data画面の `Variant` は、画面に表示するデータとアセットの生成先を切り替えるだけで、ビルドには影響しません。
> 🔧 **要エンジニア**: Groupの新設や、データを共通から版ごとへ分け直す作業はエンジニアへ依頼してください。
---

## ① ステージを増やす時
新しいステージ（バトル or シナリオ）をステージマップ（作戦画面）に追加する手順です。

### 手順
1. **ステージを作成する**
  - フォルダ: `Assets/Level/Data/Master/OutGame/StageSelect/Stages/`（体験版は `Assets/Level/Data/Demo/OutGame/StageSelect/Stages/`）
  - メニュー:
    - バトル: `KillChord/Runtime/StageSelect/BattleStageAsset`
    - シナリオ: `KillChord/Runtime/StageSelect/ScenarioStageAsset`
  - 主な設定項目:
| 項目 | 内容 |
|---|---|
| ステージを一意に識別するID | 他のどのステージとも重複しない文字列ID（後述「🔑 IDの付け方」）。**重複するとゲーム起動時にエラーで停止します** |
| ゲーム開始時点でこのノードを解放済みにする | ツリーの起点となるステージのみオンにする |
| 初回起動時に自動出撃するチュートリアルステージの場合はオンにする（Battleのみ） | ツリー全体で**1つのステージのみ**オンにできる（複数設定するとエラー） |
| ステージ名 / ステージのフレーバーテキスト | マップ画面に表示される名称・説明文 |
| 遷移先のシーン名 | 通常は`InGame`のままでよい |
| バトルパートで使用する敵Wave定義ID（Battleのみ） | ②で作成し、`EnemyWaveDefinitionRepository`へ登録したウェーブ定義のIDを候補から選択。**背景のステージシーン（`Stage_01`等）はウェーブ定義側で指定します** |
| バトルパートのミッションID（Battleのみ） | ⑤で作成し、`MissionDefinitionRepository`へ登録したミッションのIDを候補から選択 |
| シナリオパートで再生するシナリオID（Scenarioのみ） | Scenarioモジュール側で定義したシナリオID |
| 初回クリア報酬 | 初回クリア時にだけ付与するリソースと数量の組（複数可） |
| 成功報酬（毎回） | クリアするたびに付与するリソースと数量の組。初回クリア時は初回クリア報酬と合わせて付与する |
| 旧形式の初回クリア報酬（移行用） | 改造ポイント・解放ポイント。上の「初回クリア報酬」が空のときだけ使われる。初回クリア報酬をなしにする場合は0にする |
2. **（Battleの場合）敵ウェーブ定義を用意する** — ②を参照
3. **（Battleの場合）ミッション定義を用意する** — ⑤を参照
4. **ステージ間のBindを作成する**
  - フォルダ: `Assets/Level/Data/Master/OutGame/StageSelect/StageBinds/`
  - メニュー: `KillChord/Runtime/StageSelect/StageBindAsset`
  - 「接続元のステージID」と「接続先のステージID」に、①で作ったステージのIDを候補から選ぶ
  - 「接続元ステージ完了後の進行方法」を選択する
    - `Manual Selection`: クリア後にホームへ戻り、プレイヤーの選択を待つ
    - `Auto Advance`: ホームでの選択を挟まず接続先へ自動遷移する
5. **ステージツリーへ登録する**
  - `Assets/Level/Data/Master/OutGame/StageSelect/` の `StageTreeAsset` を開く（体験版は `Assets/Level/Data/Demo/OutGame/StageSelect/StageTreeAsset`）
  - 「ステージ一覧」に①で作ったステージを追加
  - 「接続一覧」に④で作ったBindを追加

### ⚠️ 注意点
- ステージIDの重複、チュートリアルステージの重複設定は、`StageTreeAsset`をインスペクターで編集した時点でコンソールにエラー表示されます（保存前に必ず確認してください）。
- Bindの接続先になっていないステージが作戦画面の起点です。起点が2つ以上ある場合は警告され、作戦画面の左端に上下で複数配置されます。通常は起点が1つになるようにBindを設定してください。
- Bindに循環がある場合は作戦画面を自動配置できないためエラーになります。
- 同じ接続元から複数の`Auto Advance`を設定すると、`StageTreeAsset`の検証でエラーになります。
- 作戦画面のノードと接続線は`StageTreeAsset`から自動生成されます。ステージ追加時にUXMLへノードを手動追加する必要はありません。
- Battleステージの敵ウェーブ定義IDまたはミッションIDが未設定の場合、**ゲーム起動時に例外が発生します**（データ作成時にはエラーが出ないため見落としやすい項目です）。

### 🔧 要エンジニア
- ステージシーン（背景・地形そのもの）を新規に作る場合は、Unityシーンの作成・配置が必要なため、シーン担当のエンジニア/背景デザイナーに依頼してください（本ガイドはデータアセットの範囲のみを扱います）。

## ② 敵の出現（ウェーブ）を組む・敵を調整する時

### 敵ウェーブ定義（そのステージに何がどれだけ出るか）
- フォルダ: `Assets/Level/Data/Master/InGame/Enemy/`
- メニュー: `KillChord/Enemy/EnemyWaveDefinitionAsset`
- 構成:
| 項目 | 内容 |
|---|---|
| 敵Wave定義を一意に識別するID | 他のウェーブ定義と重複しない文字列ID |
| このWave定義が対象とするバトルステージシーン名 | 背景の異なるステージシーン（`Stage_01`等）を選択 |
| 1Wave分の定義 | ウェーブごとに下表を設定するリスト |
| 全Wave終了後、繰り返して生成するか／繰り返す場合の開始Index | ループ設定 |
- 1Wave分の定義:
| 項目 | 内容 |
|---|---|
| 個別の敵データごとの定義 | 「生成する個別の敵データ」（下記の`EnemyDefinitionAsset`のIDを候補から選択）と「敵の生成数」（0〜20）の組み合わせを複数設定 |
| Waveの継続時間(秒) | 0〜1800秒。この時間が経過すると敵が残っていても次のウェーブへ強制的に進む |
| Wave開始時に音楽同期で実行するステージ演出 | ⑥で作成する演出をここに追加する（任意） |
| 候補スポーンポイント | このウェーブで敵を生成する地点。空の場合は全スポーンポイントが対象 |
- 作成後、`Assets/Level/Data/Master/InGame/Enemy/` の `EnemyWaveDefinitionRepository` の「IDで取得可能にする敵Wave定義アセットの一覧」へ追加します。個々のウェーブ定義をAddressableにする必要はありません。
- ①の`BattleStageAsset`では「バトルパートで使用する敵Wave定義ID」を開き、候補から登録済みIDを選択します。

### 個別の敵データ（ウェーブに出す敵1種類分）
- フォルダ: `Assets/Level/Data/Master/InGame/Enemy/Definitions/`
- メニュー: `KillChord/Enemy/EnemyDefinitionAsset`
- 作成後、同じフォルダの `EnemyDefinitionRepository` へ登録します。
| 項目 | 内容 |
|---|---|
| 個別の敵定義を一意に識別するID | 他の敵データと重複しない文字列ID |
| 使用する敵の処理種別 | `Infantry`（歩兵）/ `Artillery`（砲兵）の2種類のみ |
| この敵定義が使用する敵プレハブ | 見た目と部品を持つプレハブ |
| キャラクターステータス定義 | 下表の`CharacterDefinitionAsset` |
| 移動仕様 | 下表の`EnemyMoveSpecAsset` |
| 初回攻撃に使用する音楽仕様 / 通常攻撃に使用する音楽仕様 | 下表の`EnemyMusicSpecAsset` |
| 撃破した際にMissionへ通知するキー | ⑤の`EnemyMissionKeyAsset`（「特定の敵の撃破数」条件に使う） |
| CharacterDefinition内で使用する攻撃定義のIndex | 攻撃定義リストの何番目を使うか |
| 専用ObjectPoolの初期容量 / 最大容量 | 同時に出る数の目安。1以上 |
【要確認: プランナーが新しい個別の敵データを作ってよい範囲（プレハブの用意を誰が行うか）を企画に】

### 個々の敵の強さ（既存の敵タイプを調整する場合）
敵1体ごとの強さは、個別の敵データが参照する以下のアセット群で決まります（プレハブ自体の差し替えはエンジニア/デザイナー領域です。数値調整はプランナーのみで可能）。
| アセット | メニュー | 内容 |
|---|---|---|
| `CharacterDefinitionAsset` | `KillChord/Character/CharacterDefinitionAsset` | ID、名前、攻撃硬直時間、最大体力、基本ダメージ、会心率（0〜1。仕様書の「クリティカル率5」は0.05）、使用する攻撃定義リスト |
| `EnemyMoveSpecAsset` | `KillChord/Runtime/Enemy/EnemyMoveSpecAsset` | 移動速度、最小/最大攻撃距離（**最小≦最大でないとエラー**） |
| `EnemyMusicSpecAsset` | `KillChord/Runtime/Enemy/EnemyMusicSpecAsset` | 攻撃のリズム同期タイミング（小節フラグ・拍子・拍目） |
| `ShellAttackSpecAsset`（砲兵のみ） | `KillChord/Runtime/Enemy/ShellAttackSpecAsset` | 爆発半径（0〜32のスライダー） |
攻撃そのものの中身（ダメージ量・会心ダメージ倍率等）は③「攻撃を作る・調整する」を参照してください。
現在の敵・ボスの値は、DB「マスターデータ」の「敵・ボスのステータス」にまとめています。歩兵と砲兵は同じ`CharacterDefinitionAsset`（`Assets/Level/Data/Master/Character/Enemy.asset`）を参照しているため、片方だけ変えることはできません。分ける場合は`CharacterDefinitionAsset`を新しく作り、個別の敵データの「キャラクターステータス定義」を差し替えてください。

### ボスの攻撃パターンを設定する
| アセット | メニュー | 内容 |
|---|---|---|
| `BossAttackEntryAsset` | `KillChord/Runtime/Enemy/BossAttackEntryAsset` | ボスの攻撃種別、対応する攻撃定義のインデックス（`CharacterDefinitionAsset`の攻撃リストの何番目か）、音楽同期情報 |
| `BossAttackEntryRepo` | `KillChord/Runtime/Enemy/BossAttackEntryRepo` | 上記の集合。**空欄のスロットがあるとコンソールに警告が出ます** |
ボスのステータスは`Assets/Level/Data/Develop/Boss/BossCharacterData`（ID `boss_character`）、攻撃の定義は同じフォルダの`BossAttackEntry1`〜`3`と`BossAttackEntryRepo`です。三方向攻撃の左右の角度は、ボスのプレハブ（`Assets/Level/Prefabs/Develop/Boss.prefab`）の`TripleShotRaycastDetectView`で設定します。

### 🔧 要エンジニア
- `Infantry`/`Artillery`以外の**新しい敵の処理種別**を追加する場合（見た目だけでなく、AIの挙動が根本的に異なる新カテゴリを作る場合）。
- 既存の攻撃演出にない**新しい攻撃処理そのもの**を作る場合（③を参照）。

## ③ 攻撃・ダメージ計算を作る・調整する時
プレイヤー・敵に共通する「攻撃」は3つのアセットの組み合わせで構成されます。
```Mermaid
graph LR
    A["AttackDefinitionAsset<br>（攻撃1つ分の定義）"] --> B["AttackSpecAsset<br>（確定ダメージ）"]
    A --> C["AttackPipelineAsset<br>（処理ステップの組み合わせ）"]
```
| アセット | メニュー | 内容 |
|---|---|---|
| `AttackSpecAsset` | `KillChord/Attack/AttackSpecAsset` | 確定ダメージ |
| `AttackPipelineAsset` | `KillChord/Attack/AttackPipelineAsset` | 「攻撃ステップ」をドロップダウンから選んで**好きな順番で組み合わせる**リスト（既存: `CriticalStep`＝クリティカル抽選、`WeaponDamageStep`＝武器ダメージ倍率の適用、`OutOfRangeDamageStep`＝射程外の減衰、`ConfirmedDamage`＝確定ダメージの適用） |
| `AttackDefinitionAsset` | `KillChord/AttackDefinitionAsset` | 攻撃名、上記2つのアセットへの参照、ジャストダメージ倍率、ビートタイプを使うか／使う場合のビートタイプ、下表の武器パラメータ |
`AttackDefinitionAsset`の武器パラメータ:
| 項目 | 内容 |
|---|---|
| 武器ダメージ倍率 | 攻撃力に対する倍率。仕様の「攻撃力200%」は2 |
| 射程（m） | プレイヤーからの水平距離で判定する |
| 攻撃範囲の中心軸からの半角（度） | 直線状の攻撃は小さい値にする |
| 範囲内の複数対象へ同時に命中するか | オフの場合は最も近い1体のみを攻撃する |
| ヒット数 | 1回の攻撃で発生するヒット数。三点バーストは3 |
| 多段ヒットの間隔（秒） | 攻撃硬直より短い値にする |
| クリティカルダメージの倍率 | 武器ごとに設定する。仕様書の「クリティカルダメージ50」は1.5（会心率はキャラクター側で設定する） |
| 射程外ダメージ倍率 | 0〜1。1で減衰なし、0.5で半減。0でもヒットは成立しダメージ0が表示される |
作成した`AttackDefinitionAsset`は、②の`CharacterDefinitionAsset`の「攻撃定義リスト」に追加することでキャラクターが使用できるようになります。

### ⚠️ 注意点
- `AttackSpecAsset`・`AttackPipelineAsset`への参照を設定し忘れると、**インスペクター上ではエラーが出ず、実行時に初めて例外が発生します**。作成したら必ず両方を割り当てたか確認してください。
- 「ビートタイプを使用する」をオンにした場合、指定するビートタイプの値が正しい範囲でないと実行時にエラーになります。

### 🔧 要エンジニア
- 既存のステップ以外の**新しい攻撃処理の種類**（例: 「一定確率で追加攻撃が発生する」等）を追加したい場合、`IAttackStep`を実装する新しいC#クラスが必要です。一度実装されれば、それ以降はプランナーが`AttackPipelineAsset`のドロップダウンから自由に選んで組み合わせられます。

## ⑤ ミッション（クリア条件・サブミッション）を設定する時
1ステージにつき1つの`MissionDefinitionAsset`を作成します。
- フォルダ: `Assets/Level/Data/Master/OutGame/StageSelect/Mission/`
- メニュー: `KillChord/Mission/MissionDefinition`
- 作成後、同じフォルダの `MissionDefinitionRepository` へ登録します。登録したミッションのIDを①の`BattleStageAsset`で選択します。
| 項目 | 内容 |
|---|---|
| ミッションを一意に識別するID | 他と重複しない文字列ID |
| ミッションの表示名 / ミッションHUDに表示される説明文 | UI表示用 |
| 敗北時に表示する攻略Tips一覧 | 複数登録するとランダムで1つ表示される |
| **クリア条件** | 目標（ステップ）の並び。単一の条件で済む場合は要素数1にする。選べる条件: 「経過時間（生存）」「敵の撃破数」「すべての敵ウェーブの撃破」「行動の反復回数」「シナリオ再生の完了」、条件を組み合わせる「AND/OR」、内側の条件を包んでステップ開始時に働く「説明ポップアップの表示」「次の敵ウェーブの生成」「プレイヤーへのバフ・デバフ」 |
| **失敗条件** | ドロップダウンで選択: 「制限時間超過」「プレイヤー死亡」、または「AND/OR」で組み合わせ |
| **評価条件（サブミッション）** | リストに複数追加可能。既存の種類: クリアタイム、被ダメージ量、コンボ数、使用武器種類数 |
サブミッション（評価条件）は**重複ありで3件設定**すると、達成数に応じてリザルト画面でC/B/A/Sランクが算出されます（0件→C、1件→B、2件→A、3件→S）。
「敵の撃破数」条件で特定の敵だけを数える場合は、同じフォルダ（`Assets/Level/Data/Master/OutGame/StageSelect/Mission/`）に`EnemyMissionKeyAsset`（メニュー `KillChord/Mission/EnemyMissionKeyAsset`）を作成して `EnemyMissionKeyRepository` へ登録し、条件と、②の個別の敵データの「撃破した際にMissionへ通知するキー」の両方へ割り当ててください。

### ⚠️ 注意点
- 評価条件のIDが空欄、または他の評価条件と重複していると、**ゲーム起動時にエラーで停止します**。

### 🔧 要エンジニア
- 上記以外の**新しい種類のクリア条件・失敗条件・評価条件**を作りたい場合（例: 「特定アイテムを入手する」等）、対応するC#クラスの実装が必要です。一度実装されれば、以降はプランナーがドロップダウンから選ぶだけで使えるようになります。

## ⑥ ステージ演出（爆発・建物倒壊等）を追加する時
ウェーブ開始時にBGMと同期して発生する演出です。
- 対象アセット: `ExplosionStageEffectAsset`（爆発）/ `BuildingCollapseStageEffectAsset`（建物倒壊）/ `ObstacleStageEffectAsset`（障害物発生）
- 作成場所: ②の「敵ウェーブ定義」アセットを開き、ウェーブ単位の「Wave開始時に音楽同期で実行するステージ演出」リストへ、`+`ボタンから種類を選んで直接追加します（単独のアセットファイルとしては作らず、ウェーブ定義の中に埋め込む形式です）。
| 項目 | 内容 |
|---|---|
| StageEffectView側の演出と対応するID | 演出側（VFX/Timeline等）で用意されているIDと一致させる。詳細はデザイナー/エンジニアに確認してください |

| 演出を同期する拍子 | 通常は4のままでよい |
| 小節内で演出を実行する拍 | 何拍目で発生させるか |
インスペクター上に自動生成される「設定内容の要約」欄で、現在の設定を一目で確認できます。

### ⚠️ 注意点

### 🔧 要エンジニア
- 上記3種類以外の**新しい演出の種類**を追加する場合、対応するC#クラスと実際の演出（VFX/Timeline）の実装が必要です。

## ⑦ スキルを作る時
スキル追加は本ガイドの中で最も工程が多く、**エンジニアの協力が必須になる場面が多い**分野です。事前によく確認してから着手してください。

### 全体像
```Mermaid
graph TD
    A["① SkillTemplateAsset<br>（スキル本体のデータ）"] --> B["OutGameSkillRepository<br>（全スキルの一覧に登録）"]
    A --> C["② SkillNodeData<br>（スキルツリーのノード）"]
    C --> D["SkillNodeDataRepo<br>（ノード一覧に登録）"]
    C --> E["③ SkillNodeBindData<br>（ツリー画面のUI要素と対応付け）"]
    E --> F["SkillNodeBindRepo<br>（バインド一覧に登録）"]
```

### 手順
1. **スキル本体を作る**
  - フォルダ: `Assets/Level/Data/Master/Skill/Templates/`
  - メニュー: `Game/SkillTemplate`
  - 設定項目:
| 項目 | 内容 |
|---|---|
| スキルID | 他と重複しない文字列ID |
| スキル表示名 / アウトゲーム画面で表示するスキルアイコン / スキル詳細 | 改造・研究画面の表示用 |
| 改造画面に表示するスキルTips | 空欄の場合は表示しない |
| アウトゲーム画面でのスキル効果表示モード | `FullDescription` / `ComboOnly`。`ComboOnly`ではスキル詳細（効果説明テンプレート）が空でも警告しない【要確認: 各モードで画面に何が表示されるかをUI担当に】 |
| 効果処理と説明文で共有する数値パラメータ | 「効果パラメータの識別子」「ゲーム処理で使用する値」「表示形式」の組。効果ごとに使う識別子は下表を参照 |
| レベルアップ時に成長させるパラメータ | 成長させるパラメータだけ設定する。成長方式は加算/乗算。未設定の遷移は乗算×1.1 |
| スキルの種類 | `Attack` / `Buff` / `Debuff`（複数可） |
| スキルのレベル | 0以上 |
| 入力パターン | リズム入力コマンドの並び（`One`/`Two`/`Three`/`Four`/`Six`/`Eight`から選択） |
| クールダウン時間（小節単位の分子・分母） | 例: 分子2, 分母1 なら「2小節」 |
| **スキル効果の識別子** | 既存の効果（`Skill00`〜`Skill10`、`Skill13`）からドロップダウンで選択。**⚠️新しい効果を選ぶことはできません（下記参照）** |
| スキル対象の解決ルール | `Self`（自分）/ `CurrentTarget`（現在のロックオン対象）/ `ForwardArea`（前方エリア）/ `CurrentTargetForwardLine`（現在ロックオン対象を含む前方直線）から自由に選択可（コード変更不要） |
| 状態効果の再付与ポリシー | 同じ状態効果を重ねたときの扱い（`Stack` / `ExtendDuration` / `RefreshDuration` / `Replace` / `Ignore`） |
| スキル発動時の通常攻撃ダメージの計算ポリシー | `Apply`（通常攻撃のダメージも与える）/ `Skip`（与えない） |
| スキル発動時に再生するアニメーションキー | 空欄なら通常攻撃アニメーションを使用 |
2. **スキル一覧へ登録する**
  - `Assets/Level/Data/Master/Skill/Repositories/` の `OutGameSkillRepository` を開き、①のアセットをリストに追加する
3. **スキルツリーのノードを作る**
  - フォルダ: `Assets/Level/Data/Master/OutGame/SkillTree/SkillNodeData/`
  - メニュー: `SymphonyDev/SkillTree/SkillNodeData`
  - 設定項目: ノードID（重複不可）、親ノードID（複数可）、解放に必要な解放ポイント、ノード詳細テキスト、プレビュー動画（任意）、解放時の報酬（**このノードで解放されるスキル**＝①のID、ステータスボーナス効果＝最大HP倍率・攻撃力倍率・会心率加算・会心ダメージ倍率加算・範囲攻撃の射程加算、スキル編成枠を1つ増やすか）
  - 作成後、`Assets/Level/Data/Master/OutGame/SkillTree/` の `SkillNodeDataRepo` へ登録する
4. **ツリー画面のUI要素と対応付ける**
  - フォルダ: `Assets/Level/Data/Master/OutGame/SkillTree/SkillNodeBindData/`
  - メニュー: `SymphonyDev/SkillTree/SkillNodeBindData`
  - 対応するUI Toolkit画面上の要素名、接続線の要素名を設定します。**この画面レイアウトは事前にUI担当が用意している必要があります**（新しいノードの見た目の配置を追加する場合は、先にUI担当へ相談してください）
  - 作成後、`SkillNodeBindRepo` へ登録する
  - 新しい階層（フェーズ）を追加する場合のみ、同様に `SkillNodePhaseBindData` を作成し `SkillNodePhaseBindDataRepo` へ登録する
5. **（必要な場合）初期所持・初期装備にする**
  - `Assets/Level/Data/Master/OutGame/SkillBuild/InitialSkillLoadout` の「ゲーム開始時に解放済みとするスキルの一覧」「ゲーム開始時に装備済みとするスキルの一覧」へ①のIDを追加する

## 🔑 IDの付け方（`DataID`）
アセット同士を参照させるためのIDには`DataID`という共通の仕組みを使う。インスペクター上では**人間が読める文字列IDを入力する欄**と、**編集できない数値ID欄**の2つが並んで見える。
| 欄 | 誰が入力するか | 内容 |
|---|---|---|
| 文字列ID | プランナー | `Skill_Slash_01`のように、人が読んで意味の分かる名前を付ける |
| 数値ID | 自動 | 文字列IDとCollectionKeyから焼き込まれる。手で書き換えない |
実行時の照合はすべて数値IDで行われ、文字列IDはエディタでしか保持されない。数値IDは`DataIDHasher`がCollectionKeyと文字列IDを組み合わせて生成するため、**同じ文字列IDでも、属するコレクションが違えば別のIDになる**。
守ってほしいことは次の3点である。
- **文字列IDを後から変更しない。** 数値IDが変わり、そのIDを参照していた側の紐付けが切れる。
- **同じコレクション内で文字列IDを重複させない。** 数値IDが衝突し、意図しないデータが引かれる。
- **数値ID欄を直接編集しない。** 読み取り専用として扱う。
> 🔧 **要エンジニア**: 新しい種類のマスターデータを`SourceDataProvider`へ登録する作業（`SourceDataCollectionAttribute`によるCollectionKeyの指定、`SourceDataAddressAttribute`によるAddressableキーの選択）はコード変更を伴う。`RepositoryAddressSelectorAttribute`は互換維持用の旧属性であり、新規コードでは`SourceDataAddressAttribute`を使う。登録済みのCollectionKeyの一覧は「SourceDataProvider」ページにある。
「SourceDataProviderに登録されていません」という警告や、ハッシュ不一致の警告が出た場合は、上記の登録が済んでいないか、文字列IDが変更された可能性がある。エンジニアへ連絡してほしい。

## 📚 早見表: エンジニアへの依頼が必要になる主なケース
| ケース | 理由 |
|---|---|
| 新しい攻撃処理の種類を追加する（③） | `IAttackStep`の新規実装が必要 |
| 新しいクリア条件・失敗条件・評価条件の種類を追加する（⑤） | 対応するC#クラスの新規実装が必要 |
| 新しいステージ演出の種類を追加する（⑥） | 対応するC#クラスと演出本体の実装が必要 |
| 新しい敵の処理種別（歩兵・砲兵以外）を追加する（②） | AI・スポナーのコード変更が必要 |
| **新しいスキル効果を作る、または効果が読んでいないパラメータで調整する（⑦）** | 効果はC#クラスとして実装されており、読むパラメータも効果ごとに決まっている |
| スキルツリーの新しいノード配置・接続線のUIレイアウトを追加する（⑦） | UI Toolkitの画面レイアウト作業が必要 |
| 新しいステージシーン（背景）を作る（①） | シーン制作が必要 |
| 製品版と体験版のデータの分け方を変える（前提知識） | Addressables Groupの設定変更が必要 |
一方で、**既存の種類の範囲内でのアセット新規作成・数値変更・組み合わせ**（ステージ追加、Bindの接続、ミッション条件の設定、敵の強さ調整、攻撃パラメータ調整、プレイヤーのステータス調整、スキルの効果パラメータ調整、初期所持スキルの変更、演出のタイミング調整）は、すべてプランナーの操作のみで完結します。

## 🗂️ Planner Master Dataからデータを探してInspectorで編集する
メニュー `Window/KillChord/PlannerMasterDataWindow` から`Planner Master Data`を開くと、Stage Select / Player / UI / Enemy / Skill Tree / Scenario / Resource の各ページからデータを探せます。値の編集とプレビューはUnityのInspectorで行います。最初にツールバーの`Variant`でRelease / Demoを確認してください（表示するデータとアセットの生成先が切り替わります。ビルドには影響しません）。
- `Source Assets`: 行を選ぶと対象アセットをProjectとInspectorで選択します。Collection配列だけを保持するRepositoryはCollections側の先頭行に表示します。
- `Collections`: 行を選ぶと実体をInspectorで開きます。カタログ等のインライン要素は、所有アセットのInspector先頭に「Plannerで選択中の項目」として表示します。Inspectorを別アセットにロックしている場合はロックを解除してください。
- `Search`: アセット名、DataID、Tips本文、BGMラベル、アイコン種別を横断検索します。ページ未割当のアセットも検索から選択できます。
- `Sort`: 表示順だけを変更します。実データの配列順は変わりません。
- `データを追加`: ScriptableObject型のCollectionでは新規アセットを作成して自動登録します。インライン型ではSourceAsset内に新規要素を作成します。
- `Source Assetを開く`: 所有アセットをInspectorで選択します。配列だけのRepositoryの場合は対応Collectionの先頭行に移動します。
- `Collectionから外す`: 選択行の登録を解除します。参照先アセットファイル自体は削除しません。
ScriptableObjectの生成場所は`Project Settings > KillChord > Source Data Provider`の各Collectionにある`Asset Creation Directory`で指定します。存在する`Assets/`配下のフォルダだけを設定してください。`{Variant}`と書くと、`Variant`の選択に応じて`Master`または`Demo`に置き換わります。
Stage / Bind / StageTreeをInspectorで開くとグラフを表示します。ドラッグで移動し、ノードをクリックしてステージを選べます。緑の線は自動遷移、灰色の線はホーム帰還、選択したBindは強調表示です。BattleStageの「参照Waveのシーンマップ」を展開すると所属ツリーに対応するウェーブのマップを確認できます。CharacterのInspectorには主要ステータスのレーダーグラフを表示します。
ウェーブ定義のInspectorでは概要に続くスライダーでマップを表示するウェーブを選び、スポーン候補地を編集できます。シーンを変更した後は`Refresh Map`で更新できます。カタログのインライン要素ではAssetKeyや参照画像も選択項目欄から確認できます。複数アセット選択時は通常項目のみ一括編集でき、単一アセットのプレビューは表示しません。
Projectウィンドウでは、Addressablesに登録済みのアセットと、SourceDataProviderのCollectionに登録済みのアセットに、それぞれ小さなバッジが付きます（両方付くこともあります）。Planner Master Dataを開いていなくても表示されます。
