## 判定

- 信頼性: 判定不能（SourceTree の操作手順は正しいが、同期元ブランチが実運用と合っていない可能性がある）
  - 本文は「`feature/designer/master` からプルし、自分のブランチから PR を作る」としている
  - 2026-08-15〜09-22 のデザイナーの PR は、`designer` ブランチから `develop` へ直接出ている（#1361 / #1500 / #1515、base = develop）。個人ブランチ `feature/designer/yahata` の PR #1514 も base = develop である
  - 手元の remote-tracking に `feature/designer/master` は無い（`git for-each-ref refs/remotes` で 0 件。取得範囲の都合の可能性あり）
- 整合性:
  - 「GitHub 運用規定」（2a87c2c6-cc02-804b-9b05-d384f4d76dbc）は `feature/機能名/master` を機能開発マスターとし、個人ブランチを切ると Actions がマスターを自動作成する、としている。本ページの `feature/designer/master` はこの規則に沿った名前だが、実際の PR の流れ（`designer` → `develop`）と食い違う。
  - ステータスリストの「非エンジニア向けSourceTree手順書」（3527c2c6-cc02-80fc-bc51-cde10f82f0eb）が同じ主題のタスクで、本ページがその成果物にあたる。重複ではない。
- 変更点:
  - 「【重要】作業時の大まかな流れ」節の末尾に、同期元ブランチの【要確認】コールアウトを追加
- 織り込んだ反映項目: なし（10〜60 に本ページを反映先とする項目は無い。50_基盤・ツール・規約.md RL-08「ブランチ命名が実態と合っていない」と関連）
- 出典: prs-list.tsv / prs-all.json（#1361, #1500, #1514, #1515 の headRefName / baseRefName）、`git log --grep=designer`（84f93ba73, 71635a099）
- 要確認:
  - デザイナーの同期元・PR 先は `feature/designer/master` か `designer` か（リードデザイナー・クライアントリードに。Discord 未照合）。確定したら本文の `feature/designer/master` を置き換える
