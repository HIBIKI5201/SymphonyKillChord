# 改造画面(SkillBuild)スキル一覧UI刷新 引継ぎ資料

作成日: 2026-09-04
対象ブランチ: `feature/demo/level-design/master`

## 1. 経緯・要望

改造画面(`ScreenId.SkillBuild`)のスキル一覧は、従来「入手済み(=研究画面で解放済み)のスキルのみをアイコン+名前だけ横一列で並べる」というシンプルな表示だった。別ゲームのキャラクター一覧画面(バッジアイコン付きカードが2グループに区切り線で分かれている)を参考に、以下の要望が出された。

1. カード左上のバッジ = スキルジャンルアイコン(Attack/Buff/Debuff)。タップでそのジャンルのみに絞り込み表示。
2. 区切り線で「解放済み(前半)/未開放(後半)」の2グループに分ける。未開放スキルも一覧に表示する(従来は入手済みのみ表示だった)。
3. 装備の仕組みを「カードをスロットへ物理的にドラッグ移動する」方式から、「カードは常に一覧に残したまま、バッジ(チェックマーク)で装備中を示す」方式へ変更(ユーザーが高リスクと認識した上で選択)。
4. レイアウトは横一列スクロールを維持(グリッド折り返しはしない)。
5. カード同士の間隔を広げる(最終的に4%)。
6. 解放済み/未開放のソート(スキル番号昇順)は、スキル一覧が変わるたび(装備/解除を含む)に常に反映されること。

## 2. 実装内容サマリ

### A. 全スキル表示 + 解放済み/未開放グルーピング
- `SkillBuildInitializer` に `SkillRepository`(全スキルカタログ、Addressablesキー `"OutGameSkillRepository"`、研究画面と共用)を追加ロード。
- `SkillBuildPresenter.Push(...)` が「入手済みスキルID集合」と「全スキル」を突き合わせて `IsUnlocked` を判定し、`SkillViewData[]` を構築するように変更。
- `SkillViewData` に `IsUnlocked`(bool)、`GenreIcon`(Sprite)、`GenreIds`(int[]、後述)を追加。

### B. ジャンルバッジ + タップ絞り込み
- `SkillBuildInitializer` に `SkillGenreIconCatalogAsset`(Addressablesキー `"SkillGenreIconCatalogAsset"`、研究画面と共用)を追加ロードし、`Dictionary<SkillType, Sprite>` を構築して Presenter へ注入。
- `Skill.uxml` にジャンルバッジ用 `Image`(カード左上)・装備バッジ用 `VisualElement`(カード右上、既定非表示)・未開放ラベル用 `Label` を追加。
- カード左上のジャンルバッジをタップすると `SkillBuildScreenView` がフィルタ状態(`int? _activeGenreFilter`)を切り替え、`SkillListView.ApplyGenreFilter` で非該当カードを非表示にする(再タップで解除)。

### C. 装備をバッジ表示化(高リスク改修)
- `SkillElementDragAndDropManipulator.CompleteDrag()` からスロットへの実要素の再親化(`MoveSkillToSlot`)を廃止。ドロップ判定と装備状態の更新通知(`_onDropAction`)は維持しつつ、カード要素は常に一覧側へ戻す。
- `SkillBuildSlotLayout` を「DOM再親クラス」から「スロット内の小さな `Image`+`Label` にスキル情報をバインドするだけのクラス」へ全面書き換え。スロットタップで装備解除できるようにした。
- `SkillListView` に装備中バッジの表示切り替え(`SetEquippedSkillIds`)、未開放カードのドラッグ無効化(`SetupDraggable` 呼び出しを解放済みカードのみに限定)を追加。

### D. 見た目の調整(このチャットで段階的に対応)
- カード間の余白: 1% → 2% → **4%**(`SkillIcon.uss` / `SkillBuildScreen.uss` の `.skill-icon` `margin-left/right`)。
- 解放済み/未開放の区切り線: `.skill-group-divider` の高さ指定を `align-self: stretch`(高さが解決できず見えない場合があった)から**固定 150px** に変更し、幅・余白も拡大して視認性を上げた。

## 3. 発生した不具合と対応

### 3-1. View層がDomain型を直接参照してコンパイルエラー
`SkillViewData.Types` を `SkillType[]`(Domain層の型)のまま View層(`SkillListView`/`SkillElementView`/`SkillBuildScreenView`)に渡していたためコンパイルエラー。研究画面の `PlayerStatusScreenView` の時と同種の層違反。
→ **対応**: `SkillViewData.GenreIds` を `int[]`(Domain非依存)に変換し、View層はジャンルを int ID として扱うよう修正済み。

### 3-2. 「解放済み/未開放が逆」という報告
調査の結果、コード側の判定ロジックには問題が見当たらず、**今回のセッション中に研究画面ノード(`SkillNodeData-N1`)の `_unlockSkills` を編集した影響で、テストセーブの `UnlockedSkillIds` が古い状態のまま残っていた**ことが原因と推定。該当ノードを研究画面で再解放してもらったところ解消した(ユーザーも「以前から確認できていた既知の挙動」と認めている)。→ **コード修正なし、対応不要と判断**。

### 3-3. 新規セーブでチュートリアルが進行不能になる件 (未解決・別問題の可能性)
セーブをリセットしたところ、初期装備スキルが付与されておらずチュートリアル戦闘に進めなくなった。ユーザーは「今回の改造画面の変更が原因では」と推測しているが、**新規セーブだとチュートリアルが強制的に始まり改造画面へ到達できないため、改造画面側のコードが原因である可能性は低い**と考えられる(改造画面のコードが実行される前の話のため)。
→ **未検証のまま保留**。切り分けにはチュートリアルをスキップして改造画面に入れる状態のセーブが必要(ユーザー側に手段があるとのこと)。**別チャットで改造画面の作業を続ける場合、この件が再度話題に上る可能性がある**ため申し送りしておく。

### 3-4. スキルをドラッグすると一覧の並びが崩れる(根本原因を特定・修正済み)
「解放済み/未開放でソートしてほしい」「装備/解除のたびにソートし直してほしい」という要望を経て検証したところ、**カードを少しでもドラッグする(ドロップしなくても)と一覧の並びが崩れる**という不具合が判明。

**根本原因**: `SkillElementDragAndDropManipulator.SnapBackToStart()` がドラッグ後にカードを元の位置へ戻す際、`VisualElement.Add()` を使っていた。UI ToolkitのuAdd() は常に「親要素の末尾に追加する」ため、ドロップの成否に関わらずドラッグしたカードは毎回一覧の末尾に移動してしまい、これを補正する仕組みもなかった(状態変更を伴わないドラッグでは一覧の再構築自体が起きないため)。

**対応**:
1. `SkillElementDragAndDropManipulator` にドラッグ開始時の元インデックス(`_startIndex`)を記録し、`SnapBackToStart()` で `Add()` の代わりに `Insert(_startIndex, ...)` を使うよう修正(**これが本質的な修正**)。
2. 加えて `SkillListView.SetSkills` 自体が、渡された順序に関わらず毎回「解放済みを番号昇順→区切り線→未開放を番号昇順」に並び替えるようにし(Presenter側の並びに依存しない、多重の安全策)、`SkillBuildScreenView` はスロット状態(`Slots`)が変化するたび(装備/解除のたび)にも一覧の再構築をスケジュールするようにした。

※ `SkillId` は文字列ID("skill_00"等)から焼き込まれたハッシュ値であり連番ではないため、ソートは表示名末尾の数字("スキル13"→13)を抽出して行っている(`SkillBuildPresenter.ExtractSkillNumber` / `SkillListView.ExtractSkillNumber`、実装が2箇所に重複している点は将来的に共通化の余地あり)。
