## 【設計指摘】同じ閾値が別ファイルに重複してハードコードされている

**場所**:
[EnemyRaycastDetectView.cs:344](../../Assets/Scripts/Runtime/4.View/InGame/Enemy/EnemyRaycastDetectView.cs)、

```csharp
private bool IsEnemyOrigin(Vector3 sourcePosition)
{
    return (sourcePosition - transform.position).sqrMagnitude <= 0.0001f;   // 両ファイルで同一

```

`0.0001f`（= 0.01m の二乗）が2ファイルに複製されている。
この2クラスは全体的にコピペ関係にある（[10. コード重複](10_コード重複と過剰抽象化.md) 参照）ため、
共通化の際に一緒に定数化するのが効率的。

```csharp
/// <summary> 発射位置が敵自身の位置とみなせる距離の二乗閾値。 </summary>
private const float ORIGIN_MATCH_SQR_DISTANCE = 0.0001f;
```

## 【設計指摘】シェーダ値のマッピングが裸の数値

**場所**: [ShellView.cs:84-90](../../Assets/Scripts/Runtime/4.View/InGame/Enemy/ShellView.cs)

```csharp
_material.SetFloat("_Circle", color switch
{
    ShellColor.Green  => 0.33f,
    ShellColor.Yellow => 0.66f,
    ...
});
```

`0.33f` / `0.66f` はシェーダ側のUV分割やアトラス位置と対応した値だが、
コード上からはその根拠が読めない。シェーダ側の定義が変わると静かに壊れる。

`"_Circle"` という文字列プロパティ名も定数化対象
（[04. GC Alloc](04_GCAllocとメモリリーク.md) の `Shader.PropertyToID` 化と併せて対応）。

**修正方針**:
```csharp
/// <summary> シェーダ _Circle のセグメント総数。色ごとに 1/SEGMENT_COUNT 刻みで対応する。 </summary>
private const int SHELL_COLOR_SEGMENT_COUNT = 3;
private static readonly int CIRCLE_PROPERTY_ID = Shader.PropertyToID("_Circle");
```

## 【設計指摘】NavMesh探索パラメータがコメントで補われている

**場所**: [NearestAttackPositionSearchView.cs:57-58](../../Assets/Scripts/Runtime/4.View/InGame/Enemy/NearestAttackPositionSearchView.cs)

```csharp
// ここの1fは、NavMesh上でのサンプリングの半径。敵身長の2倍が推奨な値らしい
if (!NavMesh.SamplePosition(_positionSamples[i], out NavMeshHit hit, 1f, NavMesh.AllAreas))
```

コメントで意味を補っている時点で定数化すべきというシグナル。
しかも「敵身長の2倍が推奨」という記述がありながら固定値 `1f` になっており、
敵のサイズが変わっても追従しない。

**修正方針**: `[SerializeField]` で敵ごとに設定可能にするか、最低限定数化する。

```csharp
/// <summary> NavMesh上へ候補位置を投影する際の探索半径。敵身長の約2倍が推奨。 </summary>
private const float NAVMESH_SAMPLE_RADIUS = 1f;
```

## 【設計指摘】ACLikeRhythmGuideViewの定数化は概ね良好

**場所**: [ACLikeRhythmGuideView.cs:685-687](../../Assets/Scripts/Runtime/4.View/InGame/Music/ACLikeRhythmGuideView.cs)

```csharp
private const float DEFAULT_DISPLAY_LENGTH = 120f;
/// <summary> ゲージ全長が表す小節数。Justは小節内正規化位置(1/BeatCount)をこの値で割った位置になる。 </summary>
private const float GUIDE_LENGTH_IN_BARS = 1.5f;
```

`GUIDE_LENGTH_IN_BARS` は説明コメント付きで良い。ただしファイル内には
まだ裸の数値が残っている。

```csharp
// line 370-373 — 下限値のクランプ
float overshootDuration = Mathf.Max(0.01f, _effectConfig.JustOvershootDuration);
float returnDuration    = Mathf.Max(0.01f, _effectConfig.JustReturnDuration);
float flashDuration     = Mathf.Max(0.01f, _effectConfig.FlashDuration);

// line 440-441 — マーカー最小サイズ
Mathf.Max(0.1f, _effectConfig.MarkerWidth),
Mathf.Max(0.1f, _effectConfig.MarkerHeight));

// line 508 — Vignette最小時間
Mathf.Max(0.01f, _effectConfig.VignetteDuration))
```

`0.01f`（最小デュレーション）が4回、`0.1f`（最小サイズ）が2回出現する。

**修正方針**: 
```csharp
/// <summary> モーション時間の下限。0除算とゼロ長モーションを防ぐ。 </summary>
private const float MIN_MOTION_DURATION = 0.01f;
/// <summary> マーカー矩形サイズの下限。 </summary>
private const float MIN_MARKER_SIZE = 0.1f;
```

より根本的には、これらのクランプは **`ACLikeRhythmGuideEffectConfig` 側で
`[Min(0.01f)]` 属性を付ければ不要**になる。Inspector入力段階で制約すれば
実行時のクランプが全て消える。
