# Notion原文の書式

`pull`で取得できるのはNotionのEnhanced Markdownであり、GFMとは書式が違う。
ここに書いてあるのは実際に往復させて確認した挙動である。

## 書き込むときに使える記法

| 書きたいもの | 書き方 | 備考 |
| --- | --- | --- |
| 表 | GFMのパイプ表 | Notionが表ブロックへ変換する。往復すると`<table header-row="true">`形式で返る |
| コールアウト | `> 💡 **見出し**` の次行も `> ` で継続 | 1行にまとめる場合は`<br>`でつなぐ |
| トグル見出し | `## 見出し {toggle="true"}` の下をタブ字下げ | 中身に表も入る。目次に残るのでこちらを推奨 |
| トグル | `<details>` と `<summary>` | 中身はタブ字下げで返る |
| 見出しの背景色 | `# 見出し {color="gray_bg"}` | H1に付ける（ライティング規則） |
| 目次 | `<table_of_contents color="gray"/>` | ページ先頭に置く |
| Mermaid | ` ```mermaid ` のコードブロック | 下記の制限あり |
| 子ページ | `<page url="...">タイトル</page>` | 既存の子ページへの参照。この記法で新規作成はできない |

## できないこと

- **Mermaidの表示モード（Code / Preview / Split）はAPIから設定できない。**
  コードブロックが持つのは`caption`・`rich_text`・`language`だけで、
  `display_mode`などを送ると400 `should be not present`で拒否される。
  Markdown側にもコードフェンスの属性指定は無い。**プレビュー表示はNotion上での手動操作が必要。**
- コードブロックに`{color=...}`は付かない。属性が使えるのはテキスト・見出し・リスト・引用。
- `bookmark` / `embed` / `link preview` / `breadcrumb` はMarkdownに落ちない。
  これらを含むページを往復させると壊れるので、そのページはNotion上で直接編集してもらう。

## 子ページの位置

子ページを`create`すると、ブロックは**本文の末尾**へ追加される。
途中の位置へ置きたい場合は、作成後に`<page url="...">タイトル</page>`の行を目的の位置へ含めた本文を
`push --whole`で送る。移動は削除扱いにならず、そのまま反映される。

順序としては「子ページを作る → 本文をpush」が良い。逆にすると位置直しのためにpushが2回必要になる。

## 競合検出の誤検知

書き込み直後は、Notion側の`last_edited_time`が数分遅れて更新されることがある。
その状態で`pull`→`push`すると「pull以降にNotion側が更新されています」と出る。
他人の編集でないと分かっているなら、`pull`し直せば通る。
