# モジュール文書の運用

Notionの「システムリスト」データベースにあるモジュール文書（カメラ、プレイヤー、ミッション等）の
書き方と反映手順。

## 正本はNotion側

| 場所 | 役割 |
| --- | --- |
| Notion「システムリスト」DBの各ページ | 正本。本文と処理フローの子ページを直接編集する |
| `Docs/NotionSpecifications/Symphony Kill Chord/システム概要/システムリスト/` | 読み取り専用の写し。読むときに使う |

リポジトリにあった旧正本（`Assets/Docs/ScriptsDocs/Modules/NotionModuleDocs/`）はNotionへ反映したうえで削除した。
リポジトリからNotionへ同期するスクリプトも廃止した。

## 節の構成

既存のモジュールページ（例: 敵・ミッション）と同じ節構成にする。加えて次を守る。

- **クラス一覧はトグル見出しにする。** `## 🏗️ クラス {toggle="true"}` と書く。
  `### 🧩 Composition初期化情報`は畳まない（初期化順が見えなくなるため）。
- **処理フローは1フローにつき1ページの子ページにする。** 本文には子ページへのリンクだけを置く。
- **「アーキテクチャ上の特徴・既知の課題」の節は作らない。**
  課題はIssueへ、設計上の特徴は概要・依存関係・拡張ポイント・処理フローの文脈で述べる。
- 文体は[writing-rules.md](./writing-rules.md)に従う。

## 反映手順

本文も子ページも、[SKILL.md](../SKILL.md)の「既存ページを更新する」と同じ pull → 編集 → dry-run → 承認 → `--confirm` で直す。

1. モジュールのページを`pull`し、必要な節だけを編集する。
2. 処理フローを直すときは、そのフローの子ページを`pull`して編集する。
   新しいフローは`create --parent <モジュールのページ>`で子ページとして作る。
3. フローを改名・統合して古い子ページが不要になったら、`archive`でゴミ箱へ移す。
4. 送信の前にdry-runの差分をユーザーへ提示し、承認を得てから`--confirm`を付ける。

## 実装から書くときの調べ方

1. モジュールのフォルダを層ごとに列挙する（`Assets/Scripts/Runtime/<層>/<カテゴリ>/<モジュール>/`）。
2. Notionのクラス表と突き合わせ、増減したクラスを洗い出す。
3. 新しいクラスは`<summary>`のXMLドキュメントコメントから役割を取る。これが最も安い。
4. `Order`は`Initializer`の`public override int Order`を見る。文書に書く。
5. 依存の向きは、Initializerが`ServiceLocator.GetInstance<T>()`で何を取っているか、
   自分のContainerを誰が参照しているかで確認する。**コミットメッセージから推測して書かない。**
