# ステージ実装レポート

- 調査日: 2026-07-13
- 対象仕様: `Assets/Docs/ステージ仕様.txt`
- 調査対象: `Assets/Scripts/Runtime`、ステージ選択データ、ミッションデータ、InGame・Stageシーン
- 調査方法: コードおよびUnity YAMLの静的調査

## 結論

ステージ進行、ミッション終了、リザルト表示、敵Wave進行の基礎機能は実装されている。

一方で、チュートリアル自動開始、サブミッション3件とランク算出、フェーズ連動演出、複数ステージの実データ、クリア進行の保存が不足している。そのため、現状は仕様を部分的に満たしているものの、ステージシステム全体としては未達である。

## 実装済みのステージフロー

1. `SequenceInitializationModule`がミッション終了イベントを購読する。
2. 開始演出中は`InGamePlayDirector`がゲームプレイを停止する。
3. 開始演出終了後に入力、ミッション更新、音楽同期、敵スポナー、Waveタイマーを開始する。
4. `MissionRuntimeService`が成功または失敗を確定する。
5. `InGameSequenceDirector`がゲームプレイを停止し、終了演出とリザルト表示を行う。
6. リザルトの完了ボタンからStageシーンとInGameシーンをアンロードし、OutGameシーンへ戻る。

この流れは、ステージ開始からリザルト表示までの基本仕様を満たしている。

## 敵Waveシステム

### 適合している点

- ステージ開始時に最初のWaveを生成する。
- 現在管理している敵数が0になると次Waveを生成する。
- WaveDuration経過時は敵が残っていても次Waveを生成する。
- Waveごとに敵種類と敵数を変更できる。
- 最終Waveと全Wave撃破を表す状態を持つ。

### 問題点

- `EnemyWaveDefinition`には敵情報と時間しかなく、背景演出や障害物生成を記述できない。
- 次Wave開始を外部モジュールへ通知する、Wave番号と定義を伴ったイベントがない。
- `EnemyInitializer`がInGameシーンに設定された単一のAddressablesキーからWave定義を読むため、ステージごとにWave定義を切り替えられない。
- 本番Waveデータはループ設定であり、全Wave終了をステージクリア条件として利用できない。
- 全滅イベントとタイマー満了が近接した場合に、次Wave生成要求を一度だけに制御する排他状態がない。

### 推奨方針

ステージ選択データにステージ固有のWave定義キーを持たせ、選択済みステージ状態を経由して`EnemyInitializer.ResourceLoadAsync()`でロードする。

また、Wave定義に敵生成以外の処理を直接追加するのではなく、Wave開始時にWave IDを通知するAdaptor契約を追加する。背景演出、障害物、音楽同期演出は、それぞれ独立したモジュールがWave IDに対応する定義を処理する形にする。

## ミッション・リザルト

### 適合している点

- メインミッションのクリア条件と失敗条件が分離されている。
- サブミッション相当の評価条件がメイン条件から独立している。
- 敵撃破、経過時間、プレイヤー死亡をミッション進行へ入力できる。
- 評価結果をリザルト項目へ変換できる。

### 問題点

- 本番ミッションの評価条件が2件しかない。
- 評価条件の実装がクリア時間だけで、被ダメージ、使用銃種、コンボを評価できない。
- 達成した評価条件数からC・B・A・Sランクを算出していない。
- `StageProgressSaveDataService.SaveClearAsync()`は定義されているが、ステージクリア処理から呼ばれていない。
- `SaveDataClearStageRepository.GetClearedStageIds()`がTODOで、常に空配列を返す。
- そのため、クリア済みステージとサブミッション結果の永続化、および後続ステージ解放が完成していない。

### 推奨方針

評価条件として、被ダメージ合計、使用した攻撃・銃種、最大コンボを追加する。ミッション進行へ直接他モジュールを参照させず、AdaptorのイベントControllerから必要な実績値を記録する。

ランクは成功した評価条件数を入力とするDomainの値計算にし、メインミッションクリア時のみ次のように算出する。

| 達成したサブミッション数 | ランク |
| --- | --- |
| 0 | C |
| 1 | B |
| 2 | A |
| 3 | S |

クリア確定時には、リザルト表示前に評価結果を一度生成し、同じ結果を表示と保存の両方へ渡す。表示と保存で評価を再計算しない構造が望ましい。

## チュートリアル

### 現状

- `Stage_01.asset`の表示名はチュートリアルだがStageIdは1である。
- Titleシーンの通常遷移先と初回遷移先は、どちらも`OutGame`である。
- `TutorialData.IsTutorialCompleted`は初回出撃判定に使用されていない。
- チュートリアル完了を保存するRuntime処理が確認できない。
- リズム説明、雑魚戦、ボス戦を順に進行させるチュートリアル専用フェーズがない。

### 推奨方針

StageId 0を有効値にする場合、現在の`default(StageId)`と区別できる設計へ変更する必要がある。StageIdを正の整数のまま運用する場合は、仕様書側の「ステージ0」を表示上の番号として定義し直す必要がある。

初回起動時はTitleから直接InGameへ遷移する処理をTitleモジュールへ追加するのではなく、PersistentまたはOutGameの出撃Applicationへ「初回チュートリアル出撃要求」を渡す。通常のステージ出撃と同じ経路で、選択ステージ、ミッション、Stageシーンを設定してからロードする。

## ステージデータの問題

### StageId重複

`Stage_05.asset`と`Stage_06.asset`のStageIdが両方5である。

`StageTree`はStageIdをDictionaryキーとして登録し、重複時は後から登録したノードで上書きする。現在の`StageTreeAsset`では`Stage_06`が後に登録されているため、StageId 5のボスステージがテストステージに置き換わる。

これはステージツリーの表示、選択、解放を不定にするため、最優先で修正する必要がある。

### Stageシーンの使い分け

- `Stage_01.unity`は市街地アセットを含む本番相当のシーンである。
- `Stage_02.unity`はPlaneと簡易スポーン構成が中心の検証用に近いシーンである。
- 現在のBattle用StageNodeはすべて`Stage_01`を参照している。

ステージごとに背景を変える仕様を満たすには、StageNodeごとに異なるStageシーンを割り当てるか、共通Stageシーンへ背景セットをAddressablesから生成する方式が必要である。

## ステージ演出

現状のTimelineはステージ開始、クリア、ゲームオーバーの共通演出に限定されている。フェーズ中にBGMと同期して爆発、倒壊、SE、障害物発生を行う仕組みは確認できない。

推奨構成は次の通りである。

1. Musicモジュールが小節・拍タイミングを提供する。
2. EnemyモジュールがWave開始IDをAdaptor契約から通知する。
3. StageEffectモジュールがWave IDに対応する演出定義を選択する。
4. 演出定義が指定した拍で爆発、倒壊、SE、障害物切り替えを実行する。

敵生成、背景演出、障害物、音楽同期を一つのWaveControllerへ集約せず、フェーズIDを介して各モジュールが独立して反応する構造が望ましい。

## 優先度付き対応項目

### 優先度A

1. `Stage_05`と`Stage_06`のStageId重複を解消する。
2. ステージクリア時に評価結果とクリア状態を保存する。
3. `SaveDataClearStageRepository`を実装し、後続ステージ解放を復元する。
4. サブミッションを3件設定し、ランク算出を実装する。
5. 初回起動時のチュートリアル自動出撃経路を実装する。

### 優先度B

1. ステージごとのWave定義ロードへ変更する。
2. Wave開始通知とStageEffectモジュールを追加する。
3. 被ダメージ、使用銃種、コンボの評価条件を追加する。
4. 複数の本番Stageシーンまたは背景セットをStageNodeへ割り当てる。

### 優先度C

1. 正方形、通路なし、屋外限定をUnity上で目視確認する。
2. 1ステージ約2分になるか複数回プレイして計測する。
3. BGM同期演出のタイミングを実機環境で確認する。
4. 仕様に記載された道路、柵、電灯、戦車残骸、ドラム缶の配置を背景アセット一覧と照合する。
