# 初回チュートリアル直接出撃化計画書

- 作成日: 2026-07-16
- 対象: 初回起動時（`SaveData.Tutorial.IsTutorialCompleted == false`）に、Title→OutGame→チュートリアル戦闘という二重シーンロードが発生している問題の根本解消
- 前提: `Assets/Scripts/DesignPhilosophy.md`のレイヤー参照ルール（他モジュールへの依存はAdaptor層のみが持ち、Composition層が依存解決を行う）を判断基準とする

---

## 1. 目的

直前の対応（`LoadingScreenController`のセッション衝突例外の解消、Home画面の表示スキップ）により、初回起動時のエラーと画面のちらつきは無くなったが、**根本原因である「OutGameシーンを丸ごとロード・初期化してから、即座にチュートリアル戦闘シーンへ乗り換える」という二重ロードの構造は残ったまま**である。

本計画は、初回起動時（チュートリアル未完了時）に**Titleからチュートリアル戦闘シーンへ直接遷移し、OutGameシーンを一切ロードしない**ように変更し、二重ロードそのものを無くすことを目的とする。

---

## 2. 現状整理（調査済み）

### 2.1 現在のTitle→OutGame遷移の仕組み

`TitleSceneInitializer`（`Assets/Scripts/Runtime/6.Composition/OutGame/Title/TitleSceneInitializer.cs`、Order 20）の`Build()`が、`SaveData.Tutorial.IsTutorialCompleted`を見て次の分岐をしている。

```csharp
bool isTutorialCompleted = _loadedSaveData.Tutorial.IsTutorialCompleted;
if (!isTutorialCompleted)
{
    _titleSceneView.SetTargetSceneName(_firstLaunchTargetSceneName);
    RequestTutorialSortie(); // TutorialSortieRequestStateをServiceLocatorへ登録しRequest()するだけ
}
else
{
    _titleSceneView.SetTargetSceneName(_targetSceneName);
}
```

`Title.unity`上の実際の設定値は`_targetSceneName: OutGame`、`_firstLaunchTargetSceneName: OutGame`と**どちらも同じ**であり、実質的に「初回かどうか」で遷移先シーンが変わることは無い。`RequestTutorialSortie()`はシーンを跨いだフラグ（`TutorialSortieRequestState`、`Assets/Scripts/Runtime/3.Adaptor/OutGame/StageSelect/TutorialSortieRequestState.cs`）を立てるだけで、この時点ではチュートリアルステージの解決も出撃準備も一切行われていない。

プレイヤーがタイトル画面をクリックすると`TitleSceneView.OnPointDownEvent`→`TitleStartController.StartGameAsync(currentSceneName, targetSceneName, token)`（`Assets/Scripts/Runtime/3.Adaptor/OutGame/Title/TitleStartController.cs`）が呼ばれ、`LoadAdditiveAsync(targetSceneName)`→`UnloadAsync(currentSceneName)`という2段階でOutGameへ遷移する（TitleがOutGameの読み込み完了まで画面に残り続けることで、黒画面区間を防ぐ設計と見られる）。

### 2.2 OutGame側でチュートリアルが処理される仕組み

OutGameシーンがロードされ、`OutGameInitializationModuleBase`群のInit→ResourceLoad→Build→**Ready**フェーズが全モジュール分完了して初めて、`StageSelectInitializer`（Order 110）の`Ready()`内`TryStartTutorialSortie()`が`TutorialSortieRequestState.IsRequested`を確認し、ようやくチュートリアルステージの解決（`_stageTree.TryGetTutorialNode(...)`）と出撃準備（`TryPrepareBattleSortie(...)`）、`OutGameSortieController.RequestImmediateBattleSortie(...)`によるチュートリアル戦闘シーンへの遷移が行われる。

つまり、**OutGameシーンの全モジュールのフルロード・フル初期化（`ScreenInitializer`のHome画面構築、`StageSelectInitializer`自身のステージツリーUI構築、`OutGameSortieInitializer`、`OutGameScenarioInitializer`等すべて）が、チュートリアル出撃の判定より前に完了している**。これが二重ロードの正体である。

### 2.3 「Titleから直接チュートリアル戦闘へ飛ぶ」ことの技術的な可否（調査済み）

以下を実際に確認した。

- **`StageTree`の構築はUIに一切依存しない純粋なデータ処理**である。`StageTreeAsset.Create()`（`Assets/Scripts/Runtime/5.InfraStructure/OutGame/StageSelect/StageTreeAsset.cs`）は`_nodeAssets`/`_connections`のみから`StageTree`を構築し、`StageTree.TryGetTutorialNode(...)`（`Assets/Scripts/Runtime/1.Domain/OutGame/StageSelect/StageTree.cs`）も各ノードの`Definition.IsTutorial`フラグを見るだけで、セーブデータの進行状況（クリア済みステージ）にも、UI Toolkitの`VisualElement`にも一切依存しない。`StageSelectInitializer`がUI要素とノードを紐付けている`BuildConnectionViewMap`/`BuildNodeComponents`は、`_stageTree`構築の**後に行われる別工程**であり、チュートリアルノード解決には不要。
- **`_stageTreeAssetKey`（Addressablesキー、値は`"StageTreeAsset"`）はシーンに紐付かないデータアセット**であり、Titleが同じキーで独自にロードすることに技術的な支障はない。
- **`SelectedBattleStageState`・`SelectedMissionState`はServiceLocatorに登録される**が、現状は`StageSelectInitializer.Initialize()`（Build相当）が遅延生成・登録する形になっており、**OutGameが一度もロードされていない状態のTitleからは存在しない**。ただし生成ロジック自体は「無ければnewして登録する」という単純な遅延初期化なので、Title側で同じロジックを先に実行しても問題ない。
- **`OutGameSortieController.RequestImmediateBattleSortie`はそのままでは使えない**。内部で`OutGameUIEvent.OnStartGame`を発火するだけの薄いパススルーであり、これを購読しているのは唯一`ScreenInitializer.HandleStartGame`（OutGame専用のComposition）である。Titleには`OutGameSceneInitializer`が独自の`OutGameUIEvent`インスタンスを生成するが、`ScreenInitializer`自体がTitleシーンには存在しないため、Titleから`OnStartGame`を発火しても誰も購読しておらず何も起こらない。**Titleは`OutGameSortieController`を経由せず、`SceneTransitionController`を直接使ってチュートリアル戦闘シーンへ遷移する必要がある。**
- `IngameComposition`（戦闘シーン側の起点、`Assets/Scripts/Runtime/6.Composition/InGame/Bootstrap/IngameComposition.cs`）が実際に要求するのは、詰まるところ「`SelectedBattleStageState`が`ServiceLocator`に登録済みで`HasSelectedBattleStage == true`」という状態だけである。**どの画面から遷移してきたかは問わない。**

以上より、「Titleが自前で`StageTreeAsset`をロードし、チュートリアルノードを解決し、`SelectedBattleStageState`/`SelectedMissionState`を構築してから、`SceneTransitionController`で直接チュートリアル戦闘シーンへ遷移する」という設計に変更すれば、OutGameのロードを完全に省略できる。

## 3. 設計方針

### 3.1 出撃準備ロジックの共通化

`StageSelectInitializer.TryPrepareBattleSortie(StageDefinition)`（Composition層に埋もれている、`SelectedBattleStageState`/`SelectedMissionState`を構築する処理）を、**Adaptor層の共通クラスとして切り出す**。これはTitle・OutGame両方のComposition層から呼べるようにするための、本計画の中核となる変更である。

```csharp
// 新規: Assets/Scripts/Runtime/3.Adaptor/OutGame/StageSelect/BattleSortieSelectionService.cs
namespace KillChord.Runtime.Adaptor.OutGame.StageSelect
{
    /// <summary>
    ///     バトルステージへの出撃準備として選択状態を構築する。
    /// </summary>
    public sealed class BattleSortieSelectionService
    {
        public bool TryPrepareBattleSortie(StageDefinition stageDefinition, string returnSceneName)
        {
            if (stageDefinition == null
                || stageDefinition.StageType != StageType.Battle
                || stageDefinition.MissionDefinition == null
                || string.IsNullOrWhiteSpace(stageDefinition.BattleSceneName))
            {
                return false;
            }

            SelectedBattleStageState battleStageState = ResolveSelectedBattleStageState();
            SelectedMissionState missionState = ResolveSelectedMissionState();

            battleStageState.SelectBattleStage(stageDefinition, returnSceneName);
            new OutGameMissionSelectController(missionState).Select(stageDefinition.MissionDefinition);
            return true;
        }

        // ResolveSelectedBattleStageState / ResolveSelectedMissionState は
        // 既存のStageSelectInitializer.Initialize()にある遅延生成ロジックをそのまま移植する。
    }
}
```

`StageSelectInitializer.TryPrepareBattleSortie`は、この新クラスへの委譲に置き換える（通常の出撃フロー`HandleSortieRequested`の挙動は変えない）。

### 3.2 Titleにチュートリアル解決ロジックを追加

`TitleSceneInitializer`に、`StageSelectInitializer`と同じ`_stageTreeAssetKey`（`[RepositoryAddressSelector]`）を追加し、`ResourceLoadAsync`で`StageTreeAsset`をロードする。

`Build()`のチュートリアル分岐を、フラグを立てるだけの現状から、**その場でチュートリアルステージを解決し出撃準備まで完了させる**形に変更する。

```csharp
// TitleSceneInitializer.Build() 内、チュートリアル分岐の変更後イメージ
bool isTutorialCompleted = _loadedSaveData.Tutorial.IsTutorialCompleted;
if (!isTutorialCompleted && TryPrepareTutorialBattleSortie(out string battleSceneName))
{
    _titleStartController.SetTutorialBattleTarget(battleSceneName);
}
else
{
    _titleSceneView.SetTargetSceneName(_targetSceneName);
}

// ...

private bool TryPrepareTutorialBattleSortie(out string battleSceneName)
{
    battleSceneName = null;
    if (_loadedStageTreeAsset == null)
    {
        return false;
    }

    StageTree stageTree = _loadedStageTreeAsset.Create();
    if (!stageTree.TryGetTutorialNode(out StageNode tutorialNode))
    {
        return false;
    }

    StageDefinition definition = tutorialNode.Definition;
    if (!_battleSortieSelectionService.TryPrepareBattleSortie(definition, _targetSceneName))
    {
        return false;
    }

    battleSceneName = definition.BattleSceneName;
    return true;
}
```

- 出撃準備（`SelectedBattleStageState.SelectBattleStage`）は`Build()`の時点で行うが、これは既存の`StageSelectInitializer`側の実装と同じ「選択状態を先に構築しておき、実際のシーン遷移は後で行う」という順序であり、副作用のタイミングとして不自然ではない。
- 戻り先シーン名（`returnSceneName`）には、既存の`_targetSceneName`（＝`"OutGame"`）をそのまま使う。チュートリアル戦闘の"入り方"がTitle直行になるだけで、"抜け方"（クリア後にOutGameへ戻る）は今まで通りで問題ない。
- チュートリアル解決に失敗した場合（ステージツリーに`IsTutorial`ノードが無い等の異常系）は、ログを出した上で通常のOutGame遷移にフォールバックする。

### 3.3 `TitleStartController`にチュートリアル戦闘への直接遷移を追加

`TitleStartController.StartGameAsync`は現在、`LoadAdditiveAsync`→`UnloadAsync`という2段階遷移（黒画面防止のためTitleを残したままOutGameを読み込む方式）のみを行う。チュートリアル戦闘への遷移はこれとは異なり、**ロード画面を表示し続けたまま一気に遷移する**（`ScreenInitializer.HandleStartGame`がOutGame→戦闘シーンで使っているのと同じ`ChangeSceneKeepingLoadingAsync`）必要がある。

`TitleStartController`に、Composition層から設定される「チュートリアル戦闘遷移先」を保持させ、設定されていればそちらを優先する形にする。

```csharp
public class TitleStartController
{
    /// <summary> チュートリアル戦闘シーンへの直接遷移先を設定する（未設定なら通常遷移）。 </summary>
    public void SetTutorialBattleTarget(string battleSceneName)
    {
        _tutorialBattleSceneName = battleSceneName;
    }

    public async Task<bool> StartGameAsync(string currentSceneName, string targetSceneName, CancellationToken token)
    {
        if (_isActivate) { return false; }
        _isActivate = true;
        try
        {
            if (!string.IsNullOrWhiteSpace(_tutorialBattleSceneName))
            {
                return await _sceneTransitionController.ChangeSceneKeepingLoadingAsync(
                    currentSceneName, _tutorialBattleSceneName, token);
            }

            // 既存の通常フロー（LoadAdditiveAsync + UnloadAsync）はそのまま。
            ...
        }
        catch { _isActivate = false; throw; }
    }

    private string _tutorialBattleSceneName;
}
```

`TitleSceneView`側のクリックハンドラ（`OnPointDownEvent`）は**変更不要**。`StartGameAsync`の呼び出し方は今まで通りで、分岐は`TitleStartController`内部に閉じる。`ChangeSceneKeepingLoadingAsync`は前回の修正（アクティブセッションがあれば`ContinueAndComplete`で引き継ぐ分岐）が既に入っているため、この経路でも安全に動作する（Titleからの遷移開始時点ではまだアクティブセッションが無いので、`KeepOpen`で新規セッションが開始され、戦闘シーン側の`IngameComposition`がそれを引き継いで完了させる、という既存の正常フローと同じ形になる）。

### 3.4 不要になったOutGame側のチュートリアル処理を削除する

Titleが直接チュートリアル戦闘へ遷移するようになるため、**OutGameが`TutorialSortieRequestState`を見る必要が無くなる**。以下を削除する。

- `StageSelectInitializer.TryStartTutorialSortie()`とその呼び出し（`Ready()`内）
- `ScreenInitializer.Ready()`に前回追加した`TutorialSortieRequestState`チェック（Home画面表示スキップ処理）
- `TutorialSortieRequestState`クラス自体、および`TitleSceneInitializer.RequestTutorialSortie()`
- `TitleSceneInitializer`の`_firstLaunchTargetSceneName`フィールド（役目が`TryPrepareTutorialBattleSortie`に置き換わるため不要）

`HandleDataResetButtonClicked`（データリセット時に再度チュートリアル判定を行う処理）は、`RequestTutorialSortie()`の呼び出しを`TryPrepareTutorialBattleSortie`＋`SetTutorialBattleTarget`の呼び出しに置き換える形で存続させる（Titleに留まったままリセットボタンを押すケースにも対応する）。

なお、データリセット操作自体はTitle画面にしか存在しない（`DataResetTabView`はTitle専用UIであることを確認済み）ため、OutGame側に同種のリセット導線は無く、この変更で見落としが発生する箇所は無い。

## 4. フェーズ構成

### Phase 1: 出撃準備ロジックの共通化
1. `BattleSortieSelectionService`（Adaptor層）を新設し、`StageSelectInitializer.TryPrepareBattleSortie`の中身（`SelectedBattleStageState`/`SelectedMissionState`の遅延生成・選択処理）を移植する。
2. `StageSelectInitializer.TryPrepareBattleSortie`を、新クラスへの委譲に置き換える（挙動は変えない）。
3. 実機確認: 通常の出撃フロー（ステージ選択画面から出撃）が今まで通り動作することを確認する。

### Phase 2: Titleからのチュートリアル直接出撃
1. `TitleSceneInitializer`に`_stageTreeAssetKey`フィールドを追加し、`ResourceLoadAsync`で`StageTreeAsset`をロードする。
2. `TryPrepareTutorialBattleSortie`を実装し、`Build()`のチュートリアル分岐から呼び出す。
3. `TitleStartController`に`SetTutorialBattleTarget`と、チュートリアル戦闘シーンへの`ChangeSceneKeepingLoadingAsync`遷移を追加する。
4. 実機確認: セーブデータ無し（またはチュートリアル未完了）の状態でタイトル画面から開始し、**OutGameシーンを経由せず**チュートリアル戦闘シーンへ直接遷移することを確認する。ロード画面が最初から最後まで途切れないこと、チュートリアルクリア後は通常通りOutGame（Home画面）へ戻ることも確認する。

### Phase 3: 不要になったOutGame側処理の削除
1. `StageSelectInitializer.TryStartTutorialSortie()`と`Ready()`内の呼び出しを削除する。
2. `ScreenInitializer.Ready()`の`TutorialSortieRequestState`チェック（前回の暫定対応）を削除し、`Ready()`を元の「常に`ShowHome()`を呼ぶ」形に戻す。
3. `TutorialSortieRequestState`クラス、`TitleSceneInitializer.RequestTutorialSortie()`、`_firstLaunchTargetSceneName`フィールドを削除する。`HandleDataResetButtonClicked`は3.4節の通り置き換える。
4. 実機確認: 通常のOutGame起動（チュートリアル完了済みセーブデータ）が今まで通り動作すること、データリセットボタンからのチュートリアル再突入も直接遷移になることを確認する。

## 5. リスク・注意点

- **`TitleSceneInitializer.Build()`内で`SelectedBattleStageState`等をServiceLocatorへ登録するタイミングが早まる**。今までは「OutGameのBuildフェーズで初めて登録される」ものが「TitleのBuildフェーズで登録される」形になる。他モジュールがこれらのServiceLocator登録有無を「OutGameが起動済みかどうか」の判定に使っていないか、念のため確認する（調査時点では見つかっていないが、実装時に横断的にgrepで確認することを推奨）。
- **チュートリアル解決失敗時のフォールバック**: `StageTreeAsset`にチュートリアルノードが無い、または不正なデータの場合、`TryPrepareTutorialBattleSortie`が`false`を返し通常のOutGame遷移にフォールバックする設計にしているが、この場合`TutorialSortieRequestState`相当の再試行機構が無くなる（Phase 3で削除するため）。フォールバック時にプレイヤーが詰まらないよう、Home画面から通常に振る舞えることを確認する。
- **`ChangeSceneKeepingLoadingAsync`のロード画面デザイン**: 今までTitle→OutGameは黒画面防止のため`LoadAdditiveAsync`+`UnloadAsync`（Titleを残したまま裏でロード）だったが、Title→チュートリアル戦闘は`ChangeSceneKeepingLoadingAsync`（ロード画面表示）に変わる。見た目の遷移演出が変わる点をデザイナー・プランナーに確認する。
- **Phase順序を守る**: Phase 3（OutGame側の削除）はPhase 2（Titleからの直接遷移）が実機で確認できてから行う。逆順に進めると、チュートリアル未完了プレイヤーがどちらの経路でも救済されない状態になり得る。
